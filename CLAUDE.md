# Myco Engine

A 2D & 3D TypeScript game engine: Unity-style scripting over a hidden ECS core, Godot-style node graph, Babylon.js rendering, shipped through Tauri.

**Read [docs/README.md](docs/README.md) before making structural changes.** It indexes the architecture overview, open questions, implementation status, and the decision records (`docs/decisions/`).

- Engine code is in `src/engine/` (public API: `src/engine/index.ts`). The v1 demo, a Flappy Bird clone, is a sample project in `samples/flappy/` (ADR 0031): data plus `scripts/` that import `"myco"`. Samples ship beside the editor and are never imported from `src/` (editor tests register the sample's types through `src/editor/sampleTypes.ts`).
- [docs/architecture/implementation-status.md](docs/architecture/implementation-status.md) says what each decision record has and lacks. Update it when you implement part of a record.
- Babylon.js (the only renderer, ADR 0075 and 0081), three.js (only the OBJ/MTL/FBX loaders in `scene/models.ts` and the glTF loader in `scene/gltf.ts`, ADR 0088; its render backend was removed, ADR 0081), Rapier and Howler must never appear in the public API (ADR 0010). Import Babylon module by module, never from the `@babylonjs/core` barrel.
- Significant decisions (hard to reverse, cross-module, new dependency, public API change) get a record in `docs/decisions/` using `0000-template.md`. Accepted records aren't rewritten; supersede them with a new one.
- Build tooling is Vite ([0015](docs/decisions/0015-vite-build-tooling.md)). Every Vite/Vitest config must use the `typescriptTranspile()` plugin from `vite.shared.ts` with `oxc: false`, because oxc doesn't lower standard decorators.
- Built-in navigation (ADR 0065) is Rust in `native/nav/` (a Cargo workspace), compiled to WebAssembly by `npm run build:nav` into `src/engine/nav/wasm/`, which is committed so the engine builds without Rust. Changing `native/nav/` needs `rustup target add wasm32-unknown-unknown` and `wasm-bindgen-cli` at the version pinned in its `Cargo.toml`; rebuild and commit the output with the source. `cargo test` in `native/nav/` runs its tests.
- The scene editor is in `src/editor/` (page: `editor.html`; the desktop editor opens first on its Projects window, `projects.html`, ADR 0059); the Tauri shell is in `src-tauri/` and needs a Rust toolchain.
- Editor CSS uses the theme tokens from `src/editor/theme.ts` (`var(--panel)`, `var(--text)`, `var(--accent)`, `var(--danger)`…; the full list heads `src/editor/ui/editor.css`), never hard-coded colours, so Settings > Appearance themes it.
- Commands: `npm run dev` (dev server on :3000; editor at `/editor.html`, `?sample=flappy` opens the sample), `npm run build` (typecheck, then the game player in `dist/player/`, the editor with the samples and the player in `dist/editor/`, and the engine library in `dist/engine/`), `npm test` (Vitest, headless), `npm run test:e2e` (Playwright on Chromium and WebKit; run `npm run test:e2e:install` once first; `npm run test:e2e:chromium` for Chromium only, on the GPU locally; give concurrent runs their own `E2E_PORT`; the editor is rebuilt only when its sources changed), `npm run typecheck`, `npm run tauri:dev` (desktop editor window), `npm run tauri:build` (installers), `npm run export -- <projectDir> [--out DIR] [--target web|desktop]` (a game build: the prebuilt player from `dist/player/` plus the project's files and compiled scripts, served with `node serve.mjs`; desktop wraps it in a generated Tauri app, ADR 0041).
