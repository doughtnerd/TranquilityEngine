# Round 2: senior reviews architecture.md

**Verdict.** The architecture is sound and consistent with the ADR and my round-1 doc. The transport, state ownership, staleness bounds, clock map and failure table are specific enough to build from. My concerns are cost against benefit for M1: a soft-trap recovery path, a two-class compacting arena, a metered wasm for CI, and a three-signal adaptive cap with start-up calibration. Each adds days to the riskiest iterations for rare cases. I also think the lookahead rule taxes every gameplay sound by about 20 ms for sync nobody asked for. I accept eight of the eleven contracts as written or with small changes, and defer one (C1's adopt path). Nothing is blocking, but issues 1, 2 and 3 should be settled before M1a.0 starts.

## Issues

1. **Major, §3.6, §7, C1: soft trap recovery.** Keeping clips across a trap means re-initialising a heap that a trap left half-mutated (allocator, voice slots, ring heads) at "the same addresses", plus a checksummed directory and a trap-within-10 s rule. A trap is a bug we expect to be rare; the hard path (new node, re-upload by priority) is needed anyway. Fix: M1 builds only the hard path (both rebuild the core, count 3 per 60 s). Revisit if the soak shows traps. Saves about 3 days and a test matrix.
2. **Major, §4.3: lookahead on every sound.** `firstFrame = F_now + L + Λ`-based stamping makes a plain `playOneShot` start about 21 ms (8 quanta) later than needed, on top of Λ (~50 ms). Most gameplay sounds don't need frame-exact sync, and batch arrival jitter (1 quantum p50, 3–5 p99) is the only price of stamping nothing. Fix: add a record flag `asap` (set when `at` is absent): the core applies it on arrival at the next quantum, not counted late. Only `at`, loops restarting in sync and replays use the lookahead. Keep a project setting `audio.latency: "low" | "stable"` (default `"low"`) only if listening tests want it. This reduces typical latency by ~21 ms.
3. **Major, §6.5: metered wasm.** "An instruction counter injected after linking" needs a post-link wasm rewriter (a new dependency and build step) and a second committed artifact. The ADR's gate is deterministic work units. Fix: M1's CI gate is the WU totals on fixed scenes (deterministic, in `audio-bench` and Node); the metered binary becomes a lab tool, later. The "model within ±20% of metered counts" test is replaced by a lab-only wall-time ratio check.
4. **Major, §5.2: two-class compacting arena.** 4 KB granules, segregated lists, compaction at 50% fragmentation, plus 64 KB-run large class. Clips are loaded at scene start and freed at play stop, so fragmentation will be low. Fix: M1 uses one class (64 KB pages, first fit, coalescing, never moved). Add the fragmentation counters (already in STATUS) and build compaction only if the stress sample shows a refused load with enough total free bytes. Saves about 3 days.
5. **Major, §6.3: adaptive cap and calibration.** Three signals, a 6 ms start-up benchmark on a throwaway main-thread instance, a `Date.now()` load estimate with a ±10% error, and per-voice cost summing for the emergency demote. Fix for M1: signals are WU p99 against a fixed budget and underrun increments only; the WU-to-time constant *k* comes from the lab, not a start-up run; the presets stay a project setting (user-picked `voices`) until the low-end soak machine gives a number. Calibration and ρ̂ are post-M1a.3 additions behind the same `mixedCap` field. The ADR says presets by measured class: the measurement then happens in the lab, and a default per class can ship in M1c.
6. **Major, testability, §4.3, §6.3, §7.** The clock filter, calibration, ρ̂ and underrun detector all read `Date.now`, `getOutputTimestamp` and rAF. The doc doesn't say how tests drive them. Fix: the architecture should state the loopback contract: a `HostClock` interface (rAF time, output timestamp, `Date.now`) injected into the host and the shell logic, a manual `renderQuanta(n)` that delivers STATUS synchronously after its quanta, and calibration and the load estimator disabled when the clock is the fake. I will add this to section 8 and to tasks A1.4 and A3.2.
7. **Minor, §6.4 and §5.1: STATUS buffer size.** A 35 KB buffer pool of 4 on the worklet side, posted every 16 ms, allocates in every post's structured envelope for a block that is normally 200 bytes. Fix: 16 KB buffers, 1,024 entries per list, overflow carried over (C3).
8. **Minor, §3.9: a World that loses the view goes virtual.** Today a voice keeps sounding after its World loses the view (`AudioSource.ts:72` gates only the start, and `_sync` stops). 0074 says other Worlds are silent, so silencing is defensible, but it is a behaviour change. Fix: note it in the behaviour table; and specify what BUS_CONFIG does while voices are live (`Engine.ts:176` reconfigures the one mixer for the editor's and play mode's Engines): remap `bus` by name, unknown names to the root, as my `busEpoch` rule.
9. **Minor, §7 underruns, §6.3 ρ̂: 1 ms clock.** Both rely on a 1 ms clock. The "max(device period, 12 ms)" threshold and "1 s minimum" are unspecified enough that two implementers would differ. Fix: the architect writes the pseudocode and a replay test with a recorded `(currentFrame, Date.now)` trace.
10. **Minor, §2.1: core loaded while suspended.** The spike recommended creating the context behind the gesture (`README`, round 2); loading into a suspended context was not run in WebKit or Firefox. Also the first context costs 250–490 ms of main-thread time on Windows; created at "World service load" it could land mid-play on desktop (autoplay allowed). Fix: A0.6 verifies suspended `addModule` and node creation in WebKit and Firefox, with "create on gesture" as the coded fallback; the service loads at scene load, before the first presented frame.
11. **Minor, §5.1: 64 KB shadow stack.** The Freeverb and per-bus `[f32;128]` buffers are heap fields in the spike, but a future local array overflows silently into data. Fix: 256 KB stack, plus a test that runs the stress scenario and asserts the stack high-water mark.
12. **Minor, §10: reserved `group` field.** Speculative for M2. Fix: leave it out; add it when M2's record needs it (the id scheme already allows it).
13. **Minor, §3.3 and `rampFrames`.** PLAY should not ramp its gain from zero (a clip starts at its gain); only SET_PARAMS and BUS_MIX ramp. State it.

## Anything from 0074/0097/0098 my round-1 doc got wrong

1. **Ducking counts (0097, `howlerBackend.ts:30-38`).** Today a voice counts from play until end or stop, including paused voices; 0097 says "playing voices". I wrote that virtual voices are excluded. That deviates from 0097, and cap-driven virtualisation could flap the duck. Correction: `Bus.activeVoices` counts every live, non-ended voice, virtual and paused included, exactly as today.
2. **Who calls `mixer.voiceStarted/Ended`.** The backends do (`howlerBackend.ts:30,38,72-74`; the fake does at `audioBackend.test.ts:11`). I moved counting to the "mirror" without saying who calls them. Correction: `CoreBackend` calls them on play, free (end, stop, steal) and `setBus`.
3. **Failed backend (0098: a failed load keeps Howler).** I didn't say what the core does. The ADR's table says silent with `status = "failed"`; I will write that explicitly, and state that `audio.backend` is only a setting, with no automatic fall back to Howler.
4. **Reverb (0097: one shared convolver with a generated 1.8 s impulse, `busGraph.ts:16`).** I planned Freeverb. That is a different sound, not "within a tolerance in dB". Correction: list it as a behaviour change, tuned to a ~1.8 s decay, until M3's convolver; or generate the same impulse and wait for convolution.
5. **Filter Q (0097).** `busGraph.ts:65` sets Web Audio's `Q`, which for lowpass and highpass is in dB; the settings default `q: 1` means 1 dB, not 1.0 linear. The core must convert (linear Q = 10^(q/20)) or parity breaks. Also Web Audio's compressor applies automatic makeup gain, so "within 0.5 dB of the analytic curve" is not parity. Correction: A2.2's acceptance compares to the Web Audio behaviour measured offline in a browser (null test against an `OfflineAudioContext`), within the ADR's dB tolerance.
6. **Bus tree change while playing (0097).** Old behaviour: playing sounds keep old routing. Mine remaps by name. It is an improvement; I will list it as one.
7. **0074 distance models and HRTF:** my reading of Web Audio's `maxDistance` (linear only) is right; the HRTF loss (issue 2 in round 1) stands.
