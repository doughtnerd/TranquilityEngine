# 0162 spatial audio: contracts the senior engineer needs from `architecture.md` (round 1)

Written by the senior engineer, in parallel with the architect's document. Each contract is a number the API and models document (`api-and-models.md`, "this file") **assumes**; if the architect's value differs, this file's numbers move, so say so. The architect writes their own list separately; the coordinator merges. Shapes are exact where a field, constant or counter is named. `§n` points into `api-and-models.md`.

| # | Need | Shape this file assumes |
|---|---|---|
| S1 | **Occlusion and sends: end-to-end staleness bounds** | A wall appearing reaches full effect within `ray age + 100 ms smoothing + 1 frame ramp`. Ray age (frames since a source's last ray) at the default 0.25 ms budget: **at most 3 frames at 64 sources, 5 at 256, 22 at 1,024** (spike; 0.5 ms on high: 8 frames at 1,024; 0.06 ms on low: about 16 rays a frame). The top 16 sources by audibility **before** occlusion are recast every frame. Command latency main to core: SET_PARAMS and SET_FX are applied at the next quantum after the batch arrives: at most 1 frame (16.7 ms at 60 Hz) plus the in-record `rampFrames`. Stated as the architect's timing table's rows; zone weights are per frame, the zone **active set** re-plans every 4 frames with dwell 0.5 s and hysteresis 1.5x |
| S2 | **Listener staleness and axes (clip rotation)** | LISTENER is sent each frame the rotation moved more than 0.001 rad; the core slerps over `rampFrames` (one game frame). Worst-case rotation lag of an ambisonic clip: **1 frame + 1 ramp frame, about 33 ms at 60 Hz** (about 100 ms at 20 Hz in a background tab, where background modes already mute or pause). Axis map: engine listener space (forward -Z, up +Y, right +X) to AmbiX (X forward, Y left, Z up) is `(X, Y, Z) = (-z, -x, +y)`. The architect states the head-turn latency budget this must meet (assumed: 50 ms) |
| S3 | **Who owns what state** | Core owns: beds, zone slots and their state blocks, the fx pool, the listener rotation, chain gains. Main owns: bed **hosts** (resolution, `hostOf`), the zone **active set** and slot assignment, per-voice send levels, occlusion gain and cutoff, Doppler, `lpHz` (the lowest of its sources, `lpBy`), `hpHz`. The core never infers a send, a host or a cutoff; it applies what it is told and ramps. Smoothing of occlusion is main's (100 ms, per-material attack and release); the core only ramps between the targets main sends (`rampFrames`). Confirm no state moves across this line |
| S4 | **Stream ring and chunk sizes for wide streams** | Streams of more than 2 channels: ring **16,384 frames** (0.34 s at 48 kHz) occupying `k = ceil(ch x 16,384 x 4 / RING_BYTES)` adjacent slots (4 channels 1, 9 channels 3, 16 channels 4); chunk `4096 x 2 / ch` frames (512 at 16 channels, 64 KB). Ring slots per preset: low 4, default 8, high 16 (so 1 / 2 / 4 third-order streams at once). The architect confirms 0.34 s covers the worker round trip plus a main-thread stall (0157's 0.68 s was sized with an 800 ms main stall in mind: wide streams do not tolerate it, which is acceptable only because the worker is off main) and the preset ring counts |
| S5 | **MagLS asset and HRIR sharing** | One committed asset `engine/audio/magls-o3.bin`: 32 B header plus `16 x 2 x 256` f32 = **32,800 B** at the HRIR's native rate, resampled by main to the context rate like the HRIR, sent as CLIP_BEGIN format 4 (reserved id 0xFFFF0100), not counted against `clipMemoryMB`, re-sent on a rebuild. Decoder spectra built in the core: **64 KB**. Loaded lazily with the HRIR (same fetch, same `hrtfReady`-style flag `bedDecoderReady`). Failure behaviour: no bed decoder means beds are not created (`bedsRefused` counts, voices stay equal-power), one warning |
| S6 | **Memory sizes per preset** (48 kHz; the architect's memory table adopts or corrects them) | Beds: 48 KB state per bed + 64 KB shared decoder + `BedVoice` pool `max_mixed x 64 B`: **high (4 beds, 256 mixed) 272 KB; default (2, 128) 168 KB; low 0**. Fx pool `max(16, max_mixed/2)` entries x about 320 B: **high 40 KB, default 20 KB, low 10 KB**. Voice slot: 192 B today, **256 B if the new fields do not fit** (+256 KB at 4,096 logical voices); `VOICE_SLOT_BYTES` is the single constant. Zones (arena, not a fixed region): state + kernels **3.1 MB per 2 s slot, 6.1 MB per 4 s, about 1.5 MB per 1 s**: high 2 x 4 s = **12.2 MB**, default 2 x 2 s = **6.2 MB**, low 1 x 1 s = **1.5 MB**; the arena `maximum` = fixed regions + `clipMemoryMB` + the zone budget. Prepared-IR blobs are **not** kept on main (the worker keeps encoded bytes and re-prepares). Wasm linear memory `maximum` grows by the zone budget |
| S7 | **Per-voice cost model (µs, wasm p50 on the container) used in the budget** | Bed encode 0.5 per voice; bed decode 20 per bed (the spike's 142 / 262 µs p50 / p99 for 256 voices + one decode); ambisonic clip 3rd-order 23, 1st-order 7; zone 20 / 30 (2 s / 4 s mono-in stereo) per slot, 47 / 107 µs p50 / p99 for 2 blending 2 s; per-voice filter pair 0.85 (event filter spike) plus 0.05 coefficient recompute; zone or aux send 0.3 per voice per target (256 mono MACs); SH rotation 2 per quantum. The record's typical scene: about 0.27 ms p50, 0.5 ms p99, **0.22 ms net** after 8 fewer HRTF voices (about 55 µs saved at 16 to 8; more at 32 to 8). The architect's performance section uses the same rows and states the **p99.9 budget on the lab VM** (0157 §6 statistic) as pending the owner's run, not as this estimate |
| S8 | **Counters and debug fields the architect's observability section must list** | STATUS (§4.3): `bedVoices`, `bedsActive`, `fxVoices`, `ambisonicVoices`, `zonesActive`, `zonesRinging`, `bedsRefused`, `fxPoolFull`, `zoneUsedKB`, `workBed`, `workZones`, sections `beds`, `zoneEvents`. Main: `occlusionRays`, `occlusionUsedMs`, `occlusionOverruns`, `occlusionSources`, `oldestOcclusionAgeFrames`, `dopplerGuardTrips`, per-voice `occlusion.{gain, cutoffHz, ageFrames, hits, material, collider}`, `filter.lowpassBy`, `kindDwellMs`, per-zone `state` and `why`. The architect assigns each a health meaning (green, amber, red) and a threshold; this file assumes `oldestOcclusionAgeFrames` amber above 8 and red above 30 at the default budget, `fxPoolFull` and `bedsRefused` non-zero amber |
| S9 | **STATUS size** | Header 112 to **144 B**, two sections appended; worst case **15,856 B** of the **16,384 B** buffers in the pool of 8 (0157 §4.3). The architect confirms no other STATUS growth is planned for M3 (headroom 528 B), or raises the pool buffer size |
| S10 | **Failure behaviours (degrade, never silence)** | Bed decoder missing or `maxBeds` reached: voices stay equal-power (kind 0), counted. Zone IR failed or slot allocation refused: that zone is `failed`, its sources send nothing, the bus `reverb` effect continues, one warning with the cause. Ambisonic clip with no bed and no free decoder (and always on `maxBeds` 0): the **stereo decode** (not binaural), one warning per clip. Fx pool full: the voice plays unfiltered (the unfiltered sound is louder than it should be: acceptable for occlusion, counted). 3D physics service absent or still loading: no rays, occlusion gain 1, one debug note; **audio never starts physics**. A rebuild (hard) replays: RESET, BUS_CONFIG, BED_CONFIG, BUS_MIX, voices, SET_FX; zones **after** their IR blob is resident again (re-prepared by the worker); sends are 0 meanwhile. The architect's failure table lists these and the trap-recovery path for the new tables |
| S11 | **Hard-rebuild and sample-rate-change cost** | A context rate change or hard rebuild re-prepares every active IR in the worker: **1.3 / 2.5 / 5.3 ms of preparation per 1 / 2 / 4 s IR** (spike) plus decode and resample (unmeasured: task C2a measures it), spread across workers' idle time, never on the audio thread; zones are silent until resident (typically under 100 ms for two 2 s IRs). The architect states the acceptable gap and whether voices keep their zone sends muted or the old context's tail is kept |
| S12 | **Bed cost attribution** | The debug panel's "each bed's cost (about 20 µs after the first)" needs per-bed work units in STATUS (`beds[]` section: bus, voices, work). Assumed conversion `µs = work units x (container p50 µs per unit, from the metered build)`, shown as modelled. The architect confirms the shared modelled-work scale of `workUnits` (0157 §6.1) includes the new terms with the weights in S7 |
| S13 | **The adaptive cap and M3's work** | M3's per-quantum work is outside the mixed-voice count: beds, zones and filters add to `workUnits` but not to `mixedVoices`. The adaptive cap (0157 §6.3) must be told whether it demotes **bed voices first** (assumed: yes, a bed voice is the cheapest to demote, `score` ordering unchanged) and whether it can ever **turn off a zone or a bed** (assumed: no; only voices; zones shrink only through the planner on main). The architect rules |
| S14 | **Kind-change hysteresis ownership** | Panner kind changes (equal-power, HRTF, bed) need a 30-frame (0.5 s) dwell on main in addition to the existing 1.2x audibility hysteresis and the 3-frame mixing dwell; the core's 45 ms crossfade is unchanged. The architect's selection section states the three timers together and the expected worst case of a flapping source (at most one kind change per 0.5 s) |
| S15 | **Bus tree and bed host changes while voices play** | A bus tree edit re-resolves hosts on main and sends BED_CONFIG; a voice whose host changed crossfades (the 45 ms panner crossfade, bed share ramped) and is not stopped; a bed whose host left is freed after its voices left (at most 45 ms plus the decoder tail of 256 taps = 5 ms). The architect confirms the lifecycle and that a **bed's decoder tail is flushed** (not cut) when the bed is freed |
| S16 | **Lifetimes and ordering in the render quantum** | Order per quantum assumed: apply commands; render voices (voices add into their bus buffer, a bed's `acc`, zone `in_l/in_r` and an aux bus buffer); decode each bed into its **host bus buffer** (before that bus's effects, ducking, meter); zones' convolvers run (staggered, `plan_stagger`) and their wet adds to the output **after the bus tree and before MASTER** with the shared reverb; limiter last. The architect's component diagram and §2 timeline show this order and which table each stage reads |
| S17 | **Sample-rate dependence** | Everything prepared (IR blobs, bed decoder) is at the **context** rate: 44.1 and 48 kHz are tested (the spike used 48), 96 kHz is refused for zones with a warning if the 4,096-point transform budget fails (`convolver::ir::frames` refuses rates today). The architect states the supported rate range and whether `AudioContext` rate changes (device change) are handled by rebuild (assumed) |
| S18 | **Physics service contract for rays** | Occlusion calls `_worldRaycast(world, origin, dir, maxDistance, { layers, includeTriggers: false })` and reads `hit.node` and `hit.distance`; first hit only; up to 3 calls per source. Cost 3.1-3.7 µs per ray (spike). The architect's interactions section lists audio's read dependency on the physics World service as optional and one-way (physics never calls audio) and the physics step's position in the frame (rays read the last stepped state; moving occluders lag by at most the fixed step) |
| S19 | **Listener choice and multi-World** | One listener per frame: the first enabled `AudioListener` in the World with the view (else the main camera); only that World sends LISTENER, runs rays and zone planning; a World without the view has its voices virtual (0157 §3.9). Zones belong to the World that holds the component and are inert elsewhere. The architect confirms play mode's second Engine and the editor World (zones visible in the editor audition) follow the same rule |
| S20 | **Constants that the wire, the core and the docs share** | `MAX_BEDS` 4, `MAX_ZONE_SLOTS` 2, `BED_CHANNELS` 16, bed decoder taps 256, bed fade 45 ms (= HRTF crossfade), fx idle 8 quanta, ring-out frames = IR frames + 2,048, eviction fade 150 ms, clip event code 5 `refusedFormat`, status flag bit 6 `bedDecoderReady`. They live in `schema.rs` (generated): the architect quotes them by name, not by value, so a change has one home |
