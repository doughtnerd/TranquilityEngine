# ADR 0351 spike A0: encoder on wasip1, Opus decoder size, ADPCM voice cost, licences

Spike for [ADR 0351](../../../decisions/0351-audio-is-converted-per-platform-at-export-and-shipped-in-loadable-packages.md)
(its "Build plan": S1, S2, S3). It measures the numbers the record estimates. Code and raw results:
[`spikes/audio-encode/`](../../../../spikes/audio-encode/README.md). No shipped crate, wasm output, `src/**` file or
`package.json` was changed. The record isn't edited; amendments are proposed at the end.

## Summary

| Question | Answer |
|---|---|
| Does `audio-encode` build for `wasm32-wasip1` with libvorbis, libogg, libopus, rubato and an IMA ADPCM encoder? | **Yes.** wasi-sdk 25 installed without trouble. One module, **1,483,882 B** with `+simd128` (gzip 487 KB), 1,323,684 B without. Six WASI imports. |
| Does it run in Node and in a browser Worker? | **Yes, in both**, with one catch: Node 22.23.5's `node:wasi` **segfaults** when the module reads a multi-MB stdin through `fd_read`. Bytes must cross through linear memory (reactor exports), never through WASI file descriptors. The browser shim is 52 lines. |
| Vorbis encode speed | **63–71× realtime per core** in wasm at q ≥ 0.3 (Node and Chrome agree), **36–40×** at q 0.1–0.2. Native: 88–89× and 68×. The ADR's "50–100×" holds only for q ≥ 0.3. |
| Opus encode speed | **80–83× realtime** including 44.1 → 48 kHz with rubato's FFT resampler. **Only 40–43×** with the asynchronous sinc resampler, which costs more than the encode itself. libopus alone ≈ 117×. |
| Parallel export | Linear up to 3 workers (cores − 1): 62× → 128× → 171× aggregate for Vorbis q 0.4. |
| Opus in the decoder | libopus 1.5.2, fixed point, compiled for `wasm32-unknown-unknown` with stub headers: **+173.5 KB** (default and AAC builds alike). With symphonia's `adpcm`: +188.5 KB. Default decoder ≈ 978–993 KB: **over the 900 KB gate**. Pre-skip and end trimming checked. |
| Pure-Rust Opus decoder? | Not mature yet. opus-rs (BSD-3, first published 2026-02) works and is as fast, but adds **+285 KB**. symphonia-opus is MPL-2.0 and two weeks old. |
| ADPCM per voice in the core | **+23.0k wasm instructions per voice per quantum** at pitch 1 (×1.80 the render-and-mix of an int16 voice), +34.3k at pitch 1.5, with a branchless decoder that decodes incrementally. The ADR's block-cache design has the same mean, but **a 9.4× spike** when voices cross a block boundary together. |
| Licences | libogg, libvorbis, libopus: **BSD-3-Clause, confirmed** from their COPYING files. rubato: MIT OR Apache-2.0. The encoder also links **wasi-libc (musl, MIT)**, which the ADR doesn't list. Notices go in `THIRD_PARTY_NOTICES.md`, not `PORTS.md`. |

**Go / no-go:** PCM go · IMA ADPCM go (with the incremental decoder) · Vorbis go · Opus encode go · Opus decode go
with libopus and a decoder-gate raise (no-go on pure-Rust decoders for now) · rubato go (FFT resampler for fixed ratios).

## Machine and method

- **Machine:** this session's container, a shared VM. 4 vCPU Intel Xeon @ 2.10 GHz, 15 GB RAM.
  - `uptime` at the start: `17:35:01 up 12:03, load average: 3.35, 5.10, 5.12`.
  - Timed runs: load 1.5–2.6. Other agents were sharing the VM, so wall times carry about ±15%. One ADPCM wall-time run was at load 5.2.
  - Instruction counts (S3) don't depend on load.
- **Toolchain:**
  - Rust 1.99.1 (the pinned toolchain), plus `rustup target add wasm32-wasip1`.
  - wasi-sdk 25.0 (clang 19.1.5) for the C code.
  - Node v22.23.5 (V8 12.4); Node v24.22.3 only to confirm the crash.
  - Headless Chrome for Testing 153 through Playwright 1.64.1.
- **C sources:** libogg 1.3.5, libvorbis 1.3.7 and opus 1.5.2, from their GitHub release tarballs. The SHA-256 sums match Xiph's published ones (`fetch.sh`).
  - Compiled by `cc` in each crate's `build.rs`.
  - The encoder uses the float libopus build without DNN; the decoder uses the fixed-point build.
- **Builds:** release, LTO, `codegen-units = 1`, `panic = "abort"`, stripped, as `native/audio`'s profile.
  - The encoder reactor is the crate's `cdylib`. Its exports: `spike_alloc`, `spike_encode(ptr, len, codec, quality, rate, complexity)`, `spike_out_*`, `spike_stats_*`.
  - Times are taken inside the module with `std::time::Instant`, which is WASI `clock_time_get`. They cover the encode only, not instantiation or copies.
- **Input:**
  - `town44.wav`: `samples/flappy/music/town.mp3` decoded to 44.1 kHz stereo int16, 82.34 s of music. It is band-limited by the MP3, so it is a little kind to the encoders.
  - `noise44.wav`: 30 s of pink noise plus a 440 Hz tone, the broadband worst case.
  - Each figure is the median of 3 runs.
- **Quality mapping as in ADR §2:**
  - Vorbis: libvorbis VBR `q = quality`, so 0.4 is `-q 4`.
  - Opus: 16 + 112 × quality kbps per stereo pair, VBR, complexity 10, 20 ms frames, `OPUS_APPLICATION_AUDIO`.
- **Correctness:**
  - ffmpeg decodes every Ogg Vorbis and Ogg Opus output cleanly.
  - Vorbis has the exact source frame count (3,631,104).
  - Opus has 3,952,223 frames after pre-skip 312 and end trimming. 3,631,104 × 160/147 is 3,952,222.04; rubato rounds up by one.
  - The spike's libopus decoder (S2) gets the same count.

## S1. The encoder on wasm32-wasip1

### Size

| Build (all `wasm32-wasip1`, release) | Bytes | gzip -9 |
|---|---|---|
| All codecs, scalar | 1,323,684 | 438,235 |
| **All codecs, `+simd128`** (Rust `-C target-feature=+simd128`, C `-msimd128`) | **1,483,882** | 487,178 |
| All codecs, `+simd128`, `opt-level = "s"` / `-Os` | 1,215,164 | 404,589 |
| `+simd128`, no C (PCM, ADPCM, rubato, WAV reader) | 449,057 | — |
| `+simd128`, + libvorbis/libogg only | 1,174,366 (+725 KB over no-C) | — |
| `+simd128`, + libopus only | 781,220 (+332 KB over no-C) | — |

libvorbis's encoder dominates, mostly its static mode, codebook and psychoacoustic tables. The SIMD build is **16 KB
under the record's 1.5 MB tripwire** (read as 1,500,000 B), so the first added feature will cross it.
`-Os` saves 269 KB at no loss in codec speed (Vorbis 62×, Opus-with-FFT 78.5×). It does make the sinc resampler 3.3×
slower (26× instead of 86×), because the sinc loop no longer vectorises. The FFT resampler under `-Os` wasn't measured.

### Imports and hosts

The reactor imports exactly six WASI functions: `fd_write`, `random_get`, `clock_time_get`, `environ_get`,
`environ_sizes_get` and `proc_exit`. That is the ADR's list plus the two environment calls, which return an empty
environment.

- **Node (`node:wasi`, `run-node.mjs`):** `new WASI({ version: "preview1" })`, then `wasi.initialize(instance)`, then
  the exports. Workers are `worker_threads` sharing one compiled `WebAssembly.Module`.
- **Browser (`browser/wasi-shim.js`, 52 lines, no dependency):** a module Worker per job batch. `fd_write` goes to the
  console, `random_get` to `crypto.getRandomValues`, and `clock_time_get` reads `performance.timeOrigin + now()`.
  `@bjorn3/browser_wasi_shim` isn't needed, so there is no devDependency to list.
- **Blocker found: Node 22.23.5 crashes in `node:wasi`.** A WASI *command* that reads stdin with `fd_read` segfaults
  the process once the input passes about 8 MB. A 6 MB input works; a 9 MB one crashes.
  - Backtrace (gdb): `uvwasi_fd_read` → `NgLibMemoryManager::ReallocImpl` → `Heap::ReportExternalMemoryPressure` →
    a full GC *inside the fast-API callback* → `IterateTurbofanOptimizedFrame` (SIGSEGV).
  - Reading in 1 MiB chunks doesn't help: the pressure accumulates.
  - Node 24.22.3 runs the same module fine. The project pins no Node version (`package.json` has no `engines`).
  - **The fix is the design anyway:** pass bytes through linear memory (`spike_alloc`, then `spike_encode`). The
    reactor never touches a file descriptor except stderr for panics.

What the numbers mean:
- **wasm vs native:** Vorbis runs at 0.75–0.8× native speed, libopus at about 0.85×, and ADPCM at 0.65×.
- **Node and Chrome agree within noise.** The editor's Worker path is as fast as the CLI's.
- **`+simd128` matters only for rubato's sinc resampler (3.4×).** The C encoders don't auto-vectorise usefully.
- **Low Vorbis qualities are slower.** q < 0.3 costs about twice q ≥ 0.4, which matches libvorbis's lower modes
  doing more work.
- **The resampler choice matters more than the codec.** With the asynchronous sinc resampler, 44.1 → 48 kHz takes
  1.3–1.5 s for 82 s of audio, against 0.7 s for libopus itself. rubato's synchronous `Fft` resampler does the same
  fixed ratio in 0.29 s, at quality equal or better for a fixed ratio.
- **Cold-cache export estimate:** 3 workers × ≈ 65× ≈ 195× realtime. An hour of WAV/FLAC sources converts to Vorbis in
  about 20 s on this VM.
- **Memory:** a module instance peaks at 73–132 MB of linear memory for an 82 s stereo clip. The input, the f32 copy
  and the resampled copy are all whole-clip. Fine for the CLI pool; a Studio Worker should stream long files in
  chunks, or cap concurrent jobs.

### What the fallback would have left

wasi-sdk installed, so no fallback was needed. Without it, the pure-Rust part covers PCM, IMA ADPCM, resampling and
downmix (449 KB). It has no Vorbis encoder, because no mature pure-Rust one exists. Opus would come from a young pure-Rust
encoder: opus-rs and opus-pure (BSD-3) both encode, but neither was evaluated for quality.
rubato's own dependency tree already contains `audio-codec-algorithms` 0.8.1 (0BSD OR Apache-2.0), which has an IMA
ADPCM encoder and decoder (WAV/MS and IMA4 layouts). That would be an alternative to writing our own; the spike wrote its
own (`encode/src/adpcm.rs`, 150 lines) for the core's block layout.

## S2. Opus decoding in `audio-decode`

Method: `decode-size/` links the shipped `audio-decode` crate unchanged, as an rlib in a `cdylib` that keeps its C ABI.
- It is built exactly as `build.mjs` builds the decoder: `+simd128`, CARGO_HOME remapped, `--strip-all`.
- The baseline differs from the committed wasm by +9.4 KB: the crate name, `spike_alloc`, and absolute source paths in
  panic locations. **Deltas are measured between same-flag builds.**
- libopus is compiled `FIXED_POINT`, `DISABLE_FLOAT_API` and `-ffreestanding`, against four stub libc headers
  (`cstub/`). `malloc`, `calloc`, `realloc`, `free` and `abort` come from Rust's allocator. **No imports remain**, so

- All of CELT, SILK and `src/` is compiled; `--gc-sections` keeps only what `opus_decoder_create` and `opus_decode` reach.

## S3. ADPCM per-voice decode cost

Method: `adpcm-bench/` renders N looping stereo voices through the core's own voice resampler,
`audio_dsp::resample::lagrange` (the 4-point kernel), and sums them into a stereo mix, 128 frames a quantum.
- The wasm (`+simd128`, release) is instrumented by `tools/audio-bench/meter.mjs`, the metered gate's pass: every wasm
  instruction counts 1.
- 400 warm-up quanta, then 750 counted (2 s at 48 kHz, as the gate).
- The clip: 188 blocks of 1,024 frames (≈ 4 s) of a synthetic signal.
- Only the voice's source differs between modes:
  - `int16`: the clip's samples, as format I16 today.
  - `block`: ADR §3's design, a 1,024-frame cache per voice (plus the kernel's 1 + 2 neighbour frames), filled with a
    whole block when the read position enters it.
  - `incremental`: each quantum decodes only the frames it will read into a small sliding window, carrying the IMA
    state; block headers reset it.
  - `incremental-fast`: the same with a branchless, bounds-check-free step, two nibbles per byte.
- All three ADPCM modes produce **bit-identical** mixes (same probe values).
- "Staggered" voices start at random offsets. "Aligned" voices all start at frame 0, so block mode's boundary crossings
  coincide.

Instructions per quantum, 256 voices:

| Mode | Pitch | Mean | Max | Per voice (mean) | Extra per voice vs int16 | × int16 |
|---|---|---|---|---|---|---|
| int16 | 1 | 7,357,782 | 7,358,708 | 28,741 | — | 1 |
| block, staggered | 1 | 15,132,288 | 17,069,182 | 59,111 | +30,369 (max +37,932) | 2.06 |
| block, **aligned** | 1 | 15,145,334 | **69,364,255** | 59,161 | max **+242,209** | max **9.4** |
| incremental | 1 | 15,610,929 | 15,623,711 | 60,980 | +32,239 | 2.12 |
| **incremental-fast** | 1 | **13,236,340** | 13,249,439 | 51,704 | **+22,963** | **1.80** |
| int16 | 1.5 | 7,357,783 | 7,358,398 | 28,741 | — | 1 |
| block, staggered | 1.5 | 19,009,210 | 22,158,301 | 74,255 | +45,513 | 2.58 |
| block, aligned | 1.5 | 19,035,987 | 69,414,175 | 74,359 | max +242,405 | max 9.4 |
| incremental-fast | 1.5 | 16,140,173 | 16,153,631 | 63,048 | +34,306 | 2.19 |

The per-voice figures are the same at 32 and 128 voices (within 0.1%); see `results/adpcm-bench.jsonl`.

- **Against the real core:**
  - The gate's `automation-base` scene, 256 plain looping voices, costs 10,051,149 instructions a quantum, or
    **39.3k per voice** for everything: resampling, ramps, pan and buses.
  - An ADPCM voice adds 23.0k (fast incremental decoder, pitch 1). **A voice costs ≈ 58% more; at pitch 1.5, ≈ 87%
    more.**
  - 256 ADPCM voices: about 10.1M → 15.9M a quantum.
  - A metered-gate scene for ADPCM voices will need its own baseline. Existing scenes don't move, because ADPCM is a
    new format.
- **Wall time** (unmetered, Node, load 5.2, indicative): int16 2.1–2.4 µs per voice a quantum, ADPCM 3.1–3.8 µs. That
  is +1.0–1.4 µs per voice, or about +250–350 µs for 256 voices against a 2,667 µs quantum. Wall time rises less than
  the instruction count: much of the counted work is `local.get`/`local.set` that the JIT folds.
- **Block cache vs incremental:**
  - The block cache has the same mean cost, but a voice entering a block decodes 2 × 1,024 samples at once.
  - When voices cross together (a sequence of starts on one stamp, a synchronised layer, a loop of a common length),
    one quantum pays **9.4× an int16 quantum**. That is a deadline risk on a phone.
  - Incremental decoding is flat; its max is within 0.1% of its mean.
  - Seeks and loop starts still decode from the block start up to the target frame (≤ 1,023 samples per channel),
    once.
- **Memory (the reason for ADPCM):**
  - Layout: 516 B per channel per 1,024 frames, against 2,048 B for int16 (**3.97:1**).
  - The incremental window is 1,028 frames × 2 channels × 2 B ≈ 4 KB per voice, in the voice pool.
  - The block cache is the same size.

**How the project tracks notices:**
- `THIRD_PARTY_NOTICES.md` at the repository root has one section per compiled module ("Audio core", "Audio decoder",
  "HRIR data"…). Each entry gives the crate or library, version, licence, copyright and upstream.
- `native/audio/PORTS.md` is only for **ported Chromium files**, with the header rule checked by
  `src/plugins/audio/portsNotices.test.ts`. The ADR's "notices in `native/audio/PORTS.md`" is the wrong place.
- Vendored C sources follow the `native/audio/third_party/libebur128/` pattern: the licence file plus a `PROVENANCE.md`
  with SHA-256 sums.
- Nothing copies `THIRD_PARTY_NOTICES.md` into a game export today. BSD-3 binary redistribution needs it once libopus
  is in every game's decoder; see amendment 9.

   `*.rs`, `Cargo.toml` and `Cargo.lock` under `native/audio/`, skipping only directories named `target`, `vectors` or
   `tests` (`crates/audio-wasm/source_hash.rs`). Any crate there would have changed the hash and the committed outputs.

## Recommended amendments to 0351 (for a superseding or amending record)

1. **§4 Encoder size tripwire:** the full encoder with `+simd128` is 1,483,882 B, 16 KB under 1.5 MB. Set the tripwire
   at **1.75 MB**, or build with `-Os`/`opt-level = "s"` (1.22 MB, same codec speed) once the sinc resampler is gone.
   Either way, record it in the build log.
2. **§4 Resampling:** use rubato's **synchronous `Fft` resampler** for every fixed-ratio conversion (the sample-rate
   ceiling and Opus's 48 kHz). It runs at 296–310× realtime in wasm, against 86–134× for async sinc. On the Opus path,
   the sinc resampler costs twice the encode. Keep sinc only if a non-rational ratio ever appears. Build the encoder
   with `+simd128`.
3. **§4 Encoder host ABI:** the module is a WASI **reactor** with memory-passing exports (alloc, encode, out ptr/len).
   No byte goes through `fd_read`/`fd_write`, because of Node 22's `node:wasi` crash. The shim's import list is the six
   named above, adding `environ_get`/`environ_sizes_get` to the record's four. The shim measured 52 lines; "≤ 60" holds.
4. **Consequences, encode speed:** "Vorbis encode is roughly 50–100× realtime per core" becomes "**63–71× at q ≥ 0.3,
   36–40× at q < 0.3** in wasm (one core of a 2.1 GHz Xeon VM); **Opus ≈ 80×** including resampling with the FFT
   resampler; linear to cores − 1". Low Vorbis qualities cost twice as much; Android's 0.35 profile is fine, below 0.3
   isn't.
5. **§4 Opus decode:** libopus fixed point adds **+173.5 KB** (+78 KB gzip) to both decoder builds. Raise the default
   decoder gate from 900 KB to **1,000 KB** and the AAC gate from 1,280 KB to **1,350 KB**, with a build-log note. A
   pure-Rust decoder isn't mature enough (opus-rs adds +285 KB). The C needs no libc: stub headers with
   `-ffreestanding`, plus `malloc`/`free` from Rust's allocator. **No wasi-sdk is needed for the decoder**: the
   spike built it with the system's clang (Ubuntu clang 18.1.3, wasm32 target). Pin one clang (wasi-sdk's, for both
   modules) so the committed decoder is reproducible.
6. **§3 ADPCM in the core:** decode **incrementally per quantum** (the frames the kernel will read, carrying the IMA
   state; block headers reset it). Don't decode a whole block when the read position enters it: the mean is the same,
   but aligned voices make one quantum cost 9.4× an int16 quantum. The 1,024-frame block and its header stay; they bound
   seek cost (≤ 1,023 samples decoded per channel, once). Budget **+23k wasm instructions per voice per quantum at
   pitch 1, +34k at 1.5** (≈ +58% / +87% of a voice in today's core). The branchless step bought 29% over the naive
   one. Add an `adpcm` metered scene with its own baseline.
7. **§3/§4 ADPCM layout and symphonia:** the core's planar 1,024-frame block (one 4-byte header per channel: the
   predictor set to the block's first sample, then the step index) isn't WAV IMA ADPCM. WAV IMA uses 1 + 8k frames per
   block with interleaved 4-byte groups, so **symphonia's `adpcm` feature can't read the shipped blocks**. Either share
   the core's block reader with the decoder worker (Babylon fallback, prefetch heads) and drop symphonia `adpcm`
   (saves 15 KB), or keep `adpcm` only to read IMA/MS ADPCM *sources* users import. The spike's encoder reaches 36.7 dB
   SNR on music and 28.2 dB on noise.
8. **Consequences, notices:**
   - "notices in `native/audio/PORTS.md`" becomes **`THIRD_PARTY_NOTICES.md`**, with vendored sources under
     `native/audio/third_party/{libogg,libvorbis,opus}/` and `PROVENANCE.md`, as libebur128 has.
   - Add **wasi-libc/musl (MIT)** to the encoder's notice list.
   - The proposed text is above.
9. **New:** once libopus is in every game's decoder, BSD-3 requires the notice in what a game ships. Make
   `npm run export` write the audio modules' notices beside the player (for example `THIRD_PARTY_NOTICES.txt` in the
   build). This also covers Symphonia's MPL-2.0 notice, which builds don't carry today.
10. **Build plan:** the spike results path should read `docs/design/audio-studio/spikes/0351-a0.md`.
11. **Memory:** the encoder holds whole clips: 73–132 MB of linear memory for an 82 s stereo clip. The CLI pool is fine;
    the Studio's Worker should cap concurrent encodes or encode long files in chunks.
