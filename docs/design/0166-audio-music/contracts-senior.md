# 0166 interactive music: contracts the senior engineer needs from `architecture.md` (round 2B)

Each contract is a value, a gate or a state machine that `api-and-models.md` (the **API**) assumes. The architect owns constants, timing, memory and failure behaviour; I own every byte layout, setting, the event format and the public signatures, and publish constants by name (S11). **Status** is after round 2A and the coordinator's rulings (R1-R24); `[?]` marks a number I could not take from a measurement. `§n` points into the API; **[ARCH §n]** into `architecture.md`.

| S1 | **Prime lead, deadline, minimum latency of a quantised change** | Lead = 1.25 x Ê + L + Δ̄ for a group with unprimed streamed members, L for a decoded or already-primed one (R12, [ARCH §4.1]); Ê seeded 40 ms, EMA 0.5 up and 0.1 down, measured from the request to the batch that sees every primed bit, without Δ̄, never sampled while hidden. A re-plan never becomes a refusal; only the pool refuses (R14). Guide figure: least delay from a parameter change to a quantised landing = the lead (about 100 ms default for streamed targets, L for decoded or primed) plus the wait to the grid point | **met**; the architect adds the floor sentence to [ARCH §4.2] |
| S2 | **Group gate state machine** | PLAY `gate`: 10-bit id, 6-bit size (§4.1, R8); 16 core entries (R9), freed at the start or the report.
