# 0166 interactive music: contracts the senior engineer needs from `architecture.md` (round 1)

Each contract is a value, a gate or a state machine that `api-and-models.md` (the **API**) assumes. The architect owns constants, timing, memory and failure behaviour; I own every byte layout, setting, the event format and the public signatures, and publish constants by name (S11). **Status** says what I proposed from the spikes so the architect can accept or change it; `[?]` marks a number I could not take from a measurement. `§n` points into the API.

| # | Need | Shape assumed | Status |
|---|---|---|---|
| S1 | **Prime lead, deadline and the minimum latency of a quantised change** | Lead L_p = max(`Audio.horizon` lead, 1.25 x EMA of measured group prime times), initial 100 ms (record item 4). Main stamps a group only when every stem's ring is in `primed` (§4.4), at the latest T - L_p - one display frame (the batch leaves the frame after the bits arrive). If the bits are late it re-plans to the next grid point. I need the EMA's smoothing constant and floor, how many re-plans before a refusal, and the figure I put in the guide: the least time between a parameter change and a quantised landing (horizon at least 21.3 ms plus prime, about 100 ms worst case) | proposed; the EMA constants and the re-plan limit are the architect's |
| S2 | **Group gate state machine in the core** | PLAY carries `gate` (id 1..4095, size 1..16, §4.1); members arrive in one BATCH with one `frameOffset`. I need, row by row: **complete** (all `size` members present when the stamp's quantum begins; what happens if one is missing: start those present, or wait a bounded time, or cancel and report); **ready** (a stream member holds at least `START_FRAMES` 4,096 buffered frames or its input ended; a decoded member is always ready); **on time** (all ready at the stamp's quantum: every member starts at its stamped sample); **late** (any not ready: all wait and start at sample 0 of the first quantum where all are ready, and the slip is reported per voice with the exact start frame, `groupStarts`); a member STOPped or demoted to virtual while waiting (the group shrinks, or the gate ignores it); the longest wait and what it does when a ring never primes (give up, report, free the members); RESET. I need the exact rule and whether a refused transition retries on the next grid point or waits for the next parameter change | open |

| S8 | **Failure behaviour** | I need a ruling for each: a stem whose clip fails to load or decode (play the segment without it plus a warning, or refuse the segment); a worker crash mid-prime (re-plan, then refuse); a stream error mid-play (the group continues without that stem; `streamEvents` code 3); a stem of a different length that passed the lint within 1,024 frames (the shortest wins); `groupStarts` never arriving for a group that did start late.
