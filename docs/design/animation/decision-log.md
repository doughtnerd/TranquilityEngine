# Animation build: decision log

Decisions made during the build that the records didn't settle. Each entry: the question, the choice, why, how to revert. Numbered D1, D2…

- **D1 (planning).** *Value tracks before gate A.* Compiled clips store uniformly resampled values (0371), so value tracks play linearly from the resampled data before the shared Bézier evaluator exists. T70 adds the evaluator for source curves, tween easing curves and runtime curve tracks. *Revert:* make T20a wait for gate A.
- **D2 (planning).** *Toolchain.* `native/anim/` pins Rust 1.99.1 (audio's pin) and uses wasm-bindgen 0.2.130 (nav's pin) for setup glue. Per-frame data crosses through typed-array views, as 0370 says.
- **D3 (planning, owner).** *Build order.* Phase R builds the Rust core now; the audio branch merges (gate A); Phase B builds everything else on top of it. 0370's sentence on the curve-crate move was updated to say so. *Revert:* none needed; the order changes nothing in the records' requirements.
- **D4 (review).** *0375 was factually wrong:* `BallJoint` already had twist and scalar swing limits. The record's context and decision were corrected in place (noted in the record): T43 migrates `swingLimit` to elliptical `swing` and adds the drive. *Revert:* n/a.
- **D5 (review).** *`play()` without a graph* runs through a minimal graph program from T13r, so there is one evaluation path (0372's implicit single-layer graph). *Revert:* a separate clip-player path in T13r, rebuilt later.
- **D6 (T02).** *Crate edges:* `anim-graph` depends on `rig`, `retarget`, `match`, `physics` and `plugin-sdk` (its node families call them); those depend only on `math`, `format`, `pose` (and `sample` for `match`). *Revert:* move node families into the solver crates.
- **D7 (T02).** *`anim-format` has no dependencies; `anim-offline` depends only on `format`,* so the reference shares no code with the fast path and there's no dev-dependency cycle.
- **D8 (T02).** *`+simd128` in `native/anim/.cargo/config.toml`,* included in the source hash; `build.mjs` clears inherited RUSTFLAGS. *Revert:* pass the flag from `build.mjs` as audio does.
- **D9 (T02).** *Opcode = family id << 8 | kind;* per-family versions with exact-match decoding; test vectors as per-family JSON in the crate (no test-only TypeScript exports).
- **D10 (T10).** *Bone matrices are row-major 3×4* (three vec4 rows, translation in the fourth column), 12 floats per bone. *Revert:* transpose in `Mat3x4T`.
- **D11 (T10).** *TRS follows Unreal's `FTransform`:* per-component scale, no shear; the TRS inverse is exact for uniform scale, `Mat3x4T::inverse_or` is exact always. *Revert:* accumulate in matrices.
- **D12 (T10).** *Skeleton parents are `u16` with `NO_PARENT = 0xFFFF`, parents first.* T03r was told to match.
- **D13 (T10).** *glam only for conversions,* because its backends order operations differently and would break bit-identity between wasm and native.
- **D14 (T03r).** *Formats refuse unknown sections and flag bits* and require canonical layouts; writers re-parse their output. *Revert:* skip unknown kinds in `container::parse`.
- **D15 (T03r).** *Compressed bone tracks split into rotation (drop-w or full), translation and scale channels,* with an 8-bit range per channel per segment and bit rates {0, 3–16, 19, 23, 32 = raw}.
- **D16 (T03r).** *Every key is 32 bytes* with per-kind meaning, so TypeScript indexes one table.
- **D17 (T12).** *Blends use nlerp;* no positive weight gives the rest pose.
- **D18 (T12).** *Mirror is a local sign flip assuming mirrored local frames.* Rigs with flipped-axis conventions need a per-bone flip table in the skeleton profile: added to T41's scope.
- **D19 (T12).** *Inertialization:* a scalar offset per channel (translation vector, rotation axis-angle), a0 = 0, blend time clamped to `min(T, 2.5·|x0|/|v0|)` (the exact no-overshoot bound for a0 = 0 is 2.50087; Bollo's 5 overshoots); scale isn't inertialized; under 1e-4 s is a cut.
- **D20 (T12).** *Sync phase* = (marker index, id, fraction, normalised time), falling back to normalised time when a clip lacks the marker.
- **D21 (T11).** *Shell distance per bone* = max(3 cm, longest child offset in the rest pose).
- **D22 (T11).** *Bit-rate search* raises the channel with the best drop in excess error per added bit (excess = Σ max(0, e − bound) over the segment's frames). A plain lowest-maximum rule pushed root channels to raw and cost about 12%.
- **D23 (T11).** *Default and constant detection* at 0.1 × bound locally, screened in model space at 0.2 × bound, with a fallback that animates the worst channel and reruns.
- **D24 (T11).** *Rotations drop w by default;* both formats are tried when any |w| < 0.1.
- **D25 (T11).** *Root yaw* is the swing-twist yaw about +Y, relative to frame 0 and unwrapped, through anim-math's deterministic `atan2`.
- **D26 (T11).** *Additive clips* get constant detection only; their error is measured on the delta pose (an approximation).
- **D27 (T20r).** *Window rule:* forward `(a, b]`, reverse `[b, a)`; a start flag includes `a`; at a loop point the end key fires before the key at 0; each key fires once.
- **D28 (T20r).** *Seeks fire no keys;* notify states don't begin or tick but still end, so `end` always follows `begin`; activation edges are still reported.
- **D29 (T20r).** *Notify states are level-based on weight > threshold;* audio and control keys fire at any weight above 0 and carry it; markers are never gated.
- **D30 (T20r).** *Ranges are `[time, end)`;* in non-looping clips activation and subclip ranges ending at the duration hold the end. Discrete before its first key holds the first key's value (Unity). Window deltas are capped at four durations.
- **D31 (T13r).** *Implicit graph:* two players and a crossfade per layer (Animancer's model); a play arriving mid-fade cuts and inertializes (Unreal's advice).
- **D32 (T13r).** *Inertialization is a node at the output* that stores its captured poses in the state blob, so transitions survive snapshot and restore.
- **D33 (T13r).** *Alpha:* a pose carries how much of it is real; fades from nothing come from the rest pose.
- **D34 (T13r).** *Update every frame, pose when due;* LOD shows a lerp with one step of latency. `whenVisible` freezes pose and root motion; `rootMotionOnly` keeps root motion.
- **D35 (T13r).** *Root delta* is in the character's frame at the step start (clip frame-0 heading = rest heading). Layers give no root motion.
- **D36 (T13r).** *Columns:* the highest-weight clip fills the column block (blended columns later); at most 256 notify states per clip. Clip references in graph assets bind through a per-graph table (`graph_bind`).
- **D37 (T40).** *Rig weights* blend each local as nlerp(input, solved) with solved locals taken against solved parents (Animation Rigging).
- **D38 (T40).** *Joint limits* are swing-twist about local +X relative to the rest rotation, with an elliptical swing cone pulled radially (PhysX style).
- **D39 (T40).** *Full-body sub-bases* (hips, chest) are fitted to their children by an iterative weighted rotation fit; fitting to the first child alone missed hands by 1 cm.
- **D40 (T40).** *Spring bones* use Störmer-Verlet (k·h² ≤ 1) with dynamic follow-the-leader (Müller 2012), simulated in world space so locomotion gives inertia; an implicit spring varied 20 cm with dt.
- **D41 (T40).** *Grounder* rays and hits are in model space (the host converts); a miss returns the foot to its animated height; the pelvis only lowers by default.
- **D42 (T40).** *Motion warp* uses smoothstep and rotates the path about its start with the yaw, so the root never slides sideways; it matches position and yaw only.
- **D43 (coordinator, from T22r).** *A looping play's first window* includes the key at its start but not the key at `d` (and, backward, not the key at 0): no previous cycle has ended. Amends D27.
- **D44 (T22r).** *Tween and timeline control* goes through direct exports taking one wire record each (creation isn't per-frame); kill and destroy records appear at the next `evaluate`; capacities are set by `tweens_configure`/`timelines_configure`, not the `Init` record.
- **D45 (T22r).** *Yoyo* runs `ease(1 − p)` on odd cycles (DOTween); endpoints are exact; weight 0 in a timeline's output means leave the field alone, partial weights mean the host blends.
- **D46 (T22r).** *A timeline is a `myco.anim@1` clip used as a timeline* (no new format); overlapping entries on a track crossfade (f32 weighted, quaternions sign-aligned nlerp, u32 heaviest); only depth-1 entries contribute values.
- **D47 (T41).** *Retargeting* transfers model-space rotation changes from rest with optional rest-direction alignment per chain (Unreal's IK Retargeter); chains are bone paths resampled by normalised rest length; hand and foot goals are measured from the target limb root and scaled by that limb's own length ratio (a refinement of 0372's "scaled by leg length": arms use the arm ratio); the root scales by the leg ratio per axis. *Revert:* `align_chains: false`; scale every goal by the leg ratio.
- **D48 (T41).** *Mirror flips* are a per-bone half turn about X, Y or Z that also undoes the parent's, derived from the rest pose unless the profile sets one (`mirror_flipped`).
- **D49 (T41).** *Retarget depends on `anim-rig` (pinning) and `anim-sample` (bake),* amending D6; `anim-compress` only behind the offline `compress` feature.
- **D50 (T31).** *Update contexts:* only active states, picked children and weighted blend-space samples advance; a state is re-initialised on entry (Unreal relevance, Unity restart).
- **D51 (T31).** *Interruptions* keep a blend stack of up to 4 entries; when full the oldest drops and an ancestor inertialization is requested. Any-state transitions are tried first and skip the current state; mid-transition, only the current state's and any-state transitions can interrupt (Unity).
- **D52 (T31).** *Requests* are consumed only when a transition reading them fires and expire after their lifetime (default 0.25 s).
- **D53 (T31).** *`exit`* means an exit marker was crossed, else the clip end, or a sub-machine in an exit state. Fade shapes 0–3 are linear, smoothstep, ease-in, ease-out until audio 0350's ids are fixed.
- **D54 (T31).** *Travel* uses breadth-first next-hop tables, ties to the higher priority; a hop's condition is ignored but its `when` and interrupt rules apply (Godot). Unreachable targets are refused.
- **D55 (T31).** *Names across tables* match by FNV-1a hash. The random seed defaults to 0x9E3779B9; `SET_SEED` reseeds.
- **D56 (T31).** *Linked graphs* declare capacities in the node so the state blob stays fixed-size and snapshots exact. The blackboard has 64 parameters per row with dirty masks, applied before commands.
- **D57 (T42).** *One-shot clip frames whose future runs past the end are excluded from the database;* looping clips wrap with the loop's root displacement.
- **D58 (T42).** *Per-dimension normalisation by default* (std floor 0.01; Holden's per-feature mode available); weights are folded into the runtime copy as √weight, not stored in the file.
- **D59 (T42).** *A forced search fires on the trajectory cost against the continuation frame;* a filtered-out or finished continuation switches at once, ignoring the minimum switch time.
- **D60 (T42).** *Character space:* yaw 0 faces +Z; +X is "right" in Babylon's left-handed frame. Defaults: search every 6 updates, bias 0.1, minimum switch 0.2 s, skip ±6 frames.
- **D61 (T45).** *Plugin poses are array-of-structs,* 10 floats per bone in local space; the core converts from SoA. One call evaluates a batch of one node kind on one skeleton.
- **D62 (T45).** *The core owns plugin node state* and copies it in and out each call, so state survives a module reload after a trap and takes part in snapshots.
- **D63 (T45).** *Plugin modules:* Wasm 2.0 with simd128 plus extended-const; relaxed SIMD (non-deterministic), threads, multi-memory, memory64, exceptions, tail calls and start functions are refused. A missing memory maximum gets the limit.
- **D64 (T45).** *Fuel* is charged per block at its start; a trap fires when fuel goes below 0; a fresh instance starts at 0.
- **D65 (T40g).** *Per-frame rig data* (targets, hits, rays) enters through an `Inputs::rig` struct, outside snapshots; ray rows are cleared before each pose so stale requests never look valid.
- **D66 (T40g).** *Under update-rate LOD,* rig Update accumulates dt and Pose solves and consumes it. A node skipped by LOD or weight 0, or reset by command, forgets its history (springs restart on the animated pose).
- **D67 (T40g).** *Motion-warp windows* are named by cue markers; a late or moving target re-plans from the current frame to the window end.
- **D68 (T40g).** *Distance warping* is a `DISTANCE_MATCH` node gating its input at a computed rate (same-frame exact), not a speed parameter.
- **D69 (T40g).** *An invalid rig parameter block* loads as an unknown node: it passes its input through and is reported once at load.
- **D70 (T41g).** *The RETARGET node runs a nested source graph* on the source skeleton inside its own state words, with declared capacities (like linked graphs), so the blob stays fixed-size and snapshots exact. Retarget scratch lives per map (it holds nothing between frames).
- **D71 (T41g).** *MIRROR flips* are packed into the partner words (bits 16–17); no flips gives the old output exactly.
- **D72 (T41g).** *The raw retarget bake ships in the runtime module;* compression only behind the `editor` cargo feature.
- **D73 (T44r).** *Drive targets* are relative to the parent body, in model space (+Y up); the ragdoll plugin converts them to joint drive space with each joint's rest frames. Stiffness, damping and max force scale by global × bone × multiplier; pins default to 1 on root bodies. Builder defaults: stiffness 400, damping 40, max force 1000.
- **D74 (T44r).** *The drive source* is the first `PHYSICS_BLEND` node's stored animated input, kept in the blob so drives after a restore are exact. Belly up means on the back; anything else counts as on the front.
- **D75 (T42g).** *Matching trajectory inputs come from graph parameters* (blackboard, in the snapshot), not a new input view; the LOD multiplier too.
- **D76 (T42g).** *The matching controller runs one step behind the player* (its time is the pose the query was built from); otherwise the continuation looked a frame off and the search switched needlessly. A switch to within one database frame of the playing frame keeps playing.
- **D77 (T42g).** *The query pose is the instance's pose history* in the root bone's character frame (Unreal's pose history). Tag masks from static words, int parameters and chooser rows are ORed.
- **D78 (T45c).** *Plugin calls are one instance at a time* (count = 1) because the graph pulls poses depth-first; lock-step evaluation by node level is the documented path to batching. A plugin module is an arena asset bound like clips; a fault retries each frame and reports once (the flag is in the blob).
- **D79 (T42g).** *The pose-database bake isn't in the runtime module;* Phase B builds a separate editor wasm for the bake worker.
- **D80 (T82r).** *A per-player frame cache trades memory for speed* (ozz-animation): excluded from snapshots, invalidated by an asset epoch bumped on every release. *Revert:* `Program::pose` instead of `pose_cached`.
- **D81 (T82r).** *The wasm's name section is stripped by default;* `MYCO_ANIM_KEEP_NAMES=1` keeps it for profiling.
- **D82 (coordinator, 2026-11-23).** *The animation records are renumbered 0340–0347 → 0370–0377:* master merged the input-system records 0335–0340, taking 0340. A gap of nine is left because three branches write records concurrently (the audio branch's 0327–0339 also clash with master's and will be renumbered when it merges). Every reference in the records, plan, logs, code comments and the amended records' status lines was updated.
- **D83 (owner, 2026-11-23).** *0377 (the BioPak rename) is withdrawn* while the owner thinks about it; T74 is removed from the plan. Audio keeps `.mycopak`.
- **D84 (coordinator, 2026-11-23).** *Gate A passed:* the Audio Studio branch merged to master (PR #187) and master was merged here. The Studio's records were renumbered 0327–0346 → 0341–0360 on master, which collided with this build's 0350–0357, so the animation records moved again to **0370–0377**; every "audio NNNN" reference now uses the Studio's new numbers.
- **D85 (T05).** *String fields with `choices` count as enums (animatable); lists, plain objects, GameObject references and other classes default to not animatable.* Collider `isTrigger` and `layer` stay animatable (a hitbox toggling is normal), though they rebuild the collider.
- **D86 (coordinator).** *Sub-path animatability:* a `PlainObject` field opts sub-paths in with `animatable: ["targetPosition", …]` (a list of animatable sub-paths); `isFieldAnimatable(type, "spring.targetPosition")` resolves it. T43 implements it with the joint springs; T20t binds such paths.
- **D87 (T15).** *The low-level GPU passes take final WGSL/GLSL text;* the KSL item-kernel layer sits on top (particles keep hand-written glue to stay byte-identical). Item-kernel outputs are interleaved in one vertex-bindable buffer on WebGPU (stride 16 × outputs) and one RGBA32F target per output on WebGL2 (at most four). Lost devices stop work; owners rebuild.
- **D88 (T04).** *Optional-dependency notices* are a separate `notices` list, not `problems` (the player stops on the first problem, but the plugin did activate). A runtime half sees a dependency's runtime half; an editor half sees either half.
- **D89 (T43).** *Ball-joint drives use Rapier's per-axis spherical motors through the raw joint set;* the target quaternion is passed as a rotation vector (exact about one axis; residual grows with combined angles — Rapier's coordinates). `targetRotation` is the turn from the joint's creation pose in the joint frame; T44 writes targets in that frame.
- **D90 (T43).** *The scene format is bumped to 5* for the `swingLimit` → `swing` migration, because per-component migrations (0123) aren't built. A parallel format bump would collide on the number.
- **D91 (T43).** *`drive.targetRotation` is stored as a plain `{x, y, z, w}`* (plain objects are JSON-cloned on load). D86 is implemented: `animatable?: boolean | readonly string[]` with exact (optionally dotted) leaf paths.
- **D92 (T01).** *Frame animation runs at the start of lateUpdate,* before lateUpdate scripts: user update systems sort after built-ins, so in update their parameter writes would land a frame late. This still satisfies 0370 ("after update() scripts"); lateUpdate scripts see this frame's pose (Unity). `FixedEvaluate` runs after fixedUpdate scripts and navigation, before the physics pushes; `PredictedRootMotion` before it and only when physics is active (T33 must keep FixedEvaluate from applying predicted root motion twice).
- **D93 (T01).** *Replicated Animator state is four encoded string fields* (`netStates`, `netSlots`, `netLinks`, `netParameters`), because replication sends Number, Boolean and String fields; T33 may replace them with a replicated data component.
- **D94 (T01).** *`Animator.defaultClip`* (not named in 0372) plays on start without a graph (Unity's legacy Animation, Godot's autoplay); `play` without `slot` on an Animator with a graph is refused with a warning. `TimelineDirector`'s time field is `playhead` (`Component` has `time`).
- **D95 (T01).** *Tweens* start at the next animation update and can be grouped until then (DOTween/PrimeTween); easing defaults to `outQuad` and may be an engine `Curve` (T22t should export `Curve` from `myco`). New asset field kinds: `animgraph`, `animclip`, `skeleton`, `skelprofile`, `timeline`, `sprite` (T03t registers them).
- **D96 (T01).** *Component lifecycle goes through `LifecycleHooks` objects filled by feature files,* so later tasks never edit component files. `frameFor` returns null until T13t, so stages do nothing until the core loads.
