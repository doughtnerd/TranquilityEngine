# 0428. The UI closes its remaining CSS, text, scrolling and tooling gaps

- **Status:** Accepted
- **Date:** 2026-11-26
- **Deciders:** Chris Carlson
- **Supersedes:** —
- **Related:** 0418, 0419, 0423, 0424, 0425, 0426, 0370

## Context

The UI program (0417–0427) is built. Its records and their as-built notes list what was left out. The owner asked to cover those gaps. Some were deferred by a record ("part pseudo-elements in a later record", 0424; "`backdrop-filter` is left out", 0426). Others were left as not built in as-built notes:

- **Selectors and values:** `:has()`; `em`/`rem`/viewport units; `transition-behavior`, `linear()`, shortening a reversed transition, and inheritance passing through children mid-transition.
- **Text:** `white-space` modes; `:hover`/`:pressed`, padding, margins and borders on inline runs; inline blocks (a button inside a paragraph); SVG and media inside text.
- **Scrolling:** scroll snapping, `scrollbar-gutter`, and scrolling for `*-reverse` directions and right-to-left text.
- **Tooling:** type checking inside `.svelte` files.
- **Build hygiene:** committed wasm builds embed the building checkout's absolute path.

## Decision

**We will close every gap above, following the web standards where they exist.**

- **Selectors and values (0418's cascade):**
  - `:has()`, with relative selectors, restyling when descendants change;
  - `em` (the element's font size), `rem` (the root canvas element's), and `vw`/`vh`/`vmin`/`vmax` (the canvas in UI pixels, as 0418 wave 5's `@media` uses), anywhere a length is accepted, including `calc()`;
  - `transition-behavior: allow-discrete`, and the `linear()` easing as engine curve keys;
  - CSS's shortening of a transition reversed partway (the reversing-shortening factor);
  - inherited values passing through to children while a parent's property transitions.
- **Pseudo-elements:**
  - `::before` and `::after` with `content` (strings, `attr()`, counters out of scope), generated as hosted elements the cascade styles and the UI core lays out;
  - `::placeholder` and `::selection`;
  - **form part pseudo-elements** with standard names where they exist (`::file-selector-button` doesn't apply) and the WebKit and Blink names authors already use: `::-webkit-slider-thumb`, `::-webkit-slider-runnable-track`, `::-webkit-progress-bar`/`-value`, `::-webkit-meter-*-value`, a checkbox's mark through `accent-color` plus `::checkmark`, a select's arrow through `::picker-icon`. 0424's parts become styleable through them.
- **`backdrop-filter`:** 0426's filter functions applied to what's drawn behind the element, within its box. Drawn by sampling the canvas texture under the box into an offscreen canvas, filtering it with `ctx.filter` or the fallback, then drawing it under the element's background. It costs a readback per backdrop element per redraw.
- **Text (0425's inline layout):**
  - `white-space`: `normal | nowrap | pre | pre-wrap | pre-line | break-spaces`, with `white-space-collapse`/`text-wrap-mode` as longhands;
  - runs gain `:hover`/`:active` (pointer state per run), and padding, margins and borders, laid out as inline boxes;
  - `display: inline-block` (and form controls, buttons, SVG and media inside text) lay out as atomic inline boxes on the line, with their own Yoga subtree.
- **Scrolling (0423):**
  - `scroll-snap-type`, `scroll-snap-align`, `scroll-snap-stop`, `scroll-padding` and `scroll-margin`, honoured by wheel, drag momentum, keys, `scrollTo` and navigation;
  - `scrollbar-gutter: stable [both-edges]`;
  - `*-reverse` directions and right-to-left text start and scroll from the end, as in CSS.
- **Type checking inside `.svelte`:** `svelte2tsx` (the svelte-check transform, MIT, pinned exact) turns each component into TypeScript for the editor's existing TypeScript service. Diagnostics map back to `.svelte` positions, show in the Code panel and run in Play's type check. It's an editor-only dependency; games never load it.
- **Reproducible wasm builds:** every native build passes `--remap-path-prefix` (and `CARGO_ENCODED_RUSTFLAGS` where the build script sets flags), mapping the workspace root to a fixed name. Builds from any checkout or worktree are then byte-identical, and the committed wasm is rebuilt once with it. This sits beside the pending `wasm-opt` note.
- **Out of scope still:** counters and `content` images, `::first-line`/`::first-letter`, `:has()` inside `:has()`, physical-unit lengths (`cm`, `in`), and SVG filters.
- **As built (G1, selectors and values):**
  - **`:has()`** is a compound field (`SimpleSelector.has`: lists of relative selectors, the first part carrying its leading combinator), read by the selector reader for rule data and queries alike, so games stay parser-free. Matching searches the anchor's descendants (`" "`, `>`) or later siblings and their descendants (`+`, `~`), only one level when the relative selector has one compound. Specificity adds the most specific argument's. `:has()` inside `:has()` is refused by both readers.
  - **Restyling `:has()`, cost-aware.** Only when a registered sheet uses it (`hasUse`): an element made, moved or removed, or a change to its attributes, emptiness or pseudo-class state, marks its ancestors (and with `+`/`~`, the earlier siblings of it and of each ancestor) whose tag, id and classes fit some `:has()` compound (`couldAnchorHas`). Each restyles alone in the late sync, top first, and restyles its subtree only when what it passes on (variables, inherited fields, units) changed. When a `:has()` compound isn't its selector's subject (`.card:has(.x) .title`), the anchor's parent restyles with its subtree instead. Elements made since the last restyle start no transitions from these restyles, as with structural selectors.
  - **Relative lengths** become px in the cascade after `var()` and before `calc()`, outside strings and `url()` (`resolveRelativeUnits`), so every length, shorthand, transform, shadow and `calc()` takes them, and a mixed `calc(50% + 1em)` keeps its % part for layout. `em` is the element's own font size, found before its other declarations (the winning `font-size`, else HTML's tag default, else inherited, else 16); inside `font-size` it's the parent's. `rem` is the root canvas element's: the canvas now keeps the text properties its `:root` rules set (as well as variables), and its children inherit them, as on the web (before, only `:root` variables reached them). What an element resolved against travels in its resolved map under `@units` (never a field), so keyframes and the host's played keyframes convert with it. Viewport units use the root target's `viewport`: the canvas size from the last layout, its reference resolution before one (headless Worlds); a resize restyles the tree when a sheet or any element's attributes use viewport units, and a size at or before the first layout starts no transitions.
  - **`linear()`** is parsed with CSS Easing 2's normalisation into points and becomes an engine curve of linear keys (a repeated input is a jump), with keys at 0 and 1 on the first and last segments' lines when the points start after 0 or end before 1; reversed, the points mirror. `linear(0, 1)` is plain linear.
  - **`transition-behavior`** is a longhand and a shorthand keyword (`allow-discrete`, `normal`); the shorthand resets it. A spec carries `allowDiscrete` only when set. Discrete pairs then transition, flipping half way through the eased progress; `display` to or from `none` keeps the other value throughout, in transitions and keyframes alike (CSS Display 4).
  - **Reversing shortening** follows CSS Transitions 1: each transition keeps its reversing-adjusted start value and factor; a change to that start value scales the new transition's duration (and a negative delay) by `|eased progress × old factor + 1 − old factor|`, clamped to 1.
  - **Inheritance mid-transition.** The animator tells its owner of every value it writes (`UIAnimationOwner._animatedWrite`); the host passes a written inherited field down to children whose value is inherited (and through elements without the field), skipping a child that animates it itself. Elements that only pass an inherited field on (a panel's or button's `color`, which their components lack) animate it as a *virtual* field (`UIStyledElement.virtual`): the animator holds its value and only the owner hears it, so `button:hover { color: … }` with a transition fades its label.
  - **Left out:** `em` lengths follow a transitioning `font-size` at the element's next restyle, not per frame; `@starting-style` and `transitioncancel`; `%` font sizes.

**As built (G4, scrolling, 2026-11-26):**

- **Fields** (on every element): `scrollSnapAxis` (`none | x | y | block | inline | both`; block is y, inline x, the UI being horizontal-tb) and `scrollSnapStrictness` (`proximity | mandatory`), written by the `scroll-snap-type` shorthand; `scrollSnapAlignBlock`/`scrollSnapAlignInline`, written by `scroll-snap-align: <block> [<inline>]`; `scrollSnapStop`; `scrollPadding{Top,Right,Bottom,Left}` and `scrollMargin{…}` (UI pixels; `auto` is 0) with the `scroll-padding`/`scroll-margin` shorthands and their `-block`/`-inline` two-value forms (no `-start`/`-end` longhands); `scrollbarGutter` (`auto | stable | stable both-edges`, either order in CSS). Shorthands in `cascade.ts`'s table only.
- **`direction` is new** (`ltr | rtl`, null inherits; HTML `dir="ltr|rtl"` through the renderer): "right-to-left text" needed a direction an element lays out in, and the UI had none (only the language's, for text alignment, with Yoga always LTR). It goes to Yoga per node (rows lay out from the right) and sets the horizontal scroll origin; text runs still take the language's direction (G3's area), and the canvas stays `ltr`, so no existing game UI changes.
- **Scroll origins (CSSOM):** an axis whose content starts at its far end (`row-reverse` in ltr, a row or column in `rtl` unless `row-reverse` turns it back, `column-reverse`) has offsets from a negative `min` to 0, starts at 0 (showing that end), and its extent reaches past its start edge (content past its end edge is unreachable, as in CSS). `UIScrollInfo` gained `minX`/`minY`; clamping, the wheel's and drags' chaining (`canMove`), keys (Home is `min`), thumb dragging, scrollbars (thumb by `(offset − min) / range`), hit-testing, picking and navigation all read the range. `scrollIntoView`'s inline `start`/`end` follow the scroller's direction. `flex-wrap: wrap-reverse` doesn't change an origin; a text area always scrolls from its start.
- **`scrollbar-gutter: stable`** on an element that clips reserves the vertical bar's thickness (by `scrollbar-width`; none for `none`) between border and padding on the bar's side (left in `rtl`; both sides for `both-edges`): to Yoga, a wider border, so `clientWidth` and the content box shrink and nothing moves when the bar appears; the bar is drawn in the gutter. Without it bars still overlay the content, `overflow: scroll` included (the engine's bars are overlay bars).
- **Snapping** (`scrollSnap.ts` chooses, `scrolling.ts` moves): snap areas are the descendants a scroller is the nearest clipping ancestor of, measured at layout (border box plus `scroll-margin`, transforms ignored) into `UIScrollInfo.snap`, against the snapport (padding box minus `scroll-padding`). `scrollTo`, Home/End, `scrollTop` writes and a released thumb snap to the nearest position; `scrollBy`, arrow and page keys and a track press are directional (the nearest past where they start, so a short step moves on); the wheel scrolls at once and snaps, smoothly, after 0.12 s still (directional from where the wheel gesture started); a touch or pen drag let go eases (`ease-out`, 0.25–1 s by speed) to the position nearest where its momentum would end instead of coasting; `scrollIntoView` and navigation prefer positions that keep the element in view. `scroll-snap-stop: always` stops directional scrolls and gestures at the first such position they'd pass or reach (not explicit ones). `proximity` snaps within 30% of the snapport's length. Snaps on both axes are chosen independently.
- **Re-snapping:** each snap remembers its area per axis; the routing core's layout (nothing moving it, no drag or thumb holding it) puts the offset back on that area where the layout moved it, and a `mandatory` axis not resting on one (a raw field write, the area gone) goes to the nearest position, in the same layout (drawn where it snapped that frame). `scrollend` waits for a wheel's snap.
- Tests: `engine/tests/uiScrollSnap.test.ts` (properties and shorthands, explicit/directional/proximity, padding/margin/alignment, wheel settle, flings with `scroll-snap-stop`, slow drag and thumb release, keys, navigation and `scrollIntoView`, re-snapping, the gutter, `column-reverse`, `rtl` with navigation, `row-reverse`).

**As built (G3, text, 2026-11-27):**

- **`white-space`** is a shorthand of two inherited `UIText` fields, `whiteSpaceCollapse` (`collapse | preserve | preserve-breaks | break-spaces`) and `textWrapMode` (`wrap | nowrap`), in its own section of `cascade.ts` (a typed shorthand, so it passes through panels to their texts); it takes the CSS 2 keywords or the longhands' values in either order, and `text-wrap` takes `wrap`/`nowrap` (`balance`, `pretty`, `stable` wrap). **Collapsing moved from the Svelte renderer to the UI core:** the renderer hands text over as written (`UIText.text` is the raw text, as the DOM's text nodes are), and `textRunOf` applies each element's rules: a plain text's text (spaces, tabs and breaks collapsed and trimmed; breaks kept for `preserve-breaks`; everything kept, tabs to stops of 8, for `preserve`/`break-spaces`), and per run across a text's runs (a run's rules are its own element's; text pieces inherit theirs). A `<br>` is marked by the host (`_lineBreak`), since a text that is only `\n` is no longer a line break. Line breaking: `nowrap` on a text measures it unwrapped unless a run inside wraps; a `nowrap` run has no break after its characters; a `keepSpaces` run (`break-spaces`, or `pre`) keeps trailing spaces on the line, taking room, with a break after each. An editable text keeps `pre-wrap`. A plain `break-spaces` text goes through the inline layout (one run). Behaviour change: a script's `UIText.text` with `\n` now shows one line under the default `normal`, as in HTML.
- **Run `:hover`/`:active`.** The routing core publishes the text-kind entries on the hovered path and, while the primary button is held, on the pressed path (`UIPointerState.hoveredText`/`pressedText`); a text's pseudo-state reads them (`UIInteractions.isTextHovered`/`isTextPressed`), so the run under the pointer, its inline parents and its text element (a plain text too) are `:hover`, and `:active` follows the press. `:active` is now parsed (both selector readers) as the engine's `:pressed`. A colour or background change redraws without measuring again.
- **Inline boxes.** A run element with padding, a border or horizontal margins (`UIText` gained `borderWidth`, sides, `borderColor`, `borderRadius`) is a `UIInlineBox` on its text's run (`UITextRun.boxes`, outer before inner, over its run range) and its background moves from its runs to the box. The layout adds each box's start side (margin, border, padding, by direction) before its first character and its end side after its last, in measuring and wrapping too; each line reports its parts (`UIInlineLine.boxes`: border box around the element's glyph box plus vertical padding and border, which don't grow the line; `left`/`right` where the box starts and ends, so a box broken across lines is sliced). The core unions the parts into the run element's box and hit-tests them after the fragments; Babylon paints them (background, borders per side, a rounded stroke when whole and even) before run backgrounds and glyphs. A text element's own border is laid out by Yoga and drawn by its block, with `border-radius`.
- **Atomic inline boxes.** `isInlineAtom` (`elementKinds.ts`): inside a text, `display: inline-block | inline-flex` (new `display` values; elsewhere they lay out as `flex`) and every element that isn't phrasing text or a plain image: buttons, form controls, SVG, video, audio, panels. The renderer no longer turns non-phrasing elements in text into runs: every element keeps its own kind (the "drawn as inline text" and "isn't drawn yet" warnings are gone). The core collects an atom as an inline child (events go up through the text), with its own Yoga node as a root; `layoutAtoms` lays atoms out innermost first at their content's size (Yoga with no available width: max-content, not CSS's shrink-to-fit against the line's width), each text holding atoms updating its run in between, so nested inline blocks work. An atom is a U+FFFC run with `atom: { width, height, baseline }` (margin box; baseline its last text-holding descendant's last line by the strut, else the bottom margin edge, also when it clips), placed by its own `vertical-align` (`verticalAlign` moved from `UIText` to every element; plain images honour theirs too). `readLayout` visits each atom at its fragment, after its text, with the text's clips and transform, then its subtree; draw and hit order put atoms after their text. Babylon draws them as the elements they are and skips their runs.
- **Direction.** A text's base direction (its runs' placement, `start`/`end`) is its own `direction` or the nearest ancestor's below its canvas (G4's field, HTML `dir`), else the language's as before.
- Not built: floats; a block element in a text breaking the paragraph (it's an inline block); percentages inside inline blocks; padding on an empty run; `tab-size`; the end side of a box whose last character is a space hanging at a line's end.
- Tests: `ui/text/inlineLayout.test.ts` (nowrap and kept-space runs, boxes with slicing and right-to-left sides, atoms' baseline and breaks), `engine/tests/uiInlineText.test.ts` (white-space keywords, inheritance and per-run rules through a view, hover and active restyling through the pointer, box layout and element bounds, buttons/fields/inline blocks laid out, clicked and wrapped, Babylon drawing of boxes and atoms, `dir`); updated: `uiCore.test.ts` (a kept line break; a leaf's children under an image), `uiView.test.ts` and `uiViewForms.test.ts` (texts as written).

**As built (G2, pseudo-elements and `backdrop-filter`, 2026-11-27):**

- **Rule data:** a selector carries its pseudo-element (`Selector.pseudoElement`, a `UIPseudoElement` name without the colons), not a compound: CSS allows one only at the end. Both readers take it (`stylesheet.ts` from css-tree's node, `selectorQuery.ts` for queries and parser-free games), `::name` and CSS 2's `:before`/`:after`; anything after one (`::before:hover`), one inside a functional pseudo-class, and unknown names are refused. It adds one to the tag count of the specificity. Matching (`matchSelector`): a selector with a pseudo-element matches only a target that is that pseudo-element (`StyleTarget.pseudoElement`), its parts matched against the target's parent, the originating element; a selector without one never matches a pseudo-element target. So `:hover::before`, `.a > p::after` and `:has(…)::before` work with no other change, and queries never return them.
- **`::before`/`::after`** are generated by the UI host, not the renderer: when an element of a kind that can hold them (panel, text, button, label, form) restyles and a sheet styles them, the cascade resolves each pseudo-element's style with the element's resolved map as parent (they inherit from it) and its `content` (`CONTENT_KEY`, never inherited, only on pseudo-element targets; `contentValue.ts` reads strings with escapes and `attr(name)`, refusing counters, quotes and `url()`). With content, the host makes (or keeps) a hosted element marked as that pseudo-element: inside a text element a `UIText` run (`UIText._pseudo`; `elementKinds.ts` puts a `::before` run before the element's own text, and its events' owner is the element), elsewhere a `UIPanel` holding its text in a label (a `#text` piece that only inherits; none for `""`). Its node is the element's first or last child, so the UI core lays it out and draws it with no change; it's in no element's `children` (`UIHostElement._before`/`_after`), so queries, structural selectors, `:empty`, `:has()` and the renderer don't see it. It's synthetic, so its pointer events go to the element, as a button label's do. It restyles whenever its element does (attributes, classes, state, sheets), through the shared `apply` path, so its fields transition; `content: none` or a lost rule removes it, as does removing the element.
- **`::placeholder` and `::selection`** don't make elements: the host resolves them for input fields and text elements and puts what their rules *declare* (not what they inherit) into the element's own resolved map as fields, so they apply, transition and reset to the constructor defaults like any field: `placeholderColor` (`color`, its alpha times `opacity`, as Firefox's user-agent sheet fades it; `opacity` alone fades the default grey), the new `placeholderFontStyle` (drawn as the field's label slant), and the new `selectionColor`/`selectionBackgroundColor` on `UIInputField` and `UIText`. Drawing: an editable text's selection takes the highlight colour and its selected glyphs are drawn again in `selectionColor` inside the selection's rectangles; an input field now draws its selection while typing at all (the core's new `selectionOf`, passed in the drawing layer's `UIDrawExtra`), per line by line breaks in a text area, the same way.
- **Form parts:** per kind, the host resolves the part pseudo-elements the sheets use (as panel styles) into a `UIPartStyle` per part, from declared values only (background, `color`, radius, border width and colour, px `width`/`height`, box shadow, opacity), handed to `formParts.ts` (`setUIPartStyles`, a weak map by control), which overrides each part's defaults: a slider's thumb size and paint and its track's thickness and paint (its fill keeps the accent), a progress bar's track (a part over the box) and value, a meter's value by HTML's region, a checkbox's mark and a radio's dot (`::checkmark`'s `color`), a select's arrow (`::picker-icon`'s `color`). `UIPart` gained an optional border and shadow, which Babylon draws on the part's rectangle. Part styles don't transition (they aren't fields).
- **`backdrop-filter`** is thirteen fields on every element (`backdropBlur`…`backdropDropShadowBlur`), set by the shorthand (`filter`'s parser, renamed) and named by `transition-property: backdrop-filter`; `computedStyle` shows it. The UI core gives each element its own steps through its transform (`UILaidOutElement.backdrop`; not composed down the tree). Babylon's `Drawn` mixin, before the control draws: copies the texture's canvas under its drawn bounds (grown by the filter's reach) into an offscreen canvas, filters it into a second one with `ctx.filter` (or reads it back and runs `filterPixels`), and draws it back clipped to the box and corner radii through the control's matrix, at its opacity, not through its own `filter`. Partial redraws would otherwise sample the element's own last drawing at the region's edge, so on each texture with a backdrop element a hook after layout grows the redraw region to cover every backdrop element it touches and the area it samples (`growForBackdrops`). It's skipped when the control draws into an ancestor filter's offscreen canvas (the fallback path).
- **Costs:** one texture-to-canvas copy and one filtered draw per backdrop element per redraw, plus a pixel readback where `ctx.filter` is missing; and anything that changes under it redraws its whole sampled area. Pseudo-element styles cost a `resolveStyle` per used pseudo-element per restyled element of a kind that has them, only when some sheet uses that pseudo-element.
- **Left out (G2):** `::before`/`::after` on controls, images and media (as browsers); `display: inline` boxes (a generated box is a flex item like a panel); `::placeholder` font size, weight and family; `::selection` inheritance through descendants (CSS Highlight inheritance) and a text area's soft-wrapped selection lines; editing an editable text can type into a generated run's text; `::-webkit-meter-bar`, Firefox's `::-moz-*` names and a slider's fill; part transitions; sampling the 3D scene under a screen canvas.
- Tests: `engine/tests/uiPseudoElements.test.ts` (readers and refusals, generated boxes and runs with layout, hiding from queries, attribute/class/rule restyles and `content: none`, `:hover::before` and clicks through it, transitions and removal, `::placeholder`/`::selection` fields and reset, part styles in the core's parts), `engine/tests/uiFilters.test.ts` (`backdrop-filter` fields, transition, `computedStyle`, the core's steps), `engine/tests/babylonUI.test.ts` (the backdrop pass with `ctx.filter` and with the readback, redraw growth, part borders and shadows, the placeholder's slant, an input's selection).

## Alternatives considered

- **Leave the gaps.** The owner asked to cover them, and authors expect most of them, especially pseudo-elements, `em`/`rem` and `white-space`.
- **One record per gap.** Each is small and built on an accepted record. One record keeps them reviewable together, with each part's as-built notes added as it lands.

## Consequences

**Positive:** the UI's CSS covers what web authors routinely reach for. Svelte components are type-checked like scripts, and native builds are reproducible.

**Negative / costs:**
- more engine API;
- a readback per `backdrop-filter` element;
- inline-block layout joins Yoga subtrees into lines;
- an editor dependency (`svelte2tsx`).

## Deprecates

Nothing.

## As built (G5)

- **Type checking inside `.svelte`:** `svelte2tsx` 0.7.63 (pinned exact; editor only, loaded on first use; the player has none of it). `src/editor/code/svelteCheck.ts` makes each component's TypeScript and maps errors back through svelte2tsx's source map (`code/sourceMaps.ts`); `code/monaco.ts` serves it beside the component (`Hud.svelte.ts`, `.svelte.tsx` when a rune module has that name), so imports of components are typed everywhere, shows the errors as the component's markers in the Code panel, and adds them to Play's check (0125), which now also runs for a project whose only code is Svelte UI. Svelte syntax errors are reported too. HTML attributes, event handlers and every expression are typed; other attribute names are accepted, since engine elements take UI component fields as attributes. JavaScript components are typed for importers but not checked (svelte-check's rule). svelte2tsx's import of Node's `path` resolves to `code/posixPath.ts` (`svelteCheckPath()` in `vite.shared.ts`).
- **Reproducible wasm builds:** `native/rustflags.mjs` (`wasmBuildEnv`) gives every native build except navigation (frozen) `CARGO_ENCODED_RUSTFLAGS` with the workspace's own wasm flags and `--remap-path-prefix` for the repository root (`/myco`) and CARGO_HOME (`/cargo`). Remapping wasn't enough on its own: Cargo's `-C metadata` hashes the absolute path of a path dependency outside the workspace (`native/common/*`), and rustc lays out code and data by the resulting crate identity, so `native/rustc-wrapper.mjs` (RUSTC_WRAPPER) replaces it with a hash of the crate's arguments with the checkout's paths remapped. Builds of anim, tween, audio, input and fx-sdk in two directories are byte-identical. The committed anim, tween and audio modules were rebuilt (source hashes unchanged; input and the fx plugins named no path and came out the same or, for input, differ only by toolchain: native/input pins none), and `src/engine/wasm/reproducibleWasm.test.ts` fails on a committed module that names a checkout. The audio build's `wasm-opt` pass, which ran whenever `wasm-opt` was on PATH, is opt-in (`MYCO_WASM_OPT=1`); pinning Binaryen stays a pending owner decision. Navigation's committed wasm still embeds paths.
