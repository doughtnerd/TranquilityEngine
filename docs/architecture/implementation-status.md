Legend: **Done** = implemented as decided · **Partial** = works, with listed gaps · **Not started**.

| [0022](../decisions/0022-editor-is-a-v1-goal.md) Editor | Partial | Increments 1–8. `src/editor/main.tsx` renders the Preact layout (0025) and boots an Editor World (`Engine.create({ kind: "editor" })`). The render backend fills the viewport panel, draws a grid (XZ in 3D, XY in 2D) and axes, and doesn't render cameras inside the edited scene. `OrbitCamera` is a GameBehavior on a yaw → pitch-arm → camera rig under the World root. In 3D, right-drag or Alt + left-drag orbits; in both views, middle-drag or Shift + right-drag pans (right-drag also pans in 2D), the wheel zooms (`Input.mouseScrollDelta`) and F focuses. The 2D view is orthographic, looking down −Z. **Projects and saving** (`src/editor/projects.ts`, `session.ts`): the editor starts on the bundled Flappy demo (read-only, works in a plain browser). In the desktop editor, **Open Project…** picks a folder containing `project.json` through the platform FileSystem: every JSON file is read and binary assets become object URLs up front, since scene loading looks assets up synchronously. Each project gets a fresh Editor World with its own settings (autoloads dropped). The Assets panel lists scenes and prefabs to open, and a status bar reports errors such as unknown script types. **Save** (Ctrl/Cmd+S) writes the open scene through `formatSceneJSON` (`document/format.ts`): unchanged nodes keep their original text and blank-line grouping, and edited ones are formatted Prettier-style at 112 columns, so a one-field edit changes one line. The demo files round-trip byte for byte. Opening another scene or project, or closing the window, asks before discarding unsaved changes (Tauri dialog plugin, `beforeunload` in browsers; the window needs `core:window:allow-destroy`). Game script types still come from the editor build (the demo's), so a folder project can't use its own scripts yet (O3). The opened folder is in the fs scope only until the app closes (no persisted scope). The editor opens a scene file into a `SceneDocument`/`WorldSync` and frames the scene's own camera, switching to 2D for orthographic scenes. The **Hierarchy** shows the document's node tree (collapsible, with prefab badges, inactive nodes dimmed), and clicking selects. The **Inspector** shows the selected node's components with declared fields and live values, and edits them: each field type gets its own input (numbers with arithmetic and label scrubbing, booleans, strings, asset paths, colours, vectors per axis, node references, nested settings objects), plus the node name and active flag. Every edit is a `SetField`/`RenameNode`/`SetActive` command (an override on prefab instances; `src/editor/fieldValues.ts` converts to scene-file JSON). The toolbar has Undo/Redo, also on Ctrl/Cmd+Z and Ctrl/Cmd+Shift+Z or Ctrl+Y, and the hierarchy marks unsaved changes with •. **Viewport selection** (`src/editor/viewportSelection.ts`): a plain left click (no Alt, under 4 px of movement) picks the topmost sprite or text under the pointer (`pick` in `src/engine/editor/`, a ray test against each sprite's world quad, ordered by draw order then distance) and selects its document node, so a prefab's inner nodes select the instance. Clicking the same spot again cycles through overlapping hits, and clicking empty space clears. The selection's sprites, including descendants, get a blue outline drawn on top every frame. F and the Focus button frame the selection, or the origin when nothing is selected. **Prefab tools** (`src/editor/prefabs.ts`): prefab instances expand in the hierarchy to the nodes inside them, read from the prefab files (nested prefabs too), and those nodes are selectable (the selection is a path key such as `pipe/top`). Edits and gizmo drags on an instance or a node inside one become overrides. Overridden fields are marked with a revert button, and instance badges get a dot. Instances have **Apply**, which writes field overrides into the prefab file and refreshes every instance (the scene change undoes; the file keeps it), and **Revert All**. Plain nodes have **Create Prefab**, which writes `prefabs/<name>.prefab.json` and turns the node into an instance with the same id; it refuses if outside nodes reference nodes inside the new prefab. Apply and Create Prefab need a project folder. Not yet: renaming or deactivating nodes inside an instance, applying add/remove-component overrides, or editing a prefab in place from an instance. **Play mode** (`src/editor/playMode.ts`): **▶ Play** / **■ Stop** (Ctrl/Cmd+P) snapshots the open document, unsaved edits included, and serves it under the scene's path through a temporary asset source. It pauses the Editor World and boots a Runtime World with the project's real settings (autoloads too) in a game view over the viewport. Edits made while playing go to the document only; even a scene reload in the game (Flappy's restart) uses the snapshot. Stop disposes the Runtime World (`Engine.dispose` now destroys every node, so scripts get onDestroy, audio stops and the Rapier world is freed), removes the snapshot, gives input back to the editor canvas and resumes its loop. If the scene fails to start, the editor resumes and the status bar shows the error. **Asset browser** (`ui/Assets.tsx`, `assetBrowser.ts`): a folder tree beside a grid of tiles with image thumbnails and type labels, plus search by file name across folders; click selects a tile, double-click opens a scene or prefab, and a tile's + adds a prefab instance or a sprite node for an image (at the scene camera's focus point, under the selected node or beside a selected prefab instance) as one undoable `AddNode` with a unique id derived from the file name. **Camera gizmos**: cameras in the edited scene (which don't draw the editor's view) show a camera icon, constant size on screen and clickable to select, plus a wireframe of what they see at the game's aspect ratio, drawn to at most 30 m deep (`render/cameraGizmo.ts`); the selected camera's wireframe uses the selection colour. **Gizmos**: the toolbar's Select/Move/Rotate/Scale tools (Q/W/E/R) show three.js `TransformControls` on the selected node, wrapped inside the render backend and loaded lazily so game bundles never fetch it (`setGizmo`/`gizmoActive` in `src/engine/editor/`). The 2D view limits move and scale to X/Y and rotation to Z. Holding Ctrl/Cmd snaps to 0.25 m, 15° or 0.1. Each drag is one undo step of Transform `SetField` edits (overrides on prefab instances; `gizmoMath.ts` converts the gizmo's world pose to local values), and presses on a handle don't change the selection. Missing: selecting and editing a prefab's inner nodes, adding/removing nodes and components from the UI, multi-select, local/world space toggle, saving through the platform FileSystem, opening project folders, pausing/stepping play mode, inspecting the Runtime World while playing.  |
| [0026](../decisions/0026-editor-scene-document-and-commands.md) Scene document + commands | Partial | The editor UI edits through it (inspector fields, rename, active, undo/redo). `src/editor/document/`: `SceneDocument` holds the scene JSON as authored (round-trips exactly, key order included) and indexes nodes. The commands `SetField` (plain data, or a prefab override with an optional inner `target`), `RenameNode`, `SetActive`, `AddNode` (a subtree, at a sibling index), `RemoveNode`, `ReparentNode`, `AddComponent` and `RemoveComponent` each return a `Change` list, and undo restores the document byte for byte. `CommandStack` has undo/redo, nested `beginGroup`/`endGroup`, a dirty flag against `markSaved()`, and `subscribe`. `WorldSync` instantiates the document under an edit-mode scene node, then applies changes incrementally: field writes in place, a subtree rebuild for structural changes, and `$node` references re-pointed. It maps World nodes back to document nodes (`nodeIdOf`, `pathOf`, `nodeFor`). Editor-only engine access lives in `src/engine/editor/` (`listNodes`, `listComponents`, `writeField`, `instantiateDocument`, `moveNode`, `destroyNow`). It isn't exported from the engine or included in its `.d.ts`. Edit mode (`World.setEditMode`) stops GameBehavior hooks, built-in activation side effects such as audio, and user-system queries inside the edited subtree. Editor tools outside it keep running, and no physics world is created. Not yet: AddComponent/RemoveComponent as prefab overrides, multi-document editing, saving to disk (needs the Tauri platform adapter). |
| [0023](../decisions/0023-testing-vitest-and-browser-smoke-tests.md) Testing | Partial | Vitest on the headless core (lifecycle, transforms, scenes/prefabs, systems, Rapier physics). Playwright smoke tests (`tests/e2e/`, `npm run test:e2e`; `npm run test:e2e:install` fetches the browsers) run the production build on Chromium and WebKit. They check that the demo boots without errors, renders a non-blank frame, and goes through the ready → playing → dead → restart loop, all driven through the demo's `window.flappy.state()` handle. No GitHub Actions workflow yet. |
| [0024](../decisions/0024-storage-via-platform-adapter.md) Storage | Done | `Storage` API with three backends, picked by `Engine.create`: `TauriStorage` under Tauri (one file per key at `<appDataDir>/<namespace>/<key>.json`, or `.bin` for binary values, written to a temp file and renamed), IndexedDB in a browser, and memory when headless. Cloud saves remain an open question. |
