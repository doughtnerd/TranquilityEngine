# Implementation Status

What exists in the code (`src/engine/`, `src/editor/`, `native/`, `src-tauri/`) versus what the decision records in [docs/decisions/](../decisions/) describe, one row per record that has code (0001 is a process record; there is no 0084). Rendering is Babylon.js only (0075, 0081); three.js remains only for the OBJ/MTL/FBX and glTF loaders (0081, 0088). Rows were last audited against the code on 2026-11-07. A row may say **(Proposed)** after its status when the code is built but the record isn't accepted yet. The v1 demo is a sample project in `samples/flappy/` (ADR 0031). User guides are in [docs/guide/](../guide/).

Legend: **Done** = implemented as decided · **Partial** = works, with listed gaps · **Not started**.

## Known gaps worth fixing next

- Transform columns for systems (0064's open question): moving transforms through the facade is the slowest measured path (13 ms for 50k nodes; see the 0012 row).
- Production bundle size: the old figure (~4 MiB, mostly Rapier's inlined WASM) predates the switch to Babylon.js; re-measure the `npm run build` output (player and editor) before relying on it.
- The quality tier's `anisotropy` field is never applied on Babylon (0050), and a physical shader graph's layer values (clear coat roughness, transmission, IOR, iridescence) aren't fed to the material (0052).
- Deferred items in the newest records: the raw shader target and a code editor with inline errors (0106), static batching and lit sprites (0108), WebGPU checks for render textures and sky (0109, 0112).
- Stale code comments left by the three.js and uikit removal (0076, 0081): `vite.player.config.ts`, `ui/UICore.ts`, `ui/components.ts` (UIText/UIInputField `font`, `UIImage.fit`), `render/components.ts` (`Text`), and `RenderBackend` mentions in `RenderSurface.ts`, `navGizmo.ts`, `editorOverlays.ts`.
