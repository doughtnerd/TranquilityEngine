# Implementation Status

What exists in `src/engine/` versus what the decision records describe. Updated 2026-10-31, when the first vertical slice landed: enough engine for the Flappy Bird demo (`src/demo/flappy/`) to play end to end.

Legend: **Done** = implemented as decided · **Partial** = works, with listed gaps · **Not started**.

| Record | Status | Notes |
| --- | --- | --- |
| [0002](../decisions/0002-typescript-first-esm.md) TypeScript-first | Done | `strict` TS everywhere; Babel removed. `noImplicitOverride` is off so game scripts can write `update()` without `override`. |
| [0003](../decisions/0003-tauri-platform-browser-runtime.md) Tauri, browser runtime | Partial | Runs in the browser and has a Tauri v2 shell in `src-tauri/`. One Rust app serves both: `tauri.conf.json` loads the game (`dist/game/`, dev server :3000), and `tauri.editor.conf.json` is merged in with `--config` for the editor (`editor.html`, `dist/editor/`). Scripts: `tauri:dev`, `tauri:build`, `tauri:editor:dev`, `tauri:editor:build`. Platform adapter in `src/engine/platform/`: `isTauri()`, and an internal `FileSystem` (`TauriFileSystem` over the fs and dialog plugins; `BrowserFileSystem` is read-only over HTTP) for the editor (0026). Tauri JS packages are imported lazily, so headless tests and browser builds never load them; they're external in the engine library and absent from its declarations. `capabilities/default.json` grants app-data read/write plus the fs commands with no fixed paths: a folder picked with `pickFolder()` is added to the fs scope recursively, for the current session only (persisting it needs `tauri-plugin-persisted-scope`). No window APIs yet. The identifiers (`dev.tranquility.*`) and the icons from `tauri init` are placeholders. |
| [0004](../decisions/0004-threejs-render-pipeline.md) three.js render pipeline | Partial | `WebGLRenderer`, orthographic/perspective `Camera`, `SpriteRenderer`. No meshes, lights, materials/shaders, post-processing, animation. |
| [0005](../decisions/0005-physics-backend.md) Physics | Partial | Rapier 2D behind `Physics2DWorld`: `RigidBody2D`, `BoxCollider2D`, `CircleCollider2D`, triggers, collisions, named layers + matrix, raycast. Missing: 3D, joints, `CharacterController`, interpolation, `Stay` events, re-syncing a collider on a child node that moves relative to its body. |
| [0006](../decisions/0006-audio-howler-and-three.md) Audio | Partial | `AudioSource` and `Audio.playOneShot` on Howler. No spatial audio, `AudioListener`, mixer buses or shared AudioContext with three.js. |
| [0007](../decisions/0007-hidden-ecs-with-lifecycle-scripting.md) Hidden ECS, lifecycle | Done | Hooks run in Unity order, indexed by implemented hook, parents before children, `executionOrder`, deferred destroys. Awake waits until a node is first active (Unity semantics). |
| [0008](../decisions/0008-gameobjects-as-node-graph.md) Node graph | Done | Generational handles, hierarchy in typed arrays, active-in-hierarchy, path `find`, optional Transform. |
| [0009](../decisions/0009-components-attached-or-as-child-nodes.md) Component nodes | Done | `addChildBehavior`, `owner`, `getBehaviorInComponents`, multiple components per type, reparent → normal node with a warning. |

| [0011](../decisions/0011-frame-loop-and-system-order.md) Frame loop | Done | rAF, fixed-step accumulator (1/60, max 5 substeps, 0.25 s clamp), steps 1–10 in order, `engine.step(dt)` for tests. |
| [0012](../decisions/0012-ecs-storage-implementation.md) ECS storage | Partial | In-house: generational entities, typed-array hierarchy/transforms, sparse-set data components. | [0013](../decisions/0013-data-driven-scene-format.md) Scene format | Partial | JSON scenes/prefabs, type registry, standard-decorator fields, `$node` refs, `asset:` paths, nested prefabs, field / name / active / add / remove-component overrides, versioning + migrations. Missing: add/remove child-node overrides, references to persistent nodes by path, the TypeScript builder API, the rewrite-to-latest CLI. |
| [0014](../decisions/0014-unified-2d-and-3d.md) Unified 2D/3D | Partial | One renderer; sorting layers; 1 unit = 1 m; 100 px/unit default; per-scene physics dimension. Sprites are one mesh each (no per-atlas instancing yet); no pixel-perfect camera. |
| [0015](../decisions/0015-vite-build-tooling.md) Vite | Done | Vite 8. `vite.config.ts` runs the dev server (:3000) and the game build (`dist/game/`, a full app for a Tauri shell). `vite.engine.config.ts` builds the engine library (`dist/engine/engine.js`, with three.js, Rapier and Howler external) and `tsconfig.engine.json` emits its declarations with `stripInternal`, so no backend types leak (0010). Assets load through `Assets.fromGlob` over `import.meta.glob`. Every config compiles TS with `tsc` (`vite.shared.ts`) because oxc doesn't lower standard decorators. `vite.editor.config.ts` builds the editor (`editor.html`) into `dist/editor/`; in dev it's served at `/editor.html`. The multi-bundle layout came from the earlier `game-engine` repo. |
| [0016](../decisions/0016-world-root-and-scenes-as-nodes.md) World root, scenes as nodes | Done | Scene nodes under the root, additive loads, autoload persistence, `node.scene`, `GameObject.makePersistent`. Only a `runtime` World exists. |
| [0017](../decisions/0017-user-systems-and-data-components.md) User systems, data, buffers | Done | `defineComponent` (f32/i32/u8), `defineBuffer`, `defineSystem` with phases, `before`/`after`, queries, `ctx.single`. Physics events also exposed as `TriggerEvents2D` / `CollisionEvents2D`. |
| [0018](../decisions/0018-promise-based-waits.md) Promise waits | Done | `wait.seconds/realtime/nextFrame/fixedStep/until`, dropped on disable/destroy, `abortSignal`. |

| [0020](../decisions/0020-in-canvas-ui-with-uikit.md) In-canvas UI (uikit) | Partial | Interim `Text` component drawn to a canvas texture in a screen-space pass. Not backed by uikit yet; no layout, panels, buttons or UI input routing. |
| [0021](../decisions/0021-particles-with-three-quarks.md) Particles | Not started | |
| [0022](../decisions/0022-editor-is-a-v1-goal.md) Editor | Partial | Increments 1–2. `src/editor/main.tsx` renders the Preact layout (0025) and boots an Editor World (`Engine.create({ kind: "editor" })`). The render backend fills the viewport panel, draws a grid (XZ in 3D, XY in 2D) and axes, and doesn't render cameras inside the edited scene. `OrbitCamera` is a GameBehavior on a yaw → pitch-arm → camera rig under the World root. In 3D, right-drag or Alt + left-drag orbits; in both views, middle-drag or Shift + right-drag pans (right-drag also pans in 2D), the wheel zooms (`Input.mouseScrollDelta`) and F focuses. The 2D view is orthographic, looking down −Z. The editor bundles the Flappy demo as its project (`src/editor/project.ts`: assets, settings without autoloads, script types). It opens `scenes/main.scene.json` into a `SceneDocument`/`WorldSync` and frames the scene's own camera, switching to 2D for orthographic scenes. The **Hierarchy** shows the document's node tree (collapsible, with prefab badges, inactive nodes dimmed), and clicking selects. The **Inspector** shows the selected node's components with declared fields and live values, read-only. Missing: field editing, viewport selection, gizmos, saving through the platform FileSystem, opening project folders, play mode, prefab tools, asset browser.  |
| [0026](../decisions/0026-editor-scene-document-and-commands.md) Scene document + commands | Partial | The UI uses it read-only so far (hierarchy, inspector). `src/editor/document/`: `SceneDocument` holds the scene JSON as authored (round-trips exactly, key order included) and indexes nodes. The commands `SetField` (plain data, or a prefab override with an optional inner `target`), `RenameNode`, `SetActive`, `AddNode` (a subtree, at a sibling index), `RemoveNode`, `ReparentNode`, `AddComponent` and `RemoveComponent` each return a `Change` list, and undo restores the document byte for byte. `CommandStack` has undo/redo, nested `beginGroup`/`endGroup`, a dirty flag against `markSaved()`, and `subscribe`. `WorldSync` instantiates the document under an edit-mode scene node, then applies changes incrementally: field writes in place, a subtree rebuild for structural changes, and `$node` references re-pointed. It maps World nodes back to document nodes (`nodeIdOf`, `pathOf`, `nodeFor`). Editor-only engine access lives in `src/engine/editor/` (`listNodes`, `listComponents`, `writeField`, `instantiateDocument`, `moveNode`, `destroyNow`). It isn't exported from the engine or included in its `.d.ts`. Edit mode (`World.setEditMode`) stops GameBehavior hooks, built-in activation side effects such as audio, and user-system queries inside the edited subtree. Editor tools outside it keep running, and no physics world is created. Not yet: AddComponent/RemoveComponent as prefab overrides, multi-document editing, saving to disk (needs the Tauri platform adapter). |
| [0023](../decisions/0023-testing-vitest-and-browser-smoke-tests.md) Testing | Partial | Vitest on the headless core (lifecycle, transforms, scenes/prefabs, systems, Rapier physics). Playwright smoke tests (`tests/e2e/`, `npm run test:e2e`; `npm run test:e2e:install` fetches the browsers) run the production build on Chromium and WebKit. They check that the demo boots without errors, renders a non-blank frame, and goes through the ready → playing → dead → restart loop, all driven through the demo's `window.flappy.state()` handle. No GitHub Actions workflow yet. |
| [0024](../decisions/0024-storage-via-platform-adapter.md) Storage | Done | `Storage` API with three backends, picked by `Engine.create`: `TauriStorage` under Tauri (one file per key at `<appDataDir>/<namespace>/<key>.json`, or `.bin` for binary values, written to a temp file and renamed), IndexedDB in a browser, and memory when headless. Cloud saves remain an open question. |

- Sprite batching per atlas (0014) once a demo needs many sprites.
- Back `Text` with uikit (0020) and add UI input routing.
