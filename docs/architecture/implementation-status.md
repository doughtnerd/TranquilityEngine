# Implementation Status

What exists in `src/engine/` versus what the decision records describe. Updated 2026-10-31, when the first vertical slice landed (3D rows 0043–0045 and shader graph rows 0046–0049 added 2026-11-03): enough engine for the Flappy Bird demo to play end to end. The demo is now a sample project in `samples/flappy/` (ADR 0031). The 0032–0035 rows were checked against the code on 2026-11-02 (T17); user guides are in [docs/guide/](../guide/).

Legend: **Done** = implemented as decided · **Partial** = works, with listed gaps · **Not started**.

| [0022](../decisions/0022-editor-is-a-v1-goal.md) Editor | Partial | Increments 1–15. **Appearance and branding** (details in the 0025 row): Settings has General and Appearance sections; theme and fonts are per user; the toolbar, start screen and an About dialog carry the Myco Engine and Foxfire Studios art. **Import settings and the Sprite Editor** (ADR 0040; see that row). **Play mode debugging** (details in the 0032 row): a World picker that shows a live World of the running game in the Hierarchy and Inspector, with live edits; **Keep values** written into the scene on Stop as one undo step; Pause and single-frame Step for the session (Ctrl/Cmd+Shift+P, F10 or Ctrl/Cmd+Alt+P) and per World. **Message log** (`messages.ts`, `ui/StatusBar.tsx`): every status message is logged, as are uncaught errors, unhandled rejections and console errors and warnings, with stack traces (`errorStatus(context, err)` keeps a caught error's stack as the status `detail`). Clicking the status bar (or Log) opens the log, newest first. Errors show their details straight away; there are Copy, Clear and Close buttons, and Escape closes it. An unseen-errors count shows while it's closed, and an uncaught error also says "Something went wrong" in the status bar. **Deleting assets** (`assetDelete.ts`): the Assets panel's Delete button, or Delete/Backspace on a focused tile, deletes the selected file (asset or script) from disk after a confirmation. The confirmation lists the files that still refer to it: scenes and prefabs, `project.json`, scripts that mention its path, and the open scene's unsaved edits. "Don't ask again" is a per-user preference, also in Settings and offered back in the status bar. project.json, the open scene, read-only projects and play mode are refused. After deleting, references are removed (`assetCleanup.ts`): instances of a deleted prefab go with their children, and node references to them become None; component fields and overrides naming the file go back to their defaults; `project.json` autoloads of it are dropped. Scene and prefab files on disk are rewritten (layout kept), and instances in the open scene of a prefab that changed are rebuilt. The open scene is cleaned as one undo step (`ReplaceDocument`), kept when it's saved. Scripts aren't edited; the status bar lists what was cleaned and what still refers to it. In the Editor World an instance of a missing prefab loads as an empty node with a reported problem (after undoing such a removal, say); games still throw. Deleting a script reloads scripts and closes its Code tab. **The scene view is a panel**: there's no fixed middle any more. The Select/Move/Rotate/Scale tools, the 3D/2D toggle and Focus are a toolbar at the top of the Scene panel, so they move with it. The Scene panel docks, tabs and splits like the others, and the innermost dock fills the space the others leave, with no resize handle. Dropping at its edges adds a dock just outside it, and when it empties the next dock out fills. Saved layouts from before get the scene view as a new filling dock. The engine's containers (`#viewport`, `#game-view`) are long-lived elements the Scene panel attaches when it mounts (`viewportElements`), so moving or hiding the panel keeps the canvas and WebGL context. **Adding and removing components** (`src/editor/componentEdits.ts`, `ui/AddComponentMenu.tsx`): the Inspector's **Add Component** button opens a searchable list of every registered component (`componentCatalog` in `src/engine/editor/`), grouped Engine, Scripts and Data; Transform, engine internals and `editor.*` types aren't offered. Types a node can't take (a second SpriteRenderer, RigidBody2D, Camera, Text or data component) are greyed out with the reason. A collider added beside a sprite starts fitted to it (box: the sprite's size; circle: half its larger side; `spriteSize`). Each component header except Transform's has a ✕ that removes it. On plain nodes this edits the node's components list; on prefab instances and nodes inside them it's an `addComponent` or `removeComponent` override (`SetOverrides`). Removing a component an override added drops that override, and field overrides for a removed component are dropped or renumbered. Only the first of a type from the prefab can be removed there, since a `removeComponent` override takes the first. With several nodes selected, both act on every node that allows it. Each add or remove is one undo step. The scene camera's F key no longer fires while typing in a text field. Each script or engine component's header checkbox switches it on or off (`enabled: false` in the file; on instances an `enabled` override, ADR 0028, removed again when switched back). Disabled components are dimmed, and a mixed multi-selection shows indeterminate. Transform and data components are always on. A grip on each header drags the component to a new place, with a line showing where; Alt+↑/↓ on the focused grip moves it too. Order sets hook order within a node. On a plain node the Inspector lists components in file order, and data components move among the rest (file layout only). On an instance a move writes an `order` override (ADR 0029; `World._reorderComponents` renumbers creation order to match). Moving back to the prefab's own order removes it, and an instance's data components stay put. Apply now writes added and removed components, `enabled` and `order` overrides into the prefab file too, directly on plain prefab nodes and as overrides on nested instances; name and active overrides still stay on the instance. **Multi-selection** (`src/editor/selectionModel.ts`, `viewportSelection.ts`, `ui/RefineList.tsx`): the selection is an ordered list of path keys (`selectedKeys`); the last is the active node, which single-node tools (Create Prefab, Edit Collider, prefab Apply) act on, and `selection` still reads and sets it. A left drag on empty viewport space draws a selection box and selects every node lying entirely inside it (its sprite or text rectangle, or its origin if it draws nothing; a prefab instance counts everything drawn inside it), live as the box changes; Shift adds to the selection, Ctrl/Cmd toggles, and Escape puts the selection back. Shift+click and Ctrl/Cmd+click do the same for single viewport clicks. Colliders count as part of their node: a click anywhere inside a box or circle collider selects its node (the smallest collider first, ahead of the sprites drawn there; clicking again cycles to them), and collider rectangles count toward the box and the Alt+click list (`colliderShapes`, `worldToCanvas`). Alt+click opens a list of every node within 24 px of the pointer, occluded ones included, plus their children (prefab inner nodes too), with list controls: click, Ctrl/Cmd+click toggle, Shift+click range, arrows, Space, Ctrl/Cmd+A. The selection follows it live; Enter or clicking away keeps it, Escape restores it. The hierarchy takes Ctrl/Cmd+click and Shift+click ranges over the visible rows. Every selected node is outlined. With several nodes the Inspector shows the components they all have: differing values show a dash (vectors per axis), and an edit sets every node in one undo step (a vector axis edit keeps each node's other axes). The transform gizmo sits at the selection's centre and moves, turns or scales the topmost selected nodes around it in one undo step (`setGizmo` takes several nodes; the render backend applies the gizmo's change to each node's start pose). Delete removes them all in one step, and F frames their centre. The scene camera now ignores mouse travel from before a drag's first frame, which made Alt+clicks in 2D jump the view. `screenBounds` in `src/engine/editor/` gives each node's on-canvas rectangle. Not yet: dragging several hierarchy rows at once, multi-node Create Prefab or Apply, a pivot/centre toggle for the gizmo. **Collider gizmos** (`src/editor/colliderGizmo.ts`, `colliderMath.ts`): every 2D collider in the edited scene is outlined in green (the selected node's brighter), sized as the physics backend sizes it: box size × world scale, circle radius × the larger scale axis, centre offset scaled and rotated with the node. The Inspector's **Edit Collider** toggle on a BoxCollider2D or CircleCollider2D card shows handles in the viewport and hides the transform gizmo: box edge handles resize from the opposite edge (Alt: both edges), circle rim handles set the radius, and the centre handle moves the offset. Each drag is one undo step of `SetField` edits (overrides on prefab instances), and presses on a handle don't select or orbit. Editing ends when the selection changes or any tool is picked. The render backend draws the overlay from a per-frame provider (`setEditorOverlay`, `overlayHandleAt`, `overlayHandlesOnCanvas` in `src/engine/editor/`). **Polygon and edge colliders** (ADR 0039) are outlined too (edges open) and offered in Add Component; with Edit Collider on, each vertex has a handle (drag; Ctrl or "always snap" snaps to the move step), each edge's middle has one (press to add a vertex there and drag it), and Ctrl+click on a vertex removes it (down to 3 points, or 2 for an edge); one undo step each. Their `points` show read-only in the Inspector until it edits arrays. Not yet: 3D collider gizmos, blocked on a 3D physics backend (0005): there are no 3D collider components to draw. **Scene tools** (`src/editor/sceneTools.ts`, `align.ts`, `cameraPreview.ts`, `ui/SceneTools.tsx`, `ui/scene-tools.css`), in the Scene panel's toolbar and remembered per user: **World/Local** (X) aligns the move and rotate handles with the world or the node (the active node for several); **Center/Pivot** (Z) puts a multi-selection's gizmo at the selection's centre or the active node's origin; **Snap** turns on "always snap" (else hold Ctrl), and its ▾ popover sets the move step (m), rotate step (°), scale step, grid size (m) and grid visibility; the grid redraws at the chosen cell size (`setEditorGrid`). **Align ▾** lines up two or more selected nodes by their bounds (sprite boxes, else origins; `worldBounds`): left/centre/right/top/middle/bottom and distribute horizontally/vertically in 2D, min/centre/max and distribute along X, Y and Z in 3D (distribute needs three; the outermost stay and the gaps become equal). Each action is one undo step of position edits (overrides on prefab instances), on the topmost selected nodes. **Camera preview**: with a Camera node selected in edit mode, an inset in the scene view's corner shows what it sees at the game's aspect ratio, rendered by the backend into that part of the canvas through the camera without the grid, gizmos and overlays (`setCameraPreview`); the **Preview** toggle turns it off. Not yet: the preview doesn't follow a camera's viewport rect or post-processing (there is none), and align uses sprite bounds only (no text or collider bounds). **History panel and Settings** (`src/editor/ui/HistoryPanel.tsx`, `SettingsDialog.tsx`, ADR 0027): a dockable History panel (a tab beside the Inspector by default) draws the edit history tree like the undotree plugin, newest at the top with a column per branch, marking the current and saved states. Clicking a state jumps there, and Ctrl/Cmd+Alt+Z and Ctrl/Cmd+Alt+Shift+Z step back and forward in creation order. Saved layouts from before the panel existed get it as a tab beside the Inspector instead of being reset. A toolbar Settings dialog holds the per-user history location (project folder by default, or per user) and the ask-before-clearing-references option. `src/editor/main.tsx` renders the Preact layout (0025) and boots an Editor World (`Engine.create({ kind: "editor" })`). The render backend fills the viewport panel, draws a grid (XZ in 3D, XY in 2D) and axes, and doesn't render cameras inside the edited scene. `OrbitCamera` is a GameBehavior on a yaw → pitch-arm → camera rig under the World root. In 3D, right-drag or Alt + left-drag orbits; in both views, middle-drag or Shift + right-drag pans (right-drag also pans in 2D), the wheel zooms (`Input.mouseScrollDelta`) and F focuses. The 2D view is orthographic, looking down −Z. **Reordering and deleting** (`src/editor/hierarchyEdit.ts`, `nodeDrag.ts`, `deleteSelection.ts`): drag hierarchy rows to reorder, reparent or unparent nodes, using the same indicators as asset drops. A reparented node keeps its place in the world: its local Transform is recalculated, written as overrides on prefab instances. Delete/Backspace or the inspector's Delete button removes the selected node and its children. When other nodes reference it, an in-editor dialog lists those references and offers "Don't ask again" (a per-user preference); confirming sets them to None in the same undo step. After a delete that cleared references without asking, the status bar offers to turn the prompt back on. Nodes inside prefab instances can't be moved, take children or be deleted here; the instance itself can. Each move or delete is one undo step. **Asset drag and drop** (`src/editor/assetDrag.ts`, pointer events rather than HTML drag and drop, which Tauri's webview takes over on Windows): drag an asset tile into the viewport to add it at the top level under the cursor, on the z = 0 plane (`pointOnSpritePlane`), falling back to the camera's focus point. Drag it into the hierarchy to add it under a node (the middle of its row: the row highlights) or beside it (near the row's top or bottom edge: a line shows where); empty space or the scene header means the top level. Images become sprites, audio becomes an AudioSource, and prefabs and scenes become instances, with scenes as sub-scenes (ADR 0016). Other files, a scene or prefab that would end up inside itself, rows inside prefab instances, other panels, and play mode are invalid: the ghost label turns red and says why, and releasing changes nothing. Each drop is one undoable step and selects the new node. **Dockable panels** (`src/editor/layout/`: a pure model in `model.ts` plus the `DockLayout` renderer): the viewport is fixed in the centre, with docks around it listed outermost first. Each dock is on the left, right or bottom and splits evenly into tab groups. Dragging a panel by its header previews the drop and then lands it according to the pointer: on another panel's header it joins as a tab; at the window's outer edge it becomes a new outermost dock that claims the full height or width; at the viewport's edge it becomes a new innermost dock; inside a dock it splits the dock evenly at that position. Anywhere else, or pressing Escape, leaves the layout unchanged. Handles resize docks (clamped so the viewport keeps 200×140) and the splits between groups. The layout is saved in localStorage and validated on load (it falls back to the default), and Reset Layout restores the default. The viewport element stays mounted while panels move, since the engine renders into it. **Projects and saving** (`src/editor/projects.ts`, `session.ts`): the editor starts on a start screen (ADR 0031) with Open Project… (desktop) and the samples served beside it; a sample opens read-only (works in a plain browser), and the desktop editor can copy one into a folder to edit it. In the desktop editor, **Open Project…** picks a folder containing `project.json` through the platform FileSystem: every JSON file is read and binary assets become object URLs up front, since scene loading looks assets up synchronously. Each project gets a fresh Editor World with its own settings (autoloads dropped). The Assets panel lists scenes and prefabs to open, and a status bar reports errors such as unknown script types. **Save** (Ctrl/Cmd+S) writes the open scene through `formatSceneJSON` (`document/format.ts`): unchanged nodes keep their original text and blank-line grouping, and edited ones are formatted Prettier-style at 112 columns, so a one-field edit changes one line. The demo files round-trip byte for byte. Opening another scene or project, or closing the window, asks before discarding unsaved changes (Tauri dialog plugin, `beforeunload` in browsers; the window needs `core:window:allow-destroy`). Game script types still come from the editor build (the demo's), so a folder project can't use its own scripts yet (O3). The opened folder is in the fs scope only until the app closes (no persisted scope). The editor opens a scene file into a `SceneDocument`/`WorldSync` and frames the scene's own camera, switching to 2D for orthographic scenes. The **Hierarchy** shows the document's node tree (collapsible, with prefab badges, inactive nodes dimmed), and clicking selects. Every edit is a `SetField`/`RenameNode`/`SetActive` command (an override on prefab instances; `src/editor/fieldValues.ts` converts to scene-file JSON). Clicking the same spot again cycles through overlapping hits, and clicking empty space clears. The selection's sprites, including descendants, get a blue outline drawn on top every frame. F and the Focus button frame the selection, or the origin when nothing is selected. **Prefab tools** (`src/editor/prefabs.ts`): prefab instances expand in the hierarchy to the nodes inside them, read from the prefab files (nested prefabs too), and those nodes are selectable (the selection is a path key such as `pipe/top`). Edits and gizmo drags on an instance or a node inside one become overrides. Overridden fields are marked with a revert button, and instance badges get a dot. Instances have **Apply**, which writes field and component overrides into the prefab file and refreshes every instance (the scene change undoes; the file keeps it), and **Revert All**. Apply and Create Prefab need a project folder. Edits made while playing go to the document only; even a scene reload in the game (Flappy's restart) uses the snapshot. Stop disposes the Runtime World (`Engine.dispose` now destroys every node, so scripts get onDestroy, audio stops and the Rapier world is freed), removes the snapshot, gives input back to the editor canvas and resumes its loop. If the scene fails to start, the editor resumes and the status bar shows the error. **Asset browser** (`ui/Assets.tsx`, `assetBrowser.ts`, `assetSelection.ts`, `assetOps.ts`): a file browser. A folder tree sits beside the folder's subfolders and files, shown as a grid of tiles (image thumbnails, a tile-size slider) or a list with kind and size; the view and size are per-user preferences. A path bar with Back, Forward and Up (Alt+←/→/↑) moves between folders, and search finds files by name across folders. Click, Ctrl/Cmd+click, Shift+click, a box dragged on empty space (Shift adds, Ctrl/Cmd toggles, Escape restores) and the arrow keys (Shift extends, Ctrl/Cmd+A selects all) select files and folders; Enter or double-click opens. F2 renames in place, dragging the selection onto a folder (in the tree, the grid or the path bar) moves it, Ctrl+D duplicates, Ctrl+C/X/V copy, cut and paste, and Delete deletes, all on several entries at once; a right-click menu offers the same plus New Folder, New Script and Show in File Manager. Renames and moves update references in scenes, prefabs and project.json like deleting does (the open scene as one undo step); scripts that mention an old path are listed, not edited.
