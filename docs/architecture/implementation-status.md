# Implementation Status

What exists in `src/engine/` versus what the decision records describe. Updated 2026-10-31, when the first vertical slice landed (3D rows 0043–0045 and shader graph rows 0046–0049 added 2026-11-03): enough engine for the Flappy Bird demo to play end to end. The demo is now a sample project in `samples/flappy/` (ADR 0031). The 0032–0035 rows were checked against the code on 2026-11-02 (T17); user guides are in [docs/guide/](../guide/).

Legend: **Done** = implemented as decided · **Partial** = works, with listed gaps · **Not started**.

Only the first of a type from the prefab can be removed there, since a `removeComponent` override takes the first. With several nodes selected, both act on every node that allows it. Frames are binary with a 1-byte header (channel bit, reserved flags); unreliable messages ride the same TCP stream, so there's no loss benefit until WebRTC. Limits (`WebSocketLimits`, from the transport options): messages over 1 MiB are refused (the server sets `ws`'s `maxPayload`), a connection that sends more than 4 MiB between polls is closed as flooding, unreliable sends are dropped while more than 64 KiB is waiting in the socket's send buffer (`droppedUnreliable` counts them), and a connection with over 8 MiB of reliable data it can't drain is closed as too slow. Server errors after listening are logged. Sends while connecting are queued; every connection gets one `close` with a reason. Nothing under `src/engine/` imports `src/server/` or `ws`. **Wave 3.** **Sessions** (`net/session.ts`): each networked World has one, owning its transports, connections, handshake, tick sync and message routing; links in the bootstrap connect at `Engine.create`, `WorldHandle.connect` at runtime (loopback addresses per Engine and server World unless given). The handshake checks protocol version, tick rate, RPCs and message kinds and closes with a reason on a mismatch. Connections are nodes with `net.Connection` (`id, state, rtt, lastAckedTick`), made and removed by the session; destroying one kicks the client. Ticks: clients ping every 100 ms and estimate the server's tick; `Time.network` gives `tick`, `serverTick` (estimate + RTT/2 + a 2-tick command slack), `interpolationTick` (estimate − RTT/2 − `interpolationMs`, default 100), `rtt`. Built-ins: `engine.NetReceiveTick` (fixedUpdate, first), `engine.NetReceive` (update), `engine.NetSend` (lateUpdate, last). **RPCs** (`defineRpc`): reliable, codec-encoded, read as rows (values + `connection`) once per phase. An internal message API (`registerNetMessage`, `netSession`, `send`, `drain`) carries snapshots and inputs. **Replication** (`net/Replicated.ts`, `net/replication/`): `net.Replicated` (`mode`, `ownerId`, `importance`, `replicateTransform`) makes a node a ghost; its transform (quantized), `replicate()`d data components and `@field(…, { replicate })` behavior fields go in per-connection unreliable snapshots, delta-encoded against the connection's last acknowledged snapshot, with spawns and despawns repeated until acked, within 64 KiB (most important and longest-unsent first). Prefab roots spawn by prefab path; scene-placed ghosts match by scene and node id path. Clients interpolate at `interpolationTick` (lerp, slerp, snapping integers) and extrapolate up to 250 ms. About 1.25 bytes per unchanged ghost. **Per-World components**: `@behavior/@component(id, { worlds })`, or `worlds` on a scene file's component entry, keeps a component out of Worlds whose tags don't match (editor Worlds create everything). A prefab instance overrides it with `{ component, index?, worlds }` (ADR 0042), and the Inspector's component menu sets it. **Inputs** (`defineInput`): clients `write()` each fixed tick; each packet carries the last 4 ticks delta-encoded (15 bytes for a still 9-byte input); the server applies `Move.of(connection)` at its tick, repeating the newest input for a missing tick, with `stats()` counting received, repeated and late ticks. Review fixes: a client's timeline (serverTick, interpolationTick) starts afresh on each connection; connections time out when the handshake doesn't finish in 5 s or nothing arrives for 15 s (`handshakeTimeoutMs`, `idleTimeoutMs`; a paused server World's clients time out too), and servers refuse connections past `maxConnections` (64); input-schema mismatches are reported as such; spawns carry each component's field shapes (protocol version 2), so a client decodes and ignores components it lacks instead of losing whole snapshots; a prefab ghost under a plain scene node (a container) spawns under the same node on clients; every ghost's state history is pruned; `Move.of(playerNode)` resolves the owner from `Replicated.ownerId`; over-budget snapshots choose from last tick's sizes and encode once. **Wave 4.** **Prediction** (`net/prediction.ts`): systems with `predicted: true` (fixedUpdate only) run on a client's prediction timeline for the ghosts it owns and predicts, once per `serverTick` (bounded catch-up of skipped ticks), keeping a per-ghost history of predicted values; a snapshot that differs beyond quantization restores the server's state and re-runs the ticks since with each tick's input (`isResimulating`, `predictedTick`); small corrections blend the rendered position over 100 ms (built-ins `engine.PredictionTick`, `engine.PredictionSmooth`); `predictionStats(world)` counts mispredictions, rollbacks and re-simulated ticks. **Dedicated server** (`src/server/`, `npm run server -- <project>`, bin `myco-server`): runs a project's server-tagged Worlds headless in Node over WebSocket, with the bootstrap cut down to its server Worlds (or, when it has none, its server-tagged templates, each created at start under its key, for games whose Host button creates the server World), `--port`, `--host`, `--max-connections`, `--tick-rate` and `--stats-interval` options, a drift-free step timer, connection and stats logs and clean shutdown. Each server World listens on the port of a `websocket` link to it, the first falling back to `--port` or 7777; code bootstraps run with non-server Worlds replaced by inert handles whose `connect` records the link. Server Worlds created at runtime run but don't listen (O15), and the server logs them. Node runs the TypeScript source through module hooks (`tsLoader.mjs`). **Network tools** (`src/editor/netPlay.ts`, `ui/NetworkPanel.tsx`): Play runs 1–4 client Worlds plus 0–8 thin clients (no rendering, synthetic input) from the project's client World without editing project.json; latency, jitter and loss sliders apply live to every loopback link; the Network panel shows per World and connection the state, RTT, bytes/s per message kind, snapshot size, ghosts, input and prediction stats. **Wave 4 review fixes:** the dedicated server takes listen addresses only from `websocket` links; play mode puts simulated conditions in loopback links' options (so the handshake and tick sync see them) and Off stops reapplying them; input streams are forgotten with their scripts. **Multiplayer sample** (T16, `samples/arena/`): a top-down shooter in Unity's frontend pattern.
