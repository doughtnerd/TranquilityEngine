# Glossary

The domain terms used in Myco Engine's code, decision records and reviews. Add a term when a decision gives a concept a name, and sharpen an entry when its meaning gets clearer. The core engine terms (Node, GameObject, GameBehavior, Component, World and so on) are in the [architecture overview's glossary](docs/architecture/overview.md#glossary); this file holds the rest.

## Plugins and the SDK (ADR 0133)

- **Plugin:** a feature, packaged as a manifest (`plugin.json`), a runtime half and an editor half. It registers contributions into contribution points. A plugin is a feature, not one asset type. For example, Materials and Shaders can be one plugin. _Avoid:_ package (that means an npm package, ADR 0125), extension, module (for a whole plugin).
- **Runtime half:** a plugin's `runtime/` folder, holding Components, systems, World services and asset loaders. It ships in game builds and on the dedicated server, and never imports editor code.
- **Editor half:** a plugin's `editor/` folder, holding asset kinds, asset document formats, panels, inspector sections, viewport tools, settings sections, importers, thumbnails and "New…" entries. It may import its runtime half.
- **Contribution point:** a registry that plugins register into, such as asset kinds, Components or World services. Each supports unregistering.
- **Contribution:** one thing a plugin registers at a contribution point.
- **SDK:** the public surface plugins are written against. `myco` is the runtime SDK. `myco/editor` is the editor SDK, importable only from editor halves: the contribution points, asset documents, the **editor surface** and building blocks (fields, theme, graph view). Anything else is the **internal tier**, for first-party plugins only, and the imports first-party editor halves still make into it are listed in `plugins/plugins.test.ts` (ADR 0147).
- **Editor surface:** the `editor` object of `myco/editor` (ADR 0147): `editor.project` (the open project, its change `version`, `createFile`), `editor.assets` (what a path is), `editor.messages` (the status bar) and `editor.scene` (open scene tabs, selection, play state). It reads the shell's state (`state.ts`), which plugins never import. _Avoid:_ `currentProject`, `docVersion`, `status` in plugin code.
- **First-party plugin:** a plugin shipped with the engine, in `src/plugins/<name>/`, versioned with the engine.
- **Third-party plugin:** a plugin found in a project's `plugins/<name>/` folder or in its `node_modules`.
- **Plugin set:** what a host (the player, the dedicated server, the editor) makes plugins active through (ADR 0144): it takes every plugin the host knows and the project's `plugins.disabled`, works out which are enabled, orders them, activates or deactivates their halves, and reports the ones that fail. Plugins never see it; they see only their half's context. _Avoid:_ plugin host, plugin manager.
- **Asset kind:** one type of asset file and how the editor treats it: how its files are recognised, its label and icon, what opening it does, its inspector, preview and import, and its policies.
- **Asset kind host:** `src/editor/assetKindHost.ts` (ADR 0233), reached as `editor.assets.create`/`read`/`open`/`openIn`: it creates a kind's files in its default folder, gives a file's **current value** (the open asset document's, unwritten edits included, else the file parsed with the kind's format) and opens a file in the kind's panel, remembering each panel's file. A kind declares only its `format`, `folder` and `panel`. _Avoid:_ per-plugin `readX` wrappers, default-folder helpers or open-in-panel signals.
- **Core asset kind:** an asset kind the editor shell itself registers (ADR 0143): scenes, prefabs, images, audio, render textures and the code and text kinds, in `src/editor/assetKinds.builtin.ts`. It is an ordinary asset kind contribution, registered at boot; it can't be disabled and is in no manifest. Folders, sprite slices and plain files are answered by the asset kind module (`assetKindLookup.ts`) itself.
- **Asset reference:** a string in a project file naming a project path: optionally `asset:` and a leading `./` or `/`, the path, and optionally `#slice` (ADR 0040), such as `asset:images/sheet.png#walk_0`. The asset reference module (`assetReferences.ts`, ADR 0148) is the one place that parses them and answers who **uses** an asset (files quoting a reference to it), what an asset **depends on**, and rewrites or removes references when files move or go. _Avoid:_ stripping `asset:` by hand.
- **Reference extractor:** an asset kind's `references` (ADR 0148): how files in the kind's own format name other files, such as an .obj's material libraries or a .gltf's buffers. JSON files need none.
- **Asset entry:** an Assets panel item as a string: a file (`images/a.png`), a folder (`images/`) or a slice (`images/sheet.png#walk_0`). `assetEntry.ts` is the one place that knows the encoding (ADR 0241).
- **Assets command:** Open, Rename, Duplicate, Copy, Cut, Paste or Delete on the Assets panel's selection (`assetActions.ts`, ADR 0241). Each has one rule (`whyNotAsset`), the same check its operation makes, used by the panel's menu, its keys and the menu bar.
- **Inspector target:** what the Inspector shows: a live World's node, an asset, a UI element, nodes, or scene settings (`inspectorTarget.ts`, ADR 0242). Every selection (nodes, Assets panel entries, a UI element) goes through its functions, which keep them apart. _Avoid:_ clearing another selection by hand, or writing `selectedKeys`, `selectedAssets` or `selectedUIElement` directly.
- **Field target:** what an Inspector field row edits: one component field on one or more nodes (`src/editor/fieldTarget.ts`, ADR 0243). It has two adapters: the edited document (undoable, overrides on instances) and a live World (play only). Both Inspectors render the same field rows (`ui/fieldRows.tsx`) over it, and both adapters write through the component field write.
- **Component field write:** setting one field of one component, in a scene document or on a live node (`src/editor/componentField.ts`, ADR 0257; `editor.scene.writeField` and `beginFieldDrag` in `myco/editor`). A document write asks the edit gate, is an override inside a prefab instance and skips an unchanged value; a drag is one undo step. The Inspector, plugin sections and gizmos all use it. _Avoid:_ building `SetField` outside the shell's edit modules; calling a plugin's write helper a "field target".
- **Adding assets:** putting project files into the open scene as nodes, always through one operation, `addAssets(paths, target)` (ADR 0149): it prepares them (a model's meshes), checks a scene is open and in edit mode, adds to the scene that was open when asked or to none, makes one undo step and returns the new nodes and a status message. The target is a scene-view point, a Hierarchy slot or the selection (the Assets panel's +). An asset kind can refuse an add (`addToScene.whyNot`) and leave a note about it (`addToScene.note`).
- **Node insertion:** putting nodes into a scene document, always through `insertNodes(scene, source, place)` (`src/editor/nodeInsertion.ts`, ADR 0246). The source is a new node of a kind, copied nodes (paste), a duplicate, assets or a template; the place is into a node, after a row, or near the selection (beside a prefab instance). Into a node inside an instance it is an `addNodes` override. It mints ids, makes names unique among siblings and gives one reason when it refuses. _Avoid:_ building `AddNode` entries or minting ids anywhere else.
- **Hierarchy drop:** where a drop on the Hierarchy lands (`src/editor/hierarchyDrop.ts`, ADR 0258): before, into or after a row, or the scene's top level, as a node insertion place and as a move spot (or the reason a move can't go there). Inside a prefab instance a drop inserts an `addNodes` override (an inner row's edges mean its parent); scene nodes can't move there. Asset drags and node drags share it.
- **Tree view:** the editor's one tree widget (`ui/TreeView.tsx`, ADR 0278): the Hierarchy, the live Hierarchy and the Assets panel's folders. It owns rows, caret, collapse, the keys (arrows, Home/End, F2, Delete), renaming in place, the drop indicator and the ARIA tree; an item set's **tree adapter** turns its items into `TreeRow`s with their edits (select, open, rename, remove, drag).
- **Row drag:** the editor's one press-and-drag gesture for moving rows (`pointerDrag.ts`, ADR 0278): a drag past a few pixels, in the press's own window, ended by release, Escape or a cancelled pointer. Node, UI element and live rows drag with it.
- **Node template:** a node a contribution describes with no id (`NodeTemplate`, ADR 0246): an asset kind's `addToScene.nodes` or a kind's template. Its `parent` is the index of an earlier template; the node insertion mints ids and names the root.
- **Edit gate:** the one answer to "can this be edited now?" (`src/editor/editGate.ts`, ADR 0247) for a scene, the open scene's UI documents or the project's files: one worded reason (no scene, no project, read-only, playing), reported to the status bar, then the undo step. `editor.scene.edit` and `beginEdit` go through it; plugins ask `editor.scene.whyNotEdit`. During play the scene document is read-only everywhere (ADR 0257); play-time edits go to the live World. _Avoid:_ comparing `playState` with `"edit"` to decide whether an edit may happen.
- **Slices capability:** an asset kind's `slices` flag (ADR 0149): its files are images that can be cut into slices (ADR 0040), whose `#slice` entries are sprites. The core image kind has it. _Avoid:_ comparing a kind with `"image"` to mean "has slices".
- **Asset policies:** an asset kind's rules for use: which fields may reference it, whether and as what node it can be added to a scene, how exports process it, and whether it is read-only or an importer sidecar.
- **Asset document:** one open asset file in the editor. It owns the file's current value, queued saves, the read-only check, telling its own writes from outside edits, and its persistent undo tree (ADR 0027). That history follows the file when it is renamed and is dropped when the file is deleted.
- **Asset document frame:** the SDK's `AssetDocumentFrame` (ADR 0265): what every editor of one asset document renders in. It marks its root as the document's (the active history while focused), shows the head (kind, file name, Undo / Redo), the problems and the read-only notice, and flushes on close; the kind supplies only its body. _Avoid:_ a hand-written head, undo buttons or read-only hint in a kind's editor.
- **Settings section:** a category of the Project settings panel a plugin's editor half registers, owning the top-level `project.json` keys it declares (`keys`, ADR 0151) and checking them (`problems`), such as Physics' `physics`. While it is registered its keys are in the panel's draft, saved and undone like the core keys; unregistered, the file keeps them untouched.
- **Project section:** a set of top-level `project.json` keys being edited by one panel (ADR 0151, `src/editor/projectSection.ts`): the draft and its undo, telling the panel's own write from an outside edit, keeping the draft when only another panel's keys changed, valid-only queued saves and after-save hooks. It reports its whole edit state (ADR 0181): its problems, one status (read-only, problems, saving, failed, saved) and undo flags that are off while the project is read-only. The Project Settings and Worlds panels are views over one each (`projectSettingsInstance.ts`, `worldsInstance.ts`), drawing one shared toolbar.
- **Settings section handle:** one top-level `project.json` key of the Project panel's settings draft as one interface (ADR 0253, `settingsSection` in `myco/editor`): its lenient parse and defaults (`read`), `write`, `set` by dotted path, `reset` (the key removed, so the defaults apply) and `problems`. A settings section's model builds its edits on one (`navigationSettings`, `physicsSettings`, `audioSettings`).
- **Named list:** a list of names a settings section keeps in the draft that scenes, prefabs, asset files or other settings name (ADR 0262): physics layers, sorting layers, audio buses, acoustic materials, global parameters. The section declares it as data (`names` on its contribution: where the names live, and the component fields, asset-file fields and settings that name them); another plugin adds its own references with `registerNameReferences`. **Settings names** (`src/editor/settingsNames.ts`) is the one shell module that tells a rename from the drafts, asks first, and renames the references, and moves them back on undo. _Avoid:_ a section rewriting scenes itself, or matching component types by name.
- **Active history:** the one edit history Undo and Redo act on right now, from the Edit menu, Ctrl/Cmd+Z and the History panel alike (ADR 0145). It follows focus: a **panel-local history** a panel registered on its root while focus or the last click is inside it (Project Settings, Worlds, the Sprite Editor, the Particle Graph), else the focused asset document's, else the open scene's. Text fields keep their own text undo. _Avoid:_ undo stack (for anything but the scene's `CommandStack`).
- **History tree:** the persistent, tree-shaped edit history of one edited value (`HistoryTree`, ADR 0027, 0267): its states, the current and saved state, which child redo goes to, the path between states, pruning by count and age, and the `myco.history@1` file it writes and adopts by hash. The scene's `CommandStack` and an asset document's `TextHistory` are built on it. _Avoid:_ "undo stack" for the tree itself (the stack is the scene's adapter, with groups and listeners).
- **Step adapter:** what moves an edited value across one history state's change, forward or back (`StepAdapter`, ADR 0267); it may refuse a change that doesn't fit (a damaged history), and then the whole move is abandoned. The scene's applies a document patch and replays text files; the text history's applies a text patch.
- **Viewport tool:** a scene-view tool a plugin's editor half registers (ADR 0138), installed on every scene view: it gets presses before selection and the transform gizmo, hover and keys, draws overlays, and may be the **active tool**, the one mode that replaces the transform gizmo until Escape, Q/W/E/R or play. Tile painting is one; so is editing a collider (ADR 0142). A tool may also mark outlines **selectable**, so a click inside one picks its node.
- **Tool mode:** what the active viewport tool is doing (the collider being edited, the brush picked), owned by the viewport-tool host (ADR 0231): entered and left through the tool context or `editor.viewport`, and ended by the host on another tool, Escape, play, another scene or, where the tool asks, a new selection. _Avoid:_ a module-level mode signal in a plugin.
- **Component edit toggle:** the Edit button in an Inspector component card's header (Edit Collider, Edit Zone) that a viewport tool gets by declaring `editsComponents` (ADR 0266). The host registers it and owns its rule: the tool's mode, a `ComponentEditMode`, names the card's node, Component type and index; it hides for several nodes and ends on removal or a new selection. _Avoid:_ a plugin's own edit button.
- **Gesture:** a viewport drag that is one undo step (`view.gesture`, ADR 0231). Escape reverts it; pointer cancel, blur, a tool switch or play close it and keep the edits.
- **Undo step:** a long-running edit on the open scene, opened with `editor.scene.beginEdit` and closed with `end()` or `cancel()` (ADR 0231). _Avoid:_ `scene.stack.beginGroup` in plugin code.
- **Play Worlds:** the Worlds of the running play session, as `editor.scene.playWorlds` lists them in step order (ADR 0232): read-only to plugins, empty while editing, a new list per session. The session owns stepping, pausing and stopping. _Avoid:_ importing the shell's `playing` signal in plugin code.
- **Scene toolbar item:** a button a plugin's editor half adds to the Scene toolbar that opens a popover (ADR 0142), such as Navigation's Nav overlay toggles.
- **Component header action:** a control a plugin's editor half adds to the header of an Inspector component card for some Component types (ADR 0142), such as Physics' Edit Collider.
- **Hierarchy create entry:** a node kind a plugin's editor half adds to the Hierarchy's Create menu (and the menu bar's), placed after a named entry (ADR 0146), such as Particles' Particle System, which writes a new effect first.
- **Asset action:** an entry a plugin's editor half adds to the Assets panel's context menu for selected files or slices (ADR 0146), such as Tilemaps' Create Tileset from Slices.
- **Play stats counter:** a per-World count a plugin's editor half adds to the Play Stats panel (ADR 0146), such as Navigation's nav agents.
- **Scene-file walk:** the one walk over a scene or prefab file (`mapSceneFile` in `scene/sceneFileWalk.ts`, ADR 0279): every component field value with its component type, wherever it sits (component data, field overrides, added components, added nodes), and every node list. Format migrations and asset cleanup are rules over it.
- **Scene-open migration:** work a plugin's editor half does on a scene when the editor opens it (ADR 0146), such as moving embedded particle effects into assets.
- **Field choices:** the dropdown values a plugin's editor half supplies for one Component field when they depend on more than its declaration (ADR 0152), such as Meshes' `MeshRenderer.variant`, the referenced model's material variants. A contribution names the type and field, a `none` choice that clears it, a `key` of what the choices depend on, and `choices` (may load). A field's fixed list stays its `choices` option (ADR 0042).
- **Clipboard text:** what a copy in the editor puts on the system clipboard (ADR 0226): JSON with a `format` tag (`myco.nodes@1`, `myco.shadergraph.clipboard@1`, `myco.particles.clipboard@1`), written and read by the clipboard module (`src/editor/clipboard.ts`, in `myco/editor`). A paste reads it only from a `paste` event and takes it over the in-memory copy when another editor wrote it. _Avoid:_ calling memory "the clipboard" when the text is meant; reading it with `navigator.clipboard.read`.
- **Graph document:** the shared, pure edits on a node graph (ADR 0228, `src/editor/graph/document.ts`): properties and the nodes that read them, groups, notes, clipboard round-trip and duplicate, built from a **graph kind**, a plugin's adapter that says what its items are, where groups and notes live and what its clipboard holds. `useGraphSelection` is its selection and shortcut controller. The Shader Graph and the Particle Graph are its two kinds.
- **Wiring gesture:** pressing a port to draw a wire, letting go on a port to connect, over a refusing port to see why (the **refusal hint**), or in empty space to open the node search; pressing a wired input picks its wire up (the **detached input**) to move or remove it (ADR 0259, `src/editor/graph/wiring.ts` `useGraphWiring`). A panel plugs in its graph's **wire edits** (`GraphWiringEdits`). **Find items** (`FindItem`) are what find (Ctrl+F) reads of a graph's canvas items.
- **Field edits:** setting, axis-setting and reverting a Component field from the Inspector, in `fieldEdits.ts` (ADR 0152): overrides on prefab instances, one undo step per action across the selected nodes.
- **Node edits:** the Inspector header's actions on the selected nodes, in `nodeEdits.ts`: switching on or off, renaming, reverting an inner node's name or active override (ADR 0122), and the prefab actions Create Prefab, Apply, Revert All and Open Prefab (ADR 0022, 0087). One undo step per action across the selection; each action says why it can't run (`whyNot`), a read-only project through the one read-only message (`readOnly.ts`).
- **Story harness:** `src/editor/stories/editorStory.tsx` (ADR 0235): `withEditor` builds the editor a story renders in (an in-memory project, the plugins, real scene tabs, a real play session), and stories reach state only through the editor surface. _Avoid:_ setting `currentProject`, `openScene` or `playState` in a story.
- **Idle prefetch:** code a plugin's editor half asks the editor to fetch once it is idle (ADR 0082, 0146), such as Physics' core and backends.
- **World service:** a lazily loaded per-World subsystem a plugin provides (physics 2D, physics 3D, navigation), started when a scene or an attached Component needs it. Other plugins can look one up as "that plugin's service, if enabled".
- **Physics backend:** a physics engine (Rapier today) adapted to the Physics plugin's backend interface for one dimension (ADR 0137). A backend plugin contributes it; the Physics plugin's shared sync core drives it through neutral descriptions, so Components and scripts never see it. A project picks one with `physics.backend2d`/`backend3d`, or uses the only one enabled. _Avoid:_ physics engine (for the plugin), physics world (that is one World's simulation).
- **Editor service:** the editor-side counterpart of a World service, a named, typed object a plugin publishes for other plugins to use if it is enabled.
- **Core:** what is never a plugin. In the engine: World, ECS, GameObject and Transform, scene files, prefabs and overrides, assets, time, input, `Engine`, the renderer core and netcode. In the editor (the **editor shell**): panels and docking, Hierarchy, Viewport, the Inspector and Assets frames, undo, the scene document, the Code panel, Play, Export, and the graph view.

## Rendering (ADR 0153, 0240, 0244)

- **Effect player:** one particle effect at one transform on the Babylon backend (`render/babylon/effectPlayer.ts`): its runner, its kernel systems (every system runs on a **kernel executor**: JavaScript, WebGPU compute or WebGL2 textures, ADR 0251), their draws and fallbacks, and how it plays (restart, event-started systems, events, emit, stop, seeding). A World's ParticleSystems (one player each, through `BabylonParticles`), the particle graph's preview and the particle thumbnails all play through it. The players of one scene share **effect resources** (texture cache, dot, scene depth, kernel host). _Avoid:_ particle player (for anything but `BabylonParticles`, the World adapter).
- **Thumbnail renderer:** a `BabylonRenderer` made with `forThumbnail` that draws a prefab's, scene's, environment map's or sky's headless World with the real render features on the thumbnail engine (ADR 0153, 0189), under the thumbnail policy (no warm-up machinery, a shared studio room, an engine it doesn't own). The thumbnail code only frames and captures.
- **Engine factory:** `createEngine` (`render/babylon/createEngine.ts`, ADR 0244), the one place a Babylon engine that draws into a canvas is made, for a World's surface and every preview and thumbnail: WebGPU, else, or when WebGPU can't start, WebGL2.
- **Pipeline readiness:** a World's renderer module that warms shader pipelines, re-warms them on a tier change or new probe captures, and holds the World's first frames until what it draws is ready (`render/babylon/pipelineReadiness.ts`; ADR 0080, 0120, 0240). Thumbnail renderers have none.
- **Preview inset:** where the editor's camera preview sits on the canvas, as fractions (`PreviewInset`, ADR 0240). The editor's viewport handle measures it once a frame; the renderer never reads the DOM for it.
- **PBR injection point:** a named place in Babylon's include-expanded PBR shader where the engine puts code (ADR 0222), such as `albedoBlock` or `worldPosition`, asked for through `pbrInjections` in `render/babylon/pbrInjection.ts`, which owns its pattern per shader language and re-declares what it replaces. _Avoid:_ anchor (for anything outside that module).
- **Myco material plugin:** one of the engine's own Babylon material plugins (graph, water, probe blend, sprite UV), all extending `MycoMaterialPlugin` (ADR 0225, `render/babylon/mycoMaterialPlugin.ts`), which registers it only after its fields are set and declares WGSL and GLSL. Render tests check what such a plugin does through the **compiled shader text** (`engine/tests/pbrShaderSource.ts` `shaderText`), the source Babylon builds after expanding includes and injecting plugin code. _Avoid:_ reading a plugin's `"!"` keys outside the pin test.
- **Lighting rig:** the core module that lights a World on the Babylon backend (`BabylonLighting`, `render/babylon/lighting.ts`; ADR 0140, 0252): Light components and their shadow requests, the Environment's lighting, the studio room and the skybox. Features in the `lighting` phase give it **lighting contributions** for the frame (`contribute`: the sky's sun and bake, the fog's sky fog), and the renderer resolves it once after that phase. A lighting contribution is per-frame data, not a plugin's contribution at a contribution point. _Avoid:_ lights feature, environment feature (both gone).
- **KSL (shader source):** the engine's small shader source language (ADR 0094, 0250), the common subset of WGSL and GLSL with macros (`VAR`, `FN`, `UNI`, `KTEX`…). A `ShaderSource` (`render/shaderSource/`) holds one KSL text and gives its WGSL, its GLSL and a JavaScript program of its functions. Shader maths is written once in it; only Babylon injection glue and entry points are written per language. _Avoid:_ hand-written WGSL/GLSL twins.
- **Kernel step:** one built-in particle operation of a kernel program (age, forces, noise, orbit, collisions, place, a spawn shape), written once in KSL and once in JavaScript side by side in the steps catalogue (`render/particles/gpu/kernelSteps.ts`, ADR 0251), which the shaders and the JavaScript executor both take. _Avoid:_ behaviour (the retired CPU simulation's word); CPU simulation (for the JavaScript executor).

## Audio

- **Audio debug monitor:** the editor module behind the Audio Debug panel (ADR 0220, `audioDebugMonitor.ts`): snapshots of `Audio.debug()` in, the panel's sections out. Its rule: a **total** comes from a counter that outlives the instance that counted it (the core's, or main's session totals); a per-instance value appears only in the per-instance table. _Avoid:_ summing playing rows into a total.
- **Core assembly:** connecting an audio host to its mixer, arming trap recovery and making the core backend, done only by `assembleCore` (ADR 0221, `runtime/core/assembly.ts`). The AudioWorklet host (the service), the loopback host (`loopbackAudio`, tests) and the recording host (`recordingAudio`, the wire tier, ADR 0234) are its three adapters; outside `coreBackend.ts`, `CoreBackend` is a type only. _Avoid:_ building a `CoreBackend` by hand in a test.
- **Recording host:** the third adapter of `assembleCore` (ADR 0234, `runtime/testing.ts` `recordingAudio`): a real `AudioHost` whose node runs no core. What main posts is recorded and read as the loopback's `watch()` reads it; the test hands main its STATUS blocks, and the clock and clips (`makeFakeClipRegistry`) are the test's. It is the wire tier for the backend's own logic. _Avoid:_ a hand-rolled recording link or a fake `CoreBackendHost`.
- **Stream port:** the worklet's end of the channel to the decoder worker, handed over with `CoreLink.connectStreamPort` (`{type:"streamPort"}`). Streams and zone kernels reach the audio thread on it and its credits go back on it, never through main (ADR 0223). The test loopback serves it as the AudioWorklet processor does.
- **Frame map:** how the core maps context time to its frames: sample rate, `timeOffset` and whether a carry is pending (ADR 0224), read through `AudioClock.frameMap()`; null where the backend has no core clock.
- **Capture event:** one EVENT record of a capture, decoded into the typed `CaptureEvent` union by the capture reader (ADR 0227, `capture/events.ts` beside the writer). The Profiler reads only capture events, never the EVENT arg layout. _Avoid:_ `args[n]` outside `capture/events.ts`.
- **Promotion (music):** a run becoming the music player's playing run: it stops being the successor, the grid is anchored on its start and its loop-region state starts fresh (ADR 0229). Only `promote` in `music/musicPlayer.ts` does it; the player is otherwise a read-only view whose state moves only through that module's named transitions. _Avoid:_ assigning `player.run`, `next`, `anchor` or `state`.
- **Music lifecycle event:** what a backend reports up the music seam that isn't about one group: a rebuild's begin and end, a recovery with its cause, the page hiding and each hidden STATUS tick (ADR 0248, `MusicBackend.onLifecycle`). The backend reports; `music/background.ts` alone decides what to re-plan. _Avoid:_ a backend calling into `music/`, or music probing a backend field such as `isRecovering`.
- **Row composer:** the module above the audio backend seam that adds the event and music sections to `Audio.debug()` and the capture keyframe, from the page-wide registries, for every backend (ADR 0249, `runtime/audioRows.ts`). Backends report only voices, buses, meters and mix. _Avoid:_ building event or music rows inside a backend.
- **Keyframe layout:** the KEYFRAME row encoding of a capture (caps, state codes, flag bits, `NO_NAME`, u4.12 pitch, u0.16 audibility), owned by `capture/keyframeLayout.ts` (ADR 0230), which imports nothing so the core can use it without loading the recorder. Writers quantise through it; readers decode only through `readCaptureKeyframe`. _Avoid:_ repeating its bits or the 4096 / 65536 scales.
- **Capture names:** what a capture calls a clip, bus slot, event asset, parameter, snapshot or target at an instant (ADR 0260, `capture/names.ts`): META's names from the start, then each NAMES record from its own time; a bus slot gets a new record whenever it takes a new name. One fallback text (`bus 3`; "Master" for the output). _Avoid:_ a view's own name map or fallback.
- **Reason word:** the sink's word for why a voice stopped, was stolen, went virtual or real, was refused or queued (`busMaxVoices`, `capDemoted`), which the capture reader gives instead of §5.6's code (ADR 0260, `capture/reasons.ts`, with `reasonText`). _Avoid:_ reason code tables outside `reasons.ts`.
- **Track kit:** the Profiler's reading layer for timeline tracks (ADR 0261, `editor/mix/tracks/kit.ts`): tracks declare the STATUS columns and EVENTs they read and a build function; the kit reads each capture growth once for all of them and answers the sample in force at t. _Avoid:_ a track calling `statusColumns`, `range` or a bisect of its own.
- **Segment grid:** a music segment's compiled tempo map with its cues, entry and exit in ticks (G1), as `music/segmentGrids.ts` gives it now (ADR 0263): with the file's end once the **segment length** is known (its first track that names a clip: the clip's facts, else the decoded length). _Avoid:_ compiling or caching a segment's grid anywhere else in the runtime.
- **Stamped ramp:** a voice's `fadeShaped` (its `fade` gain, optionally stopping at the end) or `paramsShaped` (its own gain and low-pass), starting at a heard time. Every adapter's voice takes one (ADR 0264): sample-exact on the core, timer steps on the Babylon fallback, recorded and forwarded by the pending voice. _Avoid:_ probing for it or falling back to `fade`/`stop` in callers.
- **Audio frame (frame step):** one backend frame in the production order, run only by `runAudioFrame` (ADR 0270, `runtime/audioFrame.ts`): attenuation, voice collection, Doppler, zones, occlusion, selection, panner pick, fx, listener, music plan, commit on the core (its `StagedFrameHost` stages); the passes, the music plan and `update` on the Babylon fallback; the music plan and `update` on a plain backend. The audio system and every test rig (`audioFrameDriver`, the rigs' `tick`) call it. _Avoid:_ calling the core's stages, or a backend's `update`, to drive a frame.
- **Audition (editor):** the one instance the editor plays to let the person hear an event, whoever pressed Play (the Event editor, the segment transport, the rules table), owned by `editor/audition/audition.ts` (ADR 0268, `editorAudition`): flush then play, the end of the instance, live slider overrides, the notice; the music extras are options of the same play. The panels are views over it. _Avoid:_ calling `Audio.play` for an audition from a panel, or a panel keeping its own handle.
- **Music path:** a music node's address from its event's root, child indexes and library steps `"lib<n>"` (`[1, "lib0"]`), beside its id; `engine/audio/musicTree.ts` maps between the two and owns every descent over `children` and `library` (ADR 0269). _Avoid:_ walking `children`/`library` by hand to find or replace a node.

## Tilemaps (ADR 0103)

- **Orientation:** one of a tile's 8 flips and turns, its flip flags read as a transform of the cell, diagonal first, then X, then Y (as Tiled). `runtime/tileFlips.ts` is the one place that convention lives: `compose`, `inverse`, `rotateClockwise`, `flipPoint`, `sourceCorner`.

## Hosts (ADR 0236)

- **Launch:** the ordered start of a game every host shares, through `launchGame` (`src/engine/launch.ts`): the asset source, scripts, plugin activation (passed in by the host), the Engine, then the entry scene; `dispose()` undoes it in reverse. The player, the dedicated server and play mode are its adapters. _Avoid:_ boot, bootstrap (that is a World's start-up plan, ADR 0032).
- **Entry scene:** the scene that empty start-up Worlds (no `scenes` key and no nodes) load at launch: a build's main scene, or play mode's open scene. The dedicated server has none.
- **Project file:** a file in a project folder that loads as an asset (`isProjectFile` in `engine/scene/projectFiles.ts`, ADR 0254): not hidden, not in a dependency or build folder, not TypeScript source (scripts are read apart). Its **file kind** (`projectFileKind`) says what it loads as on every host: `json` (parsed), `text` (its contents) or `url` (a URL serving its bytes). Read it with `Assets.json`, `Assets.text` or `Assets.url` (`Assets.bytes` for a url file's bytes). _Avoid:_ testing an asset value's type to guess what a file is; a host's own extension list.
- **Listen target:** where a server World listens over one transport (`listenTarget` in `engine/net/listenTarget.ts`, ADR 0255): host, port, path and the normalised address, from the host's overrides (the dedicated server's `--host`/`--port`), then the options (`address`, else `port`/`host`/`path`, else a client `url`), then the host's per-Engine defaults. _Avoid:_ building or parsing listen address strings by hand; process-wide listen defaults.
- **Bootstrap topology:** which World of a declarative bootstrap plays which network role (`bootstrapTopology` in `engine/core/bootstrapTopology.ts`, ADR 0256): start-up servers, server templates and lobbies, the **Host template** (the first `server`-tagged template when nothing else serves: play creates it, the dedicated server starts it), what the dedicated server starts, where each server listens, and the client Worlds play copies. The server, play mode and the Worlds panel read it. _Avoid:_ testing `tags` for "server" by hand.

## Play mode (ADR 0237)

- **Play controller:** the editor's one play session (`createPlaySession` in `playSession.ts`, ADR 0237). It owns the edit, starting and playing states and the work deferred to Stop: kept values, plugin settings and script reloads. Not the same as `PlaySession` in `playMode.ts`, which is one running game.

## Engine (ADR 0238, 0239)

- **View allocator:** what decides which surface (the main view, a tile, or none after a hand-over) and which input target each World has (`core/viewAllocator.ts`, ADR 0238). The Engine asks it `surfaceOf(world)`.
- **End of frame:** the last step of a World's frame (ADR 0011, 0239). Work queued with `World.atFrameEnd` runs there, after deferred destroys; outside a frame it runs at once. _Avoid:_ checking `inFrame` by hand.

## UI (ADR 0076, 0271)

- **Element kind:** one of the closed set of UI element kinds (canvas, panel, text, image, button, input field), each one row in `ui/elementKinds.ts`: its component type, markup tag, whether it is a leaf, whether it takes the pointer, its pseudo-classes and whether it paints. _Avoid:_ switching on UI component classes outside that module.
- **Text run:** an element's resolved text: text, size, CSS weight, family, line height and wrapping (`textRunOf`, ADR 0271). The UI core measures it and reports it on each laid-out element; the drawing layer draws exactly it. _Avoid:_ reading a text component's font fields in a drawing layer.

## Project settings (ADR 0272)

- **Runtime settings section:** one top-level `project.json` key the engine reads, declared once in `RUNTIME_SETTINGS` (`core/settings.ts`): its key, default and lenient parse giving the value the engine runs with (bad values replaced by defaults) and its problems and warnings by field. `resolveSettings`, the Engine's start-up warnings and the Project panel go through it; a settings section handle (ADR 0253) is its editor twin. _Avoid:_ checking a runtime key's values in the editor alone.
