# Glossary

The domain terms used in Myco Engine's code, decision records and reviews. Add a term when a decision gives a concept a name, and sharpen an entry when its meaning gets clearer. The core engine terms (Node, GameObject, GameBehavior, Component, World and so on) are in the [architecture overview's glossary](docs/architecture/overview.md#glossary); this file holds the rest.

## Plugins and the SDK (ADR 0133)

- **Plugin:** a feature, packaged as a manifest (`plugin.json`), a runtime half and an editor half. It registers contributions into contribution points. A plugin is a feature, not one asset type. For example, Materials and Shaders can be one plugin. _Avoid:_ package (that means an npm package, ADR 0125), extension, module (for a whole plugin).
- **Runtime half:** a plugin's `runtime/` folder, holding Components, systems, World services and asset loaders. It ships in game builds and on the dedicated server, and never imports editor code.
- **Editor half:** a plugin's `editor/` folder, holding asset kinds, asset document formats, panels, inspector sections, viewport tools, settings sections, importers, thumbnails and "New…" entries. It may import its runtime half.
- **Contribution point:** a registry that plugins register into, such as asset kinds, Components or World services. Each supports unregistering.
- **Contribution:** one thing a plugin registers at a contribution point.
- **SDK:** the public surface plugins are written against. `myco` is the runtime SDK. `myco/editor` is the editor SDK, importable only from editor halves: the contribution points, asset documents, the **editor surface** and building blocks (fields, theme, graph view). Anything else is the **internal tier**, for first-party plugins only, and the imports first-party editor halves still make into it are listed in `plugins/plugins.test.ts` (ADR 0147).
- **Editor surface:** the `editor` object of `myco/editor` (ADR 0147): `editor.project` (the open project, its change `version`, `createFile`), `editor.assets` (what a path is), `editor.messages` (the status bar) and `editor.scene` (open scene tabs, selection, play state). It reads the shell's state (`state.ts`), which plugins never import. _Avoid:_ `currentProject`, `docVersion`, `status` in plugin code.
- **First-party plugin:** a plugin shipped with the engine, in `src/plugins/<name>/`, versioned with the engine.
- **Third-party plugin:** a plugin found in a project's `plugins/<name>/` folder or in its `node_modules`.
- **Plugin set:** what a host (the player, the dedicated server, the editor) makes plugins active through (ADR 0144): it takes every plugin the host knows and the project's `plugins.disabled`, works out which are enabled, orders them, activates or deactivates their halves, and reports the ones that fail. Plugins never see it; they see only their half's context. _Avoid:_ plugin host, plugin manager.
- **Asset kind:** one type of asset file and how the editor treats it: how its files are recognised, its label and icon, what opening it does, its inspector, preview and import, and its policies.
- **Core asset kind:** an asset kind the editor shell itself registers (ADR 0143): scenes, prefabs, images, audio, render textures and the code and text kinds, in `src/editor/assetKinds.builtin.ts`. It is an ordinary asset kind contribution, registered at boot; it can't be disabled and is in no manifest. Folders, sprite slices and plain files are answered by the asset kind module (`assetKindLookup.ts`) itself.
- **Asset reference:** a string in a project file naming a project path: optionally `asset:` and a leading `./` or `/`, the path, and optionally `#slice` (ADR 0040), such as `asset:images/sheet.png#walk_0`. The asset reference module (`assetReferences.ts`, ADR 0148) is the one place that parses them and answers who **uses** an asset (files quoting a reference to it), what an asset **depends on**, and rewrites or removes references when files move or go. _Avoid:_ stripping `asset:` by hand.
- **Reference extractor:** an asset kind's `references` (ADR 0148): how files in the kind's own format name other files, such as an .obj's material libraries or a .gltf's buffers. JSON files need none.
- **Asset entry:** an Assets panel item as a string: a file (`images/a.png`), a folder (`images/`) or a slice (`images/sheet.png#walk_0`). `assetEntry.ts` is the one place that knows the encoding (ADR 0157).
- **Assets command:** Open, Rename, Duplicate, Copy, Cut, Paste or Delete on the Assets panel's selection (`assetActions.ts`, ADR 0157). Each has one rule (`whyNotAsset`), the same check its operation makes, used by the panel's menu, its keys and the menu bar.
- **Adding assets:** putting project files into the open scene as nodes, always through one operation, `addAssets(paths, target)` (ADR 0149): it prepares them (a model's meshes), checks a scene is open and in edit mode, adds to the scene that was open when asked or to none, makes one undo step and returns the new nodes and a status message. The target is a scene-view point, a Hierarchy slot or the selection (the Assets panel's +). An asset kind can refuse an add (`addToScene.whyNot`) and leave a note about it (`addToScene.note`).
- **Slices capability:** an asset kind's `slices` flag (ADR 0149): its files are images that can be cut into slices (ADR 0040), whose `#slice` entries are sprites. The core image kind has it. _Avoid:_ comparing a kind with `"image"` to mean "has slices".
- **Asset policies:** an asset kind's rules for use: which fields may reference it, whether and as what node it can be added to a scene, how exports process it, and whether it is read-only or an importer sidecar.
- **Asset document:** one open asset file in the editor. It owns the file's current value, queued saves, the read-only check, telling its own writes from outside edits, and its persistent undo tree (ADR 0027). That history follows the file when it is renamed and is dropped when the file is deleted.
- **Settings section:** a category of the Project settings panel a plugin's editor half registers, owning the top-level `project.json` keys it declares (`keys`, ADR 0151) and checking them (`problems`), such as Physics' `physics`. While it is registered its keys are in the panel's draft, saved and undone like the core keys; unregistered, the file keeps them untouched.
- **Project section:** a set of top-level `project.json` keys being edited by one panel (ADR 0151, `src/editor/projectSection.ts`): the draft and its undo, telling the panel's own write from an outside edit, keeping the draft when only another panel's keys changed, valid-only queued saves and after-save hooks. The Project Settings and Worlds panels are views over one each.
- **Active history:** the one edit history Undo and Redo act on right now, from the Edit menu, Ctrl/Cmd+Z and the History panel alike (ADR 0145). It follows focus: a **panel-local history** a panel registered on its root while focus or the last click is inside it (Project Settings, Worlds, the Sprite Editor, the Particle Graph), else the focused asset document's, else the open scene's. Text fields keep their own text undo. _Avoid:_ undo stack (for anything but the scene's `CommandStack`).
- **Viewport tool:** a scene-view tool a plugin's editor half registers (ADR 0138), installed on every scene view: it gets presses before selection and the transform gizmo, hover and keys, draws overlays, and may be the **active tool**, the one mode that replaces the transform gizmo until Escape, Q/W/E/R or play. Tile painting is one; so is editing a collider (ADR 0142). A tool may also mark outlines **selectable**, so a click inside one picks its node.
- **Scene toolbar item:** a button a plugin's editor half adds to the Scene toolbar that opens a popover (ADR 0142), such as Navigation's Nav overlay toggles.
- **Component header action:** a control a plugin's editor half adds to the header of an Inspector component card for some Component types (ADR 0142), such as Physics' Edit Collider.
- **Hierarchy create entry:** a node kind a plugin's editor half adds to the Hierarchy's Create menu (and the menu bar's), placed after a named entry (ADR 0146), such as Particles' Particle System, which writes a new effect first.
- **Asset action:** an entry a plugin's editor half adds to the Assets panel's context menu for selected files or slices (ADR 0146), such as Tilemaps' Create Tileset from Slices.
- **Play stats counter:** a per-World count a plugin's editor half adds to the Play Stats panel (ADR 0146), such as Navigation's nav agents.
- **Scene-open migration:** work a plugin's editor half does on a scene when the editor opens it (ADR 0146), such as moving embedded particle effects into assets.
- **Field choices:** the dropdown values a plugin's editor half supplies for one Component field when they depend on more than its declaration (ADR 0152), such as Meshes' `MeshRenderer.variant`, the referenced model's material variants. A contribution names the type and field, a `none` choice that clears it, a `key` of what the choices depend on, and `choices` (may load). A field's fixed list stays its `choices` option (ADR 0042).
- **Field edits:** setting, axis-setting and reverting a Component field from the Inspector, in `fieldEdits.ts` (ADR 0152): overrides on prefab instances, one undo step per action across the selected nodes.
- **Idle prefetch:** code a plugin's editor half asks the editor to fetch once it is idle (ADR 0082, 0146), such as Physics' core and backends.
- **World service:** a lazily loaded per-World subsystem a plugin provides (physics 2D, physics 3D, navigation), started when a scene or an attached Component needs it. Other plugins can look one up as "that plugin's service, if enabled".
- **Physics backend:** a physics engine (Rapier today) adapted to the Physics plugin's backend interface for one dimension (ADR 0137). A backend plugin contributes it; the Physics plugin's shared sync core drives it through neutral descriptions, so Components and scripts never see it. A project picks one with `physics.backend2d`/`backend3d`, or uses the only one enabled. _Avoid:_ physics engine (for the plugin), physics world (that is one World's simulation).
- **Editor service:** the editor-side counterpart of a World service, a named, typed object a plugin publishes for other plugins to use if it is enabled.
- **Core:** what is never a plugin. In the engine: World, ECS, GameObject and Transform, scene files, prefabs and overrides, assets, time, input, `Engine`, the renderer core and netcode. In the editor (the **editor shell**): panels and docking, Hierarchy, Viewport, the Inspector and Assets frames, undo, the scene document, the Code panel, Play, Export, and the graph view.

## Rendering (ADR 0153)

- **Effect player:** one particle effect at one transform on the Babylon backend (`render/babylon/effectPlayer.ts`): its runner, CPU simulation and kernel systems, their draws and fallbacks, and how it plays (restart, event-started systems, events, emit, stop, seeding). A World's ParticleSystems (one player each, through `BabylonParticles`), the particle graph's preview and the particle thumbnails all play through it. The players of one scene share **effect resources** (texture cache, dot, scene depth, kernel host). _Avoid:_ particle player (for anything but `BabylonParticles`, the World adapter).
- **Thumbnail renderer:** a `BabylonRenderer` made with `forThumbnail` that draws a prefab's or scene's headless World with the real render features on the thumbnail engine, under the thumbnail policy (no warm-up machinery, a shared studio room, an engine it doesn't own). The thumbnail code only frames and captures.

## Hosts (ADR 0155)

- **Launch:** the ordered start of a game every host shares, through `launchGame` (`src/engine/launch.ts`): the asset source, scripts, plugin activation (passed in by the host), the Engine, then the entry scene; `dispose()` undoes it in reverse. The player, the dedicated server and play mode are its adapters. _Avoid:_ boot, bootstrap (that is a World's start-up plan, ADR 0032).
- **Entry scene:** the scene that empty start-up Worlds (no `scenes` key and no nodes) load at launch: a build's main scene, or play mode's open scene. The dedicated server has none.

## Inspector (ADR 0158)

- **Field target:** what an Inspector field row edits: one component field on one or more nodes (`src/editor/fieldTarget.ts`). It has two adapters: the edited document (undoable, overrides on instances) and a live World (play only). Both inspectors render the same field rows over it.

## Engine (ADR 0159, 0160)

- **View allocator:** what decides which surface (the main view, a tile, or none after a hand-over) and which input target each World has (`core/viewAllocator.ts`, ADR 0159). The Engine asks it `surfaceOf(world)`.
- **End of frame:** the last step of a World's frame (ADR 0011, 0160). Work queued with `World.atFrameEnd` runs there, after deferred destroys; outside a frame it runs at once. _Avoid:_ checking `_inFrame` by hand.

## Play mode (ADR 0161)

- **Play controller:** the editor's one play session (`createPlaySession` in `playSession.ts`, ADR 0161). It owns the edit, starting and playing states and the work deferred to Stop: kept values, plugin settings and script reloads. Not the same as `PlaySession` in `playMode.ts`, which is one running game.
