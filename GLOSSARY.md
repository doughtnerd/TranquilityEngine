# Glossary

The domain terms used in Myco Engine's code, decision records and reviews. Add a term when a decision gives a concept a name, and sharpen an entry when its meaning gets clearer. The core engine terms (Node, GameObject, GameBehavior, Component, World and so on) are in the [architecture overview's glossary](docs/architecture/overview.md#glossary); this file holds the rest.

## Plugins and the SDK (ADR 0133)

- **Plugin:** a feature, packaged as a manifest (`plugin.json`), a runtime half and an editor half. It registers contributions into contribution points. A plugin is a feature, not one asset type. For example, Materials and Shaders can be one plugin. _Avoid:_ package (that means an npm package, ADR 0125), extension, module (for a whole plugin).
- **Runtime half:** a plugin's `runtime/` folder, holding Components, systems, World services and asset loaders. It ships in game builds and on the dedicated server, and never imports editor code.
- **Editor half:** a plugin's `editor/` folder, holding asset kinds, asset document formats, panels, inspector sections, viewport tools, settings sections, importers, thumbnails and "New…" entries. It may import its runtime half.
- **Contribution point:** a registry that plugins register into, such as asset kinds, Components or World services. Each supports unregistering, and records which plugin registered each entry. The editor's points are declared once, in the table the plugin context is made from (`CONTRIBUTION_POINTS`, ADR 0284).
- **Contribution:** one thing a plugin registers at a contribution point.
- **SDK:** the public surface plugins are written against. `myco` is the runtime SDK. `myco/editor` is the editor SDK, importable only from editor halves: the contribution points, asset documents, the **editor surface** and building blocks (fields, theme, graph view). Anything else is the **internal tier**, for first-party plugins only, and the imports first-party editor halves still make into it are listed in `plugins/plugins.test.ts` (ADR 0147).
- **Editor surface:** the `editor` object of `myco/editor` (ADR 0147): `editor.project` (the open project, its change `version`, `createFile`), `editor.assets` (what a path is), `editor.messages` (the status bar) and `editor.scene` (open scene tabs, selection, play state). It reads the shell's state (`state.ts`), which plugins never import. _Avoid:_ `currentProject`, `docVersion`, `status` in plugin code.
- **First-party plugin:** a plugin shipped with the engine, in `src/plugins/<name>/`, versioned with the engine.
- **First-party catalogue:** `src/plugins/catalogue.ts` (ADR 0275): one entry per first-party plugin, keyed by its folder, holding its manifest. The runtime and editor halves are tables keyed by its entries, and every host checks third-party plugins against it. _Avoid:_ a separate list of first-party plugins or manifests.
- **Plugin code plan:** `planPluginCode` (ADR 0139, 0275): what a host loads of a project (its plugins found, usable, enabled and loaded, the code and npm entries to compile, the problems). The editor, game builds and the dedicated server all run it. _Avoid:_ a host discovering or checking plugins itself.
- **Third-party plugin:** a plugin found in a project's `plugins/<name>/` folder or in its `node_modules`.
- **Plugin set:** what a host (the player, the dedicated server, the editor) makes plugins active through (ADR 0144): it takes every plugin the host knows and the project's `plugins.disabled`, works out which are enabled, orders them, activates or deactivates their halves, and reports the ones that fail. Plugins never see it; they see only their half's context. _Avoid:_ plugin host, plugin manager.
- **Asset kind:** one type of asset file and how the editor treats it: how its files are recognised, its label and icon, what opening it does, its inspector, preview and import, and its policies.
- **Asset kind host:** `src/editor/assetKindHost.ts` (ADR 0233), reached as `editor.assets.create`/`read`/`open`/`openIn`: it creates a kind's files in its default folder, gives a file's **current value** (the open asset document's, unwritten edits included, else the file parsed with the kind's format) and opens a file in the kind's panel, remembering each panel's file. A kind declares only its `format`, `folder` and `panel`. _Avoid:_ per-plugin `readX` wrappers, default-folder helpers or open-in-panel signals.
- **Core asset kind:** an asset kind the editor shell itself registers (ADR 0143): scenes, prefabs, images, audio, render textures and the code and text kinds, in `src/editor/assetKinds.builtin.ts`. It is an ordinary asset kind contribution, registered at boot; it can't be disabled and is in no manifest. Folders, sprite slices and plain files are answered by the asset kind module (`assetKindLookup.ts`) itself.
- **Asset reference:** a string in a project file naming a project path: optionally `asset:` and a leading `./` or `/`, the path, and optionally `#slice` (ADR 0040), such as `asset:images/sheet.png#walk_0`. The asset reference module (`assetReferences.ts`, ADR 0148) is the one place that parses them and answers who **uses** an asset and what an asset **depends on** from one walk (a kind's `references` reader, else a JSON file's reference strings; scripts by quoted path; ADR 0302), and rewrites or removes references when files move or go. _Avoid:_ stripping `asset:` by hand.
- **Reference extractor:** an asset kind's `references` (`AssetReferences`, ADR 0148, 0314): how files in the kind's own format name other files, such as an .obj's material libraries or a .gltf's buffers, and how such a file is rewritten for a move (references to moved files, and a moved file's own relative references). JSON files need none: their owners rewrite them (ADR 0302).
- **Asset entry:** an Assets panel item as a string: a file (`images/a.png`), a folder (`images/`) or a slice (`images/sheet.png#walk_0`). `assetEntry.ts` is the one place that knows the encoding (ADR 0241).
- **Assets command:** Open, Rename, Duplicate, Copy, Cut, Paste or Delete on the Assets panel's selection (`assetActions.ts`, ADR 0241). Each has one rule (`whyNotAsset`), the same check its operation makes, used by the panel's menu, its keys and the menu bar.
- **Inspector target:** what the Inspector shows: a live World's node, an asset, a UI element, nodes, or scene settings (`inspectorTarget.ts`, ADR 0242). Every selection (nodes, Assets panel entries, a UI element) goes through its functions, which keep them apart. _Avoid:_ clearing another selection by hand, or writing `selectedKeys`, `selectedAssets` or `selectedUIElement` directly.
- **Field target:** what an Inspector field row edits: one component field on one or more nodes (`src/editor/fieldTarget.ts`, ADR 0243). It has two adapters: the edited document (undoable, overrides on instances) and a live World (play only). Both Inspectors render the same field rows (`ui/fieldRows.tsx`) over it, and both adapters write through the component field write.
- **Component field write:** setting one field of one component, in a scene document or on a live node (`src/editor/componentField.ts`, ADR 0257; `editor.scene.writeField` and `beginFieldDrag` in `myco/editor`). A document write asks the edit gate, is an override inside a prefab instance and skips an unchanged value; a drag is one undo step. The Inspector, plugin sections and gizmos all use it. _Avoid:_ building `SetField` outside the shell's edit modules; calling a plugin's write helper a "field target".
- **Field kind:** one kind of value an Inspector field edits (number, vector, colour, node reference, asset, rotation, list…), as an entry of the field-kinds table (`fieldKind(field)` in `src/editor/fields/kinds.ts`, ADR 0273). It owns the value's scene-file form (node references resolved by a required `NodeIds`; a list's kind carries its item kind), when two values are the same, the blank value, whether it may be unset (vectors: Auto) and per-axis edits. Its widget is registered by kind in `ui/fieldRows.tsx`. A rotation's kind is built on its field codec (ADR 0165).
- **Adding assets:** putting project files into the open scene as nodes, always through one operation, `addAssets(paths, target)` (ADR 0149): it prepares them (a model's meshes), checks a scene is open and in edit mode, adds to the scene that was open when asked or to none, makes one undo step and returns the new nodes and a status message. The target is a scene-view point, a Hierarchy slot or the selection (the Assets panel's +). An asset kind can refuse an add (`addToScene.whyNot`) and leave a note about it (`addToScene.note`).
- **Node insertion:** putting nodes into a scene document, always through `insertNodes(scene, source, place)` (`src/editor/nodeInsertion.ts`, ADR 0246). The source is a new node of a kind, copied nodes (paste), a duplicate, assets or a template; the place is into a node, after a row, or near the selection (beside a prefab instance). Into a node inside an instance it is an `addNodes` override. It mints ids, makes names unique among siblings and gives one reason when it refuses. _Avoid:_ building `AddNode` entries or minting ids anywhere else.
- **Hierarchy drop:** where a drop on the Hierarchy lands (`src/editor/hierarchyDrop.ts`, ADR 0258): before, into or after a row, or the scene's top level, as a node insertion place and as a move spot (or the reason a move can't go there). Inside a prefab instance a drop inserts an `addNodes` override (an inner row's edges mean its parent); scene nodes can't move there. Asset drags and node drags share it.
- **Tree view:** the editor's one tree widget (`ui/TreeView.tsx`, ADR 0278): the Hierarchy, the live Hierarchy and the Assets panel's folders. It owns rows, caret, collapse, the keys (arrows, Home/End, F2, Delete), renaming in place, the drop indicator and the ARIA tree; an item set's **tree adapter** turns its items into `TreeRow`s with their edits (select, open, rename, remove, drag).
- **OS drop controller:** the one module that decides a file drop from the OS on the Assets panel (`editor/osDropController.ts`, ADR 0324): for the element under the pointer, whether it is the panel's, the target folder, the hover state, the project's refusal and the import. A **drop source adapter** turns a platform's events (the browser's HTML5 drag events, Tauri's drag-drop event) into its over, left and dropped phases. _Avoid:_ checking `whyNotImportable` or resetting the hover state in an adapter.
- **Row drag:** the editor's one press-and-drag gesture for moving rows (`pointerDrag.ts`, ADR 0278): a drag past a few pixels, in the press's own window, ended by release, Escape or a cancelled pointer. Node, UI element and live rows drag with it.
- **Node template:** a node a contribution describes with no id (`NodeTemplate`, ADR 0246): an asset kind's `addToScene.nodes` or a kind's template. Its `parent` is the index of an earlier template; the node insertion mints ids and names the root.
- **Edit gate:** the one answer to "can this be edited now?" (`src/editor/editGate.ts`, ADR 0247) for a scene, the open scene's UI (its views' Svelte components) or the project's files: one worded reason (no scene, no project, read-only, playing), reported to the status bar, then the undo step. `editor.scene.edit` and `beginEdit` go through it; plugins ask `editor.scene.whyNotEdit`. During play the scene document is read-only everywhere (ADR 0257); play-time edits go to the live World. _Avoid:_ comparing `playState` with `"edit"` to decide whether an edit may happen.
- **Slices capability:** an asset kind's `slices` flag (ADR 0149): its files are images that can be cut into slices (ADR 0040), whose `#slice` entries are sprites. The core image kind has it. _Avoid:_ comparing a kind with `"image"` to mean "has slices".
- **Asset policies:** an asset kind's rules for use: which fields may reference it, whether and as what node it can be added to a scene, how exports process it, and whether it is read-only or an importer sidecar.
- **Asset document:** one open asset file in the editor. It owns the file's current value, queued saves, the read-only check, telling its own writes from outside edits, and its persistent undo tree (ADR 0027). That history follows the file when it is renamed and is dropped when the file is deleted. A project-wide edit (a moved reference, a renamed settings name) is applied by the document to every state of that history, not as a step (ADR 0302).
- **Asset document frame:** the SDK's `AssetDocumentFrame` (ADR 0265): what every editor of one asset document renders in. It marks its root as the document's (the active history while focused), shows the head (kind, file name, Undo / Redo), the problems and the read-only notice, and flushes on close; the kind supplies only its body. _Avoid:_ a hand-written head, undo buttons or read-only hint in a kind's editor.
- **Asset picker:** the SDK's `AssetPicker` (ADR 0282): the one control for a slot that names a project file. Given the slot's field kinds (the names asset kinds declare in `referencedAs`), it lists what fits from the open project, labels the entries, stores `asset:<path>` or the bare path, offers built-ins first and marks a reference to a missing file. _Avoid:_ a datalist, a select over `project.files` or a "(missing)" option written in a panel.
- **Commit rule (value controls):** how the SDK's `SliderField` and `ColorField` report a value (ADR 0282): `onValue(value, drag)`, `drag` true while a gesture is under way and false for the report that ends it or a typed value, so a caller makes one undo step per gesture (`doc.edit(next, drag ? { coalesce: true } : undefined)`).
- **Settings section:** a category of the Project settings panel a plugin's editor half registers, owning the top-level `project.json` keys it declares (`keys`, ADR 0151) and checking them (`problems`), such as Physics' `physics`. While it is registered its keys are in the panel's draft, saved and undone like the core keys; unregistered, the file keeps them untouched.
- **Project section:** a set of top-level `project.json` keys being edited by one panel (ADR 0151, `src/editor/projectSection.ts`): the draft and its undo, telling the panel's own write from an outside edit, keeping the draft when only another panel's keys changed, valid-only queued saves and after-save hooks. It reports its whole edit state (ADR 0181): its problems, one status (read-only, problems, saving, failed, saved) and undo flags that are off while the project is read-only. The Project Settings and Worlds panels are views over one each (`projectSettingsInstance.ts`, `worldsInstance.ts`), drawing one shared toolbar.
- **Settings section handle:** one top-level `project.json` key of the Project panel's settings draft as one interface (ADR 0253, `settingsSection` in `myco/editor`): its lenient parse and defaults (`read`), `write`, `set` by dotted path, `reset` (the key removed, so the defaults apply) and `problems`. A settings section's model builds its edits on one (`navigationSettings`, `physicsSettings`, `audioSettings`). A **canonical** handle (ADR 0306, audio) stores what its parse makes of a value set by path (clamped, rounded, or the fallback), so its scalar keys need no setters and their limits live only in the parse's declaration (`AUDIO_NUMBERS`).
- **Named list:** a list of names a settings section keeps in the draft that scenes, prefabs, asset files or other settings name (ADR 0262): physics layers, sorting layers, audio buses, acoustic materials, global parameters. The section declares it as data (`names` on its contribution: where the names live, and the component fields, asset-file fields and settings that name them); another plugin adds its own references with `registerNameReferences`. **Settings names** (`src/editor/settingsNames.ts`) is the one shell module that tells a rename from the drafts, asks first, and renames the references, and moves them back on undo. _Avoid:_ a section rewriting scenes itself, or matching component types by name.
- **Active history:** the one edit history Undo and Redo act on right now, from the Edit menu, Ctrl/Cmd+Z and the History panel alike (ADR 0145). It follows focus: a **panel-local history** a panel registered on its root while focus or the last click is inside it (Project Settings, Worlds, the Sprite Editor, the Particle Graph), else the focused asset document's, else the open scene's. Text fields keep their own text undo. _Avoid:_ undo stack (for anything but the scene's `CommandStack`).
- **History tree:** the persistent, tree-shaped edit history of one edited value (`HistoryTree`, ADR 0027, 0267): its states, the current and saved state, which child redo goes to, the path between states, pruning by count and age, and the `myco.history@1` file it writes and adopts by hash. The scene's `CommandStack` and an asset document's `TextHistory` are built on it. _Avoid:_ "undo stack" for the tree itself (the stack is the scene's adapter, with groups and listeners).
- **Step adapter:** what moves an edited value across one history state's change, forward or back (`StepAdapter`, ADR 0267); it may refuse a change that doesn't fit (a damaged history), and then the whole move is abandoned. The scene's applies a document patch and replays text files; the text history's applies a text patch.
- **History persistence:** keeping one document's history tree on disk (`persistHistory` in `historyPersistence.ts`, ADR 0316), for a scene stack or an asset text history alike: load it (adopt it, or set it aside), save after changes through the project's disk queue, follow the location setting. Its host hears only the outcome (`adopted`, `set aside`, `new`) and save failures.
- **Edits-started rule:** a saved history that arrives after the document was already edited is set aside, not adopted; the edits win and their history replaces it (ADR 0316). Scene tabs avoid the case by opening only once their history is read.
- **Storage scope:** whose saves and settings a `Storage` backend holds (`StorageScope` in `platform/storageScope.ts`, ADR 0317): an exported `game`'s, a `project` played in the editor (its own, apart from every other project's), or the `editor`'s own per-user data, which game code never sees. _Avoid:_ "game name" as the identity of a played project.
- **Viewport tool:** a scene-view tool a plugin's editor half registers (ADR 0138), installed on every scene view: it gets presses before selection and the transform gizmo, hover and keys, draws overlays, and may be the **active tool**, the one mode that replaces the transform gizmo until Escape, Q/W/E/R or play. Tile painting is one; so is editing a collider (ADR 0142). A tool may also mark outlines **selectable**, so a click inside one picks its node.
- **Tool mode:** what the active viewport tool is doing (the collider being edited, the brush picked), owned by the viewport-tool host (ADR 0231): entered and left through the tool context or `editor.viewport`, and ended by the host on another tool, Escape, play, another scene or, where the tool asks, a new selection. _Avoid:_ a module-level mode signal in a plugin.
- **Component edit toggle:** the Edit button in an Inspector component card's header (Edit Collider, Edit Zone) that a viewport tool gets by declaring `editsComponents` (ADR 0266). The host registers it and owns its rule: the tool's mode, a `ComponentEditMode`, names the card's node, Component type and index; it hides for several nodes and ends on removal or a new selection. _Avoid:_ a plugin's own edit button.
- **Gesture:** a viewport drag that is one undo step (`view.gesture`, ADR 0231). Escape reverts it; pointer cancel, blur, a tool switch or play close it and keep the edits.
- **Undo step:** a long-running edit on the open scene, opened with `editor.scene.beginEdit` and closed with `end()` or `cancel()` (ADR 0231). _Avoid:_ `scene.stack.beginGroup` in plugin code.
- **Play Worlds:** the Worlds of the running play session, as `editor.scene.playWorlds` lists them in step order (ADR 0232): read-only to plugins, empty while editing, a new list per session. The session owns stepping, pausing and stopping. _Avoid:_ importing the shell's `playing` signal in plugin code.
- **Scene toolbar item:** a button a plugin's editor half adds to the Scene toolbar that opens a popover (ADR 0142), such as Navigation's Nav overlay toggles.
- **Component header action:** a control a plugin's editor half adds to the header of an Inspector component card for some Component types (ADR 0142), such as Physics' Edit Collider.
- **Hierarchy create entry:** a node kind a plugin's editor half adds to the Hierarchy's Create menu (and the menu bar's), placed after a named entry (ADR 0146), such as Particles' Particle System, which writes a new effect first.
- **Asset action:** an entry a plugin's editor half adds to the Assets panel's context menu for selected files or slices (ADR 0146), such as Tilemaps' Create Tileset from Slices.
- **Play stats counter:** a per-World count a plugin's editor half adds to the Play Stats panel (ADR 0146), such as Navigation's nav agents.
- **Scene-file walk:** the one walk over a scene or prefab file (`mapSceneFile` in `scene/sceneFileWalk.ts`, ADR 0279): every component field value with its component type, wherever it sits (component data, field overrides, added components, added nodes), and every node list. Format migrations and asset cleanup are rules over it.
- **Override fold:** the one place that knows what a scene or prefab file and its instances' overrides come to (`foldNodes` in `scene/overrideFold.ts`, ADR 0280): targeting through nested instances, the prefab-root alias, `removeNode`/`addNodes` scope, the component index, behaviours-only `order`, enabled, Worlds, tags and fields. Its adapters are instantiation (GameObjects), the resolved scene view (entries) and the editor's Apply (document commands); which override sets which property is its `setsProperty`, shared with the override writer. _Avoid:_ walking overrides by hand anywhere else.
- **Override writer:** the write side of the override fold (`editor/overrideWriter.ts`, ADR 0287): sets or reverts one property of the node or component at an editor path, choosing the node's entry, an added component's entry or an override, merging into the override that sets it and dropping empty ones; also answers "is it overridden?" and what a property inherits. _Avoid:_ editing an instance's `overrides` list anywhere else in the Inspector.
- **Resolved scene view:** every effective node and component of a scene or prefab file, instances expanded and overrides applied, without instantiating (`resolveScene`, ADR 0280); each node has its editor path. Warm-up, detection, thumbnails and the editor (`SceneDocument.resolve`) read it.
- **Node reference:** `{"$node": id}` as a component field value or a list item, never deeper (`scene/nodeReferences.ts`, ADR 0280). In a node entry, component data, field overrides and added components resolve among the file's nodes; added nodes' components among those added nodes.
- **Scene-open migration:** work a plugin's editor half does on a scene when the editor opens it (ADR 0146), such as moving embedded particle effects into assets.
- **Field choices:** the dropdown values a plugin's editor half supplies for one Component field when they depend on more than its declaration (ADR 0152), such as Meshes' `MeshRenderer.variant`, the referenced model's material variants. A contribution names the type and field, a `none` choice that clears it, a `key` of what the choices depend on, and `choices` (may load). A field's fixed list stays its `choices` option (ADR 0042).
- **Clipboard text:** what a copy in the editor puts on the system clipboard (ADR 0226): JSON with a `format` tag (`myco.nodes@1`, `myco.shadergraph.clipboard@1`, `myco.particles.clipboard@1`), written and read by the clipboard module (`src/editor/clipboard.ts`, in `myco/editor`). A paste reads it only from a `paste` event and takes it over the in-memory copy when another editor wrote it. _Avoid:_ calling memory "the clipboard" when the text is meant; reading it with `navigator.clipboard.read`.
- **Graph document:** the shared, pure edits on a node graph (ADR 0228, `src/editor/graph/document.ts`): properties and the nodes that read them, groups, notes, clipboard round-trip and duplicate, built from a **graph kind**, a plugin's adapter that says what its items are, where groups and notes live and what its clipboard holds. `useGraphSelection` is its selection and shortcut controller. The Shader Graph and the Particle Graph are its two kinds.
- **Wiring gesture:** pressing a port to draw a wire, letting go on a port to connect, over a refusing port to see why (the **refusal hint**), or in empty space to open the node search; pressing a wired input picks its wire up (the **detached input**) to move or remove it (ADR 0259, `src/editor/graph/wiring.ts` `useGraphWiring`). A panel plugs in its graph's **wire edits** (`GraphWiringEdits`). **Find items** (`FindItem`) are what find (Ctrl+F) reads of a graph's canvas items.
- **Field edits:** setting, axis-setting and reverting a Component field from the Inspector, in `fieldEdits.ts` (ADR 0152): overrides on prefab instances, one undo step per action across the selected nodes.
- **Node edits:** the Inspector header's actions on the selected nodes, in `nodeEdits.ts`: switching on or off, renaming, reverting an inner node's name or active override (ADR 0122), and the prefab actions Create Prefab, Apply, Revert All and Open Prefab (ADR 0022, 0087). One undo step per action across the selection; each action says why it can't run (`whyNot`), a read-only project through the one read-only message (`readOnly.ts`).
- **Story harness:** `src/editor/stories/editorStory.tsx` (ADR 0235): `withEditor` builds the editor a story renders in (an in-memory project, the plugins, real scene tabs, a real play session), and stories reach state only through the editor surface. _Avoid:_ setting `currentProject`, `openScene` or `playState` in a story.
- **Idle prefetch:** code a plugin's editor half asks the editor to fetch once it is idle (ADR 0082, 0146), such as Physics' core and backends.
- **World service:** a lazily loaded per-World subsystem a plugin provides (physics 2D, physics 3D, navigation), started when a scene or an attached Component needs it. Other plugins can look one up as "that plugin's service, if enabled".
- **Physics dimension:** 2D or 3D physics, each described once (ADR 0283, `physics/runtime/dimensions.ts`): its World service id, the Components that work in it and need its backend, and its fixed-step systems. A Component in no dimension (Buoyancy) never needs a backend of its own.
- **Physics backend:** a physics engine (Rapier today) adapted to the Physics plugin's backend interface for one dimension (ADR 0137). A backend plugin contributes it; the Physics plugin's shared sync core drives it through neutral descriptions, so Components and scripts never see it. A project picks one with `physics.backend2d`/`backend3d`, or uses the only one enabled. _Avoid:_ physics engine (for the plugin), physics world (that is one World's simulation).
- **Collider shape table:** the Physics editor half's one entry per collider type Edit Collider works on (`colliderShapes.ts`, ADR 0288): its outline or wireframe from the collider's **shape fields** and centre, its handles, and what a press or drag on a handle writes as a field patch. Its 3D entries are built from the **3D shape kit**. The collider gizmo loops over it; sizes come from `engine/physics/shape2d.ts`/`shape3d.ts`, which the physics worlds build with. _Avoid:_ `instanceof` dispatch on collider classes in the gizmo.
- **3D shape kit:** what every 3D handle gizmo shares (`src/editor/shapeKit3d.ts`, `shapeKit3d` in `myco/editor`, ADR 0295): pose maths, wireframes (oriented boxes and spheres, blend shells, shapes as `shape3d` sizes them, meshes), the face, radius and blend-shell handle rules, and the **axis drag** (a pointer ray turned into how far out along its axis a handle is). A gizmo's shape table is entries (`HandleShape3D`) built from it. _Avoid:_ copying pose maths or a drag rule into a plugin.
- **Zone shape table:** the Audio editor half's box zone and sphere zone entries (`zoneShapes.ts`, ADR 0295), each with the blend-shell handle; their volume is `zoneVolumeFromMatrix`, the zone manager's own sizing, so the outline is the runtime volume.
- **Shape fields:** a collider's shape as its own class describes it, backend-neutral (`_shapeFields()`, `ShapeFields2D`/`ShapeFields3D` in `engine/physics`, ADR 0305): a box, circle or sphere, capsule, polygon, edge, mesh or shape source with its sizes in local units. The physics worlds build from them, the collider shape table draws them, and the shape is rebuilt when `shapeSignature(fields)` changes. A joint likewise gives its kind (`jointKind`), its fields (`_jointFields()`) and its anchors in world space (`_worldAnchors()`). _Avoid:_ `instanceof` chains on collider or joint classes; a hand-written shape signature.
- **2D frame:** a node's world matrix read as a 2D pose (`engine/scene/frame2d.ts`, ADR 0301): position, angle, signed per-axis scale and whether it is mirrored, the mirror carried on x, composing back to the matrix; its inverse (`localAngle2D`) writes an angle back keeping the node's mirroring. Every 2D pose reader (`worldRotation2D`, the 2D physics world, tilemap colliders, 2D gizmos) goes through it. _Avoid:_ an angle from `atan2` beside `worldScale` (a mirrored node then reads as turned half a turn).
- **Component wireframe:** a Component's world-space wireframe a plugin offers through `registerComponentWireframe` (ADR 0295) so another plugin's tool can draw it without importing that plugin; the Physics plugin offers its 3D colliders', which the occluder gizmo draws.
- **Editor service:** the editor-side counterpart of a World service, a named, typed object a plugin publishes for other plugins to use if it is enabled.
- **Core:** what is never a plugin. In the engine: World, ECS, GameObject and Transform, scene files, prefabs and overrides, assets, time, input, `Engine`, the renderer core and netcode. In the editor (the **editor shell**): panels and docking, Hierarchy, Viewport, the Inspector and Assets frames, undo, the scene document, the Code panel, Play, Export, and the graph view.
- **Particle property value field:** the one field that edits a particle effect's graph property by type (`ParticlePropertyValue`, ADR 0290), on the Blackboard and as a ParticleSystem's per-instance override in the Inspector. It reports `(value, drag)` as the SDK's fields do (ADR 0282). _Avoid:_ a per-panel property input.
- **Project file edit:** one edit across the project's JSON files (a moved reference, a removed asset, a renamed settings name), described by its module and applied by each file's **owner** (`projectFileEdits.ts`, ADR 0262, 0302): the scene format or the open scene's document, the asset document (`assetFileOwner`: the open document, else the kind's format) or, for `project.json` and plain JSON, the shell. A file the Code panel holds unsaved text for has its **Code buffer** as a second owner (ADR 0308). A move then asks each other file whose kind rewrites its format (`.obj`/`.mtl`/`.gltf`, ADR 0314); files no one writes (scripts, read-only kinds) are reported, not edited. _Avoid:_ writing an asset file behind its document, or a file behind its Code buffer.
- **Code buffer:** a file open in the Code panel and its text, unsaved while it differs from the file on disk (`code/codeBuffers.ts`, ADR 0308): the one owner of the panel's tabs and unsaved text, which the discard guard asks, which follows moves and deletes, and which a project file edit rewrites. Monaco's models are its adapter. _Avoid:_ reading unsaved text from a Monaco model, or a dirty flag beside the text.
- **Project opening:** turning what the start screen or File menu asked for (an **open intent**: pick a folder, a recent entry, a sample, a copy of one, a new project) into an **open outcome**: opened, cancelled, or refused with a reason (`src/editor/projectOpening.ts`, ADR 0318). The editor window opens the resolved project there; the Projects window hands it to the editor window. _Avoid:_ reading the status line to learn whether a project opened.

## Rendering (ADR 0153, 0240, 0244)

- **Effect player:** one particle effect at one transform on the Babylon backend (`render/babylon/effectPlayer.ts`): its runner, its kernel systems (every system runs on a **kernel executor**: JavaScript, WebGPU compute or WebGL2 textures, ADR 0251), their draws and fallbacks, and how it plays (restart, event-started systems, events, emit, stop, seeding). A World's ParticleSystems (one player each, through `BabylonParticles`), the particle graph's preview and the particle thumbnails all play through it. The players of one scene share **effect resources** (texture cache, dot, scene depth, kernel host). _Avoid:_ particle player (for anything but `BabylonParticles`, the World adapter).
- **Thumbnail renderer:** a `BabylonRenderer` made with `forThumbnail` that draws a prefab's, scene's, environment map's or sky's headless World with the real render features on the thumbnail engine (ADR 0153, 0189), under the thumbnail policy (no warm-up machinery, a shared studio room, an engine it doesn't own). The thumbnail code only frames and captures.
- **Engine factory:** `createEngine` (`render/babylon/createEngine.ts`, ADR 0244), the one place a Babylon engine that draws into a canvas is made, for a World's surface and every preview and thumbnail: WebGPU, else, or when WebGPU can't start, WebGL2.
- **Pipeline readiness:** a World's renderer module that warms shader pipelines, re-warms them on a tier change or new probe captures, and holds the World's first frames until what it draws is ready (`render/babylon/pipelineReadiness.ts`; ADR 0080, 0120, 0240). Thumbnail renderers have none.
- **Preview inset:** where the editor's camera preview sits on the canvas, as fractions (`PreviewInset`, ADR 0240). The editor's viewport handle measures it once a frame; the renderer never reads the DOM for it.
- **PBR injection point:** a named place in Babylon's include-expanded PBR shader where the engine puts code (ADR 0222), such as `albedoBlock` or `worldPosition`, asked for through `pbrInjections` in `render/babylon/pbrInjection.ts`, which owns its pattern per shader language and re-declares what it replaces. _Avoid:_ anchor (for an injection point; "anchor" alone means music's grid anchor, see **Heard position**).
- **Myco material plugin:** one of the engine's own Babylon material plugins (graph, water, probe blend, sprite UV), all extending `MycoMaterialPlugin` (ADR 0225, `render/babylon/mycoMaterialPlugin.ts`), which registers it only after its fields are set and declares WGSL and GLSL. Render tests check what such a plugin does through the **compiled shader text** (`engine/tests/pbrShaderSource.ts` `shaderText`), the source Babylon builds after expanding includes and injecting plugin code. _Avoid:_ reading a plugin's `"!"` keys outside the pin test.
- **Lighting rig:** the core module that lights a World on the Babylon backend (`BabylonLighting`, `render/babylon/lighting.ts`; ADR 0140, 0252): Light components and their shadow requests, the Environment's lighting, the studio room and the skybox. Features in the `lighting` phase give it **lighting contributions** for the frame (`contribute`: the sky's sun and bake, the fog's sky fog), and the renderer resolves it once after that phase. A lighting contribution is per-frame data, not a plugin's contribution at a contribution point. _Avoid:_ lights feature, environment feature (both gone).
- **KSL (shader source):** the engine's small shader source language (ADR 0094, 0250), the common subset of WGSL and GLSL with macros (`VAR`, `FN`, `UNI`, `KTEX`…). A `ShaderSource` (`render/shaderSource/`) holds one KSL text and gives its WGSL, its GLSL and a JavaScript program of its functions. Shader maths is written once in it; only Babylon injection glue and entry points are written per language. _Avoid:_ hand-written WGSL/GLSL twins.
- **Kernel step:** one built-in particle operation of a kernel program (age, forces, noise, orbit, collisions, place, a spawn shape), written once in KSL and once in JavaScript side by side in the steps catalogue (`render/particles/gpu/kernelSteps.ts`, ADR 0251), which the shaders and the JavaScript executor both take. _Avoid:_ behaviour (the retired CPU simulation's word); CPU simulation (for the JavaScript executor).
- **Kernel operator:** one expression operator of a kernel program (`KOp`: arithmetic, safe division, remap, smoothstep, noise, vector building, normalize, hsv, toLinear), written once in KSL and once in JavaScript side by side in the operator catalogue (`render/particles/gpu/kernelOps.ts`, ADR 0325), with the set statement. **Width-fit rule:** how a kernel value of one width is used at another (`fitSource`): a number broadcasts, a wider vector is cut, a narrower vector is padded with zeros; both executors read it. _Avoid:_ swizzle-fitting (it no longer cuts and pads differently per executor).
- **Pass plan:** a camera's passes on the Babylon frame graph, in order, the textures they need and a layout key built only from them (`planCameraPasses`, `render/passPlan.ts`, ADR 0274). The frame graph rebuilds only when a plan key (or the frame's own layout) changes; everything else, the finish pass's uniforms included, is set each frame. _Avoid:_ stack key; calling a uniform-only setting (vignette, grading, tone mapping) a pass.
- **Drawn node:** what a render feature drew for one Component, as its `drawn()` hook reports it (`DrawnNode`, ADR 0276): a shape (a sprite's quad, meshes, a tile layer's quad batches, a screen rectangle, or none when batched), a pick order (layered 2D content its draw order; depth-tested content below every layer; screen Text above everything), its materials and size. The editor's picking, framing and outlines, thumbnail framing and `RenderDiagnostics.drawn` read every loaded feature's.
- **Default light rig:** the ambient light (0.35), sun (1) and studio room (0.4) that light a World without Lights or an Environment map, and every asset thumbnail and preview (`DEFAULT_RIG`, `addDefaultLights` in `render/babylon/lighting.ts`, ADR 0277).
- **Preview stage:** what every Babylon preview draws on (ADR 0300, `previews/previewStage.ts`): the engine from the engine factory and a preview disposed while it starts, the default-lit scene, one orbit (`thumbnailMath`'s `Orbit`: yaw 0 at +Z, dragging right grows the yaw) turned by drag and wheel, the loop, resize and GPU context loss. A preview keeps only what it puts on the stage. _Avoid:_ calling `createEngine`, or writing orbit or drag code, in a preview.
- **Particle-effect compile:** turning a particle effect into what plays (`compileParticleEffect`, `scene/particleEffect.ts`, ADR 0315): parse (from raw JSON), expand its sub-graphs and custom blocks with an asset resolver, compile; it returns the expanded graph, the program, every problem and the assets it depends on. The effect player adds its kernel plan; the editor's Inspector, Particle Graph and preview make the same call with the project's resolver. _Avoid:_ compiling a document graph with `compileParticleGraph` directly (it skips the expansion).
- **Automatic quality:** the start-up policy that picks the graphics tier when a project sets `autoDetect` (`render/autoQuality.ts`, ADR 0055, 0322): a guess from the device mapped onto the project's tiers ("the default" is the platform's default), then stepping down while the first seconds of play are slow, saved as the detected tier. A player's choice always wins and ends it. `Graphics` holds the **active tier**. _Avoid:_ "auto-detect" for the step-down alone.
- **2D materials:** the one module a 2D draw (a sprite, a quad batch, a 2D particle system) gets its material from (`render/babylon/materials2D.ts`, ADR 0418): given the texture, material asset, sorting layer, blend and mask it returns a handle, and owns the lit decision, the normal and mask maps, the graph-or-layered choice, sharing and refreshing when the lighting rig changes. _Avoid:_ a draw kind working out its own lit setup or cache key.

- **Capture event:** one EVENT record of a capture, decoded into the typed `CaptureEvent` union by the capture reader (ADR 0227, `capture/events.ts` beside the writer). The Profiler reads only capture events, never the EVENT arg layout. _Avoid:_ `args[n]` outside `capture/events.ts`.
- **Promotion (music):** a run becoming the music player's playing run: it stops being the successor, the grid is anchored on its start and its loop-region state starts fresh (ADR 0229). Only `promote` in `music/musicPlayer.ts` does it; the player is otherwise a read-only view whose state moves only through that module's named transitions. _Avoid:_ assigning `player.run`, `next`, `anchor` or `state`.
- **Music lifecycle event:** what a backend reports up the music seam that isn't about one group: a rebuild's begin and end, a recovery with its cause, the page hiding and each hidden STATUS tick (ADR 0248, `MusicBackend.onLifecycle`). The backend reports; `music/background.ts` alone decides what to re-plan. _Avoid:_ a backend calling into `music/`, or music probing a backend field such as `isRecovering`.
- **Row composer:** the module above the audio backend seam that adds the event and music sections to `Audio.debug()` and the capture keyframe, from the page-wide registries, for every backend (ADR 0249, `runtime/audioRows.ts`). Backends report only voices, buses, meters and mix. _Avoid:_ building event or music rows inside a backend.
- **Keyframe layout:** the KEYFRAME row encoding of a capture (caps, state codes, flag bits, `NO_NAME`, u4.12 pitch, u0.16 audibility), owned by `capture/keyframeLayout.ts` (ADR 0230), which imports nothing so the core can use it without loading the recorder. Writers quantise through it; readers decode only through `readCaptureKeyframe`. _Avoid:_ repeating its bits or the 4096 / 65536 scales.
- **Capture names:** what a capture calls a clip, bus slot, event asset, parameter, snapshot or target at an instant (ADR 0260, `capture/names.ts`): META's names from the start, then each NAMES record from its own time; a bus slot gets a new record whenever it takes a new name. One fallback text (`bus 3`; "Master" for the output). _Avoid:_ a view's own name map or fallback.
- **Reason word:** the sink's word for why a voice stopped, was stolen, went virtual or real, was refused or queued (`busMaxVoices`, `capDemoted`), which the capture reader gives instead of §5.6's code (ADR 0260, `capture/reasons.ts`, with `reasonText`). _Avoid:_ reason code tables outside `reasons.ts`.
- **Track kit:** the Profiler's reading layer for timeline tracks (ADR 0261, `editor/mix/tracks/kit.ts`): tracks declare the STATUS columns and EVENTs they read and a build function; the kit reads each capture growth once for all of them and answers the sample in force at t. _Avoid:_ a track calling `statusColumns`, `range` or a bisect of its own.
- **Segment grid:** a music segment's compiled tempo map with its cues, entry and exit in ticks (G1), as `music/segmentGrids.ts` gives it now (ADR 0263): with the file's end once the **segment length** is known (its first track that names a clip: the clip's facts, else the decoded length). _Avoid:_ compiling or caching a segment's grid anywhere else in the runtime.
- **Stamped ramp:** a voice's `fadeShaped` (its `fade` gain, optionally stopping at the end) or `paramsShaped` (its own gain and low-pass), starting at a heard time. Every adapter's voice takes one (ADR 0264): sample-exact on the core, timer steps on the Babylon fallback, recorded and forwarded by the pending voice. _Avoid:_ probing for it or falling back to `fade`/`stop` in callers.
- **Audio frame (frame step):** one backend frame in the production order, run only by `runAudioFrame` (ADR 0270, `runtime/audioFrame.ts`): attenuation, voice collection, Doppler, zones, occlusion, selection, panner pick, fx, listener, music plan, commit on the core (its `StagedFrameHost` stages); the passes, the music plan and `update` on the Babylon fallback; the music plan and `update` on a plain backend. `stepAudioFrame` runs it inside the main-thread audio frame; the rigs' `tick` runs it alone. _Avoid:_ calling the core's stages, or a backend's `update`, to drive a frame.
- **Main-thread audio frame (audio frame step):** `mixer.update`, then the audio frame, then the playlist runtime's frame, run only by `stepAudioFrame` (ADR 0434, `runtime/audioFrame.ts`) over `AudioFrameParts` (mixer, playlists or null, backend, listener frame). The audio system calls it after resolving the listener; every rig calls it (`audioFrameDriver`, `loopbackAudio().mainFrame`, and `step`, which renders after it). _Avoid:_ writing `mixer.update`, `tick` and `playlistHost().update` in sequence by hand.
- **Audition (editor):** the one instance the editor plays to let the person hear an event, whoever pressed Play (the Event editor, the segment transport, the rules table), owned by `editor/audition/audition.ts` (ADR 0268, `editorAudition`): flush then play, the end of the instance, live slider overrides, the notice; the music extras are options of the same play. The panels are views over it. _Avoid:_ calling `Audio.play` for an audition from a panel, or a panel keeping its own handle.
- **Music path:** a music node's address from its event's root, child indexes and library steps `"lib<n>"` (`[1, "lib0"]`), beside its id; `engine/audio/musicTree.ts` maps between the two and owns every descent over `children` and `library` (ADR 0269). _Avoid:_ walking `children`/`library` by hand to find or replace a node.
- **Send rule (core):** whether the audio core may be written to now, answered only by the core session (`SendGate` on `CoreSession`, ADR 0291). **May send:** a core listens now (not disposed, no rebuild, the context running): voice starts, posts outside the frame, music group operations. **May queue:** a core will keep what is written (not disposed, no rebuild, not failed), so it holds while locked: automation state and the frame commit. _Avoid:_ restating `disposed`/`recovering`/`status` checks in a part, or a `sending()` closure.
- **Mixer session:** the Mixer panel's module for what Reset, Play and Stop clear: the meters' hold and clip latch, the monitor controls and their taint marks, Compare with Play start, plus Pause, elapsed and the loudness target (ADR 0292, `editor/mix/mixerSession.ts`). It alone runs the monitor and Compare models' lifecycle. _Avoid:_ clearing meters or monitor state in the panel controller.
- **Heard position (music):** where a playing segment is on the heard clock, answered only by `music/anchors.ts` (ADR 0285) from the segment's **grid anchor** (integer ticks plus the heard time they play at, P3) by walking the loop passes: the position heard at T (`ticksAt`), the heard time of the next grid point, cue or exit after T in the pass it is heard in (`nextHeard`, `nextGridHeard`), the next wrap (`predictWrap`, `nextWrapOf`). A caller says *what* file position it wants (a `NextPoint`); the module says *when* it is heard. _Avoid:_ `anchor.time + (file - anchorFile)` outside that module; moving the anchor to "the pass heard now" before reading it.
- **Fake clock (audio):** the fake backend's one clock (ADR 0286, `runtime/testing.ts`): `advance`/`advanceTo` move it, and `time`, the rAF time `timeAt` maps from, `clock.horizon()` (`lookahead` ahead) and the frame map (after `startContext`) are read off it. Music tests step it through the real frame (`musicFrameStep`) or take the plan step's frame from it (`musicFrameAt`). _Avoid:_ writing the fake's `time` through a cast; a hand-built `MusicFrame`.
- **Event reference (audio):** one place in an audio event that names a parameter or a bus, with where it is and whether the name is local (the event's own parameter, which hides a global one) or global, listed and rewritten only by `engine/audio/eventReferences.ts` (ADR 0299). The Event editor's use count and rename and the settings renames go through it. _Avoid:_ walking an event's JSON for keys called `parameter` or `bus`.
- **Clip resolver:** the module that turns a clip path into the base play request (ADR 0293, `runtime/clipResolver.ts` `clipRequest`): its URL, the import volume with the FuMa gain, stream or decode (a sound by its import setting and the ambisonic >5 s rule; a music stem by the 30 s rule once the backend's clip facts are known), the ambisonic flag and the bus. Sources, one-shots, event clips and segment runs all start from it. _Avoid:_ reading a clip's import settings, URL or facts to build a play anywhere else.
- **Held music record:** a FADE, SET_PARAMS or group prime asked while the core session may not send, kept by `core/musicOps.ts` and sent by `sendHeld` right after the locked queue's drain, so after the member's PLAY (ADR 0294). The mirror and the stamped log move when it is asked. _Avoid:_ dropping a music ramp because the context is locked.
- **Parameter list (audio):** the one module that edits a list of audio parameters, an event's own or the project's global ones (`parameterList.ts`, ADR 0304), as `parseParameters` reads it back. A **parameter holder** plugs in where the list lives and what a rename or a remove carries along (an event's references; the settings' bus automation). The **parameter cards** are its one view. _Avoid:_ editing `parameters` arrays by hand in a panel.
- **Refused-or-next result:** what an audio editor edit returns (`EditResult`, ADR 0307, 0313): the next value, or why it was refused. `applyEdit` is the one place it is applied: one labelled undo step, or the refusal in the status bar. A view's disabled check asks the edit itself (`refusalOf`). _Avoid:_ returning the input unchanged to mean "refused", a `can*` guard or `*Refusal` query beside the edit, an edit that throws on a refusal, or a panel keeping its own refusal line.
- **Music node handle:** one open music node of an audio event, a segment or a playlist or music switch by id (`music/musicNodeHandle.ts`, ADR 0313): the node, the document's read-only state, an edit result applied as one undo step (coalesced for a drag), and clip facts and waveforms from the peaks service with a version signal. The segment view, segment panel and rules table are views over it. _Avoid:_ a panel opening the event's document, finding the node and writing it back itself.
- **Sounding voices (event instance):** the voices one event instance sounds, read from one walk (ADR 0320, `EventInstance.sounding()`): its own 0158 voices, then its music's as `music/soundingVoices.ts` lists them (stems of the run and successor, stingers, loop tails and ringing runs). Every voice read and control of the instance goes through it. _Avoid:_ a second walk over `player.run`, `stingers` or `tails` in the event runtime; adding a music voice kind anywhere but `soundingMusicVoices`.
- **Profiler table kit:** the one module that turns a profiler table's unfiltered rows and the seek into what the table shows (ADR 0326, `profilerTablesModel.ts` `profilerTable`/`profilerTables`): the rows after the name filter, the summary line and the empty state (`TableEmpty`); one section (`TableSection`) draws any of the four tables (voices, buses, event instances, music), each a column list and cells. _Avoid:_ a per-table data function.

## Animation (ADR 0370–0376)

User-facing guide: [docs/wiki/guide/animation.md](docs/wiki/guide/animation.md).

- **Clip:** a set of tracks over time: an authored `*.anim.json`, an imported `model.glb#Anim/<name>`, an image flipbook `sheet.png#Flip/<name>`, compiled to `myco.anim@1` (`.anim.bin`). A timeline is a clip used across many nodes (ADR 0371).
- **Track / key:** a track is one animated thing of one kind (`bone`, `float`…`color`, `quat`, `discrete`, `morph`, `event`, `audio`, `activation`, `subclip`, `control`, `marker`, `curve`); a key is a value (or notify) at a time on it. Clips, timelines and tweens share one track model.
- **Marker:** a named point on a clip: `sync` (phase sync), `exit` (where a transition may leave), `hit` (an impact a play can align to) or `cue` (a named point scripts and `section`s use).
- **Notify:** an `event` track key that calls a method on the Animator's node's behaviours and fills `AnimationEvents`; a **notify state** also ticks (`begin`, `tick`, `end`). No event bus (ADR 0017).
- **Layer / mask:** a graph layer (or an implicit-graph layer index) blended over the base by weight, optionally through an avatar mask (`*.mask.json`: bones or profile roles with weights).
- **Slot:** a named insertion point in a graph where code plays a one-shot clip over the graph (`anim.play(clip, { slot })`); a **section** is the part of the clip it plays.
- **Sync group:** a `syncGroup` node; the clip players under it follow the heaviest one's phase by `sync` markers.
- **Blend space:** a 1D or 2D blend node over float parameters (piecewise-linear, or Delaunay-triangulated with hull projection, as audio's Blend).
- **Chooser:** a table of condition rows that picks a clip, blend space or pose database.
- **Request:** `Animator.request(name, { within })`: a live signal a transition reads, consumed by the first transition that reads it or expired. It replaces triggers.
- **Linked graph:** a `linked` node that runs another `*.animgraph.json` with its own parameters, swappable per Animator (`Animator.link`).
- **Rig (stack):** the ordered rig nodes (IK, look-at, grounder, spring bones, constraints, warps) that run after a pose. A **goal** is a named IK target slot.
- **Profile:** a `*.skelprofile.json`: roles (with mirrors and joint ranges) and chains mapped onto a skeleton's bones; the built-in Humanoid is one.
- **Retarget:** playing clips made for one skeleton on another through the two profiles' chains (`retarget` node, `Skeleton.retargetSource`, or an offline bake).
- **Pose database:** baked features of tagged clip ranges (`*.posedb.json` → `*.posedb.bin`) that a `poseDatabase` node searches for motion matching.
- **Root motion:** movement extracted from a clip's root bone and applied to a Transform, `CharacterController` or kinematic `RigidBody`; always in the `RootMotion` buffer.
- **Inertialization:** removing the pop of a pose switch by decaying the difference (Bollo's quintic) instead of crossfading.
- **Fuel:** the instruction budget a third-party wasm graph node gets per evaluation (`animationNodes[].budget`); a node that exhausts it faults and passes its input pose through.
- **Take:** in import, an animation stack of a model file that clip settings cut into clips. A recorded run of what the game asked of animation (`ANIM_*` records) is designed (ADR 0373) and not built.
- **Debug link:** the versioned connection by which a running build is inspected from the editor (ADR 0376): topics, pulled subscriptions, commands applied at the next frame start.

## Tilemaps (ADR 0103)

- **Orientation:** one of a tile's 8 flips and turns, its flip flags read as a transform of the cell, diagonal first, then X, then Y (as Tiled). `runtime/tileFlips.ts` is the one place that convention lives: `compose`, `inverse`, `rotateClockwise`, `flipPoint`, `sourceCorner`.
- **Brush:** what the Tile Palette set up to paint (a stamp, its flips, random, or a terrain) and the one module that answers what it paints (`tilemaps/editor/brush.ts`, ADR 0289): a **brush stroke** from press to release (`beginStroke`: the cells each tool paints, where stamps land, what the release does) and the **footprint**, the cells it covers or would paint. A multi-cell stamp is flipped and turned as a block, its tiles with it. _Avoid:_ placing stamps or sizing the footprint outside the brush.

## Hosts (ADR 0236)

- **Launch:** the ordered start of a game every host shares, through `launchGame` (`src/engine/launch.ts`): the asset source, scripts, plugin activation (passed in by the host), the Engine, then the entry scene; `dispose()` undoes it in reverse. The player, the dedicated server and play mode are its adapters. _Avoid:_ boot, bootstrap (that is a World's start-up plan, ADR 0032).
- **Launch settings:** the project settings a host that runs a project's files launches with (`launchSettings` in `src/engine/launchSettings.ts`, ADR 0435): `project.json` with `audio` from `audio.json`'s runtime view (ADR 0344), or a **refusal** the host words for its surface (`project.json` not an object, or still holding the old `audio` section), plus audio.json's **notices**. The player and the dedicated server read it; play mode passes the editor's own settings. The player's **build launch** (`buildLaunch` in `src/player/buildLaunch.ts`) adds what `game.json`'s Export options decide at launch (debug link dial/listen/platform, audio capture and take triggers), without a page. _Avoid:_ calling `projectWithAudio` or testing `legacyAudio` in a host; reading `game.json` fields with casts.
- **Entry scene:** the scene that empty start-up Worlds (no `scenes` key and no nodes) load at launch: a build's main scene, or play mode's open scene. The dedicated server has none.
- **Project file:** a file in a project folder that loads as an asset (`isProjectFile` in `engine/scene/projectFiles.ts`, ADR 0254): not hidden, not in a dependency or build folder, not TypeScript source (scripts are read apart). Its **file kind** (`projectFileKind`) says what it loads as on every host: `json` (parsed), `text` (its contents) or `url` (a URL serving its bytes). Read it with `Assets.json`, `Assets.text` or `Assets.url` (`Assets.bytes` for a url file's bytes). _Avoid:_ testing an asset value's type to guess what a file is; a host's own extension list.
- **Project code linker:** the one pipeline that turns a host's selected code (scripts and enabled plugins' files) into modules it can run (`link` in `src/projectCode/linker.ts`, ADR 0329): compile, parse JSON, bundle packages and plugin entries, order, rewrite imports, with one problem list and the asset references the code names. Its **link target** is where modules go: the **memory target** (module URLs, imported; the editor and the server each hold one) or the **build target** (files under `code/`). _Avoid:_ compiling or bundling project code outside it; deciding in a host what counts as a problem.
- **Listen target:** where a server World listens over one transport (`listenTarget` in `engine/net/listenTarget.ts`, ADR 0255): host, port, path and the normalised address, from the host's overrides (the dedicated server's `--host`/`--port`), then the options (`address`, else `port`/`host`/`path`, else a client `url`), then the host's per-Engine defaults. _Avoid:_ building or parsing listen address strings by hand; process-wide listen defaults.
- **Bootstrap topology:** which World of a declarative bootstrap plays which network role (`bootstrapTopology` in `engine/core/bootstrapTopology.ts`, ADR 0256): start-up servers, server templates and lobbies, the **Host template** (the first `server`-tagged template when nothing else serves: play creates it, the dedicated server starts it), what the dedicated server starts, where each server listens, and the client Worlds play copies. The server, play mode and the Worlds panel read it. _Avoid:_ testing `tags` for "server" by hand.
- **Server listen:** the one way the dedicated server has a server World listen (`serverListen` in `server/run.ts`, ADR 0323): for its start-up Worlds and for templates created at runtime, which the link applier reports (`LinkApplier.watch`) at the start of the next frame. It skips a World whose network session listens or is starting to (`session.listens()`), so game code that listens itself (a lobby's match World) is left alone. _Avoid:_ walking `engine.worlds()` each step for new Worlds; reading `addresses()` to ask whether a World listens (it leaves out listens still starting).

## Play mode (ADR 0237)

- **Play controller:** the editor's one play session (`createPlaySession` in `playSession.ts`, ADR 0237). It owns the edit, starting and playing states and the work deferred to Stop: kept values, plugin settings and script reloads. Not the same as `PlaySession` in `playMode.ts`, which is one running game.

## Engine (ADR 0238, 0239)

- **View allocator:** what decides which surface (the main view, a tile, or none after a hand-over) and which input target each World has (`core/viewAllocator.ts`, ADR 0238). The Engine asks it `surfaceOf(world)`.
- **End of frame:** the last step of a World's frame (ADR 0011, 0239). Work queued with `World.atFrameEnd` runs there, after deferred destroys; outside a frame it runs at once. _Avoid:_ checking `inFrame` by hand.
- **World owner:** what owns a set of Worlds and what it offers the modules working with them (`WorldOwner` in `core/worldOwner.ts`, ADR 0281): a World's config and handle, whether it is alive, creating Worlds (from a template under a chosen name too), the declared bootstrap, listen defaults and view hand-over. `Engine` is the implementation; a World holds it as `_owner`.
- **Declared bootstrap:** the one bootstrap World templates are looked up in and lobbies are found in (ADR 0281): the declarative bootstrap passed to `Engine.create`, else `project.json`'s when declarative. Distinct from the bootstrap that runs, which may be code.
- **Server lobby:** the lobby World a dedicated server starts (`BootstrapTopology.serverLobby`, ADR 0281), which `Lobby.connect("local")` runs too; a `lobby` config no server would run is a bootstrap problem.
- **Behaviour message:** a hook with an argument (`onCollisionEnter`, `onTriggerStay`, `onJointBreak`, `onControllerColliderHit`, the music hooks), sent by a plugin to the active GameBehaviors of some nodes through `World._sendMessage` (ADR 0303). The sender picks the nodes and the argument; the World delivers to each node once, with lifecycle hooks' edit-mode, error and async rules. _Avoid:_ looping over a node's components to call a hook.
- **Device snapshot:** the Engine's one keyboard and pointer (`devices` in `input/devices.ts`, ADR 0310): device events in from an adapter (the DOM listener, `listenToDom`), one snapshot per Engine frame, then the **routing step**, where the UI core is handed the frame's `PointerFrame` and answers its `InputClaim` (pointer, keyboard); `Input`'s getters read what the game sees after it. _Avoid:_ injecting input around the adapter (test-only `simulate` members) or reaching into the snapshot from the UI.
- **Project context:** the process globals a project registers while something runs it (`acquireProjectContext` in `core/projectContext.ts`, ADR 0319): asset sources, the storage backend, the mixer's buses and the graphics tiers, applied by one acquire and undone by its `release()`. An Engine holds one from create to dispose; `launchGame`, the editor's open project and the exporter hold one for their asset sources. Nested contexts: sources go with their owner, storage returns to the newest live context's, mixer and graphics stay. _Avoid:_ `Assets.addSource`/`Storage.use` by hand in hosts, `Assets.clearSources` to reset.

## UI (ADR 0076, 0271, 0437)

- **Element kind:** one of the closed set of UI element kinds (canvas, panel, text, image, button, input field, and the form, SVG and media kinds), each one row in `ui/elementKinds.ts`: its component type, UI tag (the kind the HTML tags of `host/htmlTags.ts` map onto), whether it is a leaf, whether it takes the pointer, its pseudo-classes and whether it paints; and the **per-tag facts** the UI host and the Svelte renderer look up by tag: whether its markup children are dropped (`isChildlessTag`), whether it takes focus (`isFocusableTag`, read from `isFocusableUI`'s class hierarchy, so the two can't disagree), its content attributes, whether it generates `::before`/`::after`, its part pseudo-elements and whether it has HTML defaults. _Avoid:_ switching on UI component classes outside that module; per-tag side tables (a `Set<UITag>` or `Record<UITag, …>`) in the host or a renderer.
- **Text run:** an element's resolved text: text, size, CSS weight, family, line height and wrapping (`textRunOf`, ADR 0271). The UI core measures it and reports it on each laid-out element; the drawing layer draws exactly it. _Avoid:_ reading a text component's font fields in a drawing layer.
- **Resolved paint:** what an element's box is drawn with now, its interaction state resolved: fill, border colour and widths, corner radii (`paintOf` in `ui/paint.ts`, `UIPaint`, ADR 0437). The UI core works it out each sync and reports it on each laid-out element; the drawing layer draws exactly it. The Unity-style **state colours** (`hoverColor`, `pressedColor`, `focusColor`) are its inputs, the fallback look for a state; where the element's own style rules state that look (`:hover`, `:pressed`, `:focus`, recorded by the UI host as it restyles), the style's restyled, transitioned value wins. _Avoid:_ picking a colour from `hovered`, `pressed` or focus in a drawing layer; restyling an element in pretend states to fill in its state colours.
- **UI view:** a `UIView` (ADR 0423): mounts a Svelte component on a canvas it makes under its node, through the engine's renderer and the UI core's **tree host** (`ui/host/UIHost.ts`, internal), the only maker of UI elements since wave D retired **UI documents** (`*.ui.xml`, ADR 0077). A rendered element is a **view element** (`UIViewElement`, `view.query(…)`), addressed in the editor by its template location. _Avoid:_ "UI document" for Svelte UI; making UI components outside the host.
- **Interaction log:** what the player did to one World's UI, recorded only by the UI core (`uiInteractions(world)` in `ui/interactions.ts`, ADR 0309): the hovered and pressed button, the focused field, and the frame's **interaction events** (`click`, `change`, `submit`, `hover`), published by the routing for the World's next frame so every script phase sees them. Component getters and the UI host read it. _Avoid:_ finding a change or hover by comparing values each frame, or stamping event frames onto components.

## Project settings (ADR 0272)

- **Runtime settings section:** one top-level `project.json` key the engine reads, declared once in `RUNTIME_SETTINGS` (`core/settings.ts`): its key, default and lenient parse giving the value the engine runs with (bad values replaced by defaults) and its problems and warnings by field. `resolveSettings`, the Engine's start-up warnings and the Project panel go through it; a settings section handle (ADR 0253) is its editor twin. _Avoid:_ checking a runtime key's values in the editor alone.

## Builds and tooling (ADR 0296, 0297)

- **Build writer:** the one module that writes a planned web build (`writeWebBuild` in `src/export/buildWriter.ts`, ADR 0296) for the command-line export and the editor's Build / Export: it checks the player and the output folder before touching anything, bakes models and processes images, clears an earlier build (keeping a desktop package's Rust cache) and writes each file once, a processed image in place of its copy. _Avoid:_ writing build files, or clearing an output folder, outside it.
- **Build folder:** the folder a build is written into, as the writer sees it (`BuildFolder`: exists, list, remove, write text, write bytes, by path relative to the folder). Adapters: Node's fs (`node.ts`) and the platform FileSystem (`fileSystemFolder`). A **file source** (`FileSource`) is the read side: the project's files, or a built player.
- **Command (Node):** a command-line entry point (`myco-server`, `npm run export`) whose arguments go through `parseCommandLine` (`src/server/commandLine.ts`, ADR 0297): it declares its options and its one positional argument, and keeps its own usage text. _Avoid:_ hand-written flag loops.
- **Script compiler settings:** how TypeScript is emitted (`SCRIPT_EMIT`) and checked (`SCRIPT_CHECK`, Bundler resolution), with the relative import rule (`relativeImportCandidates`), written once in `src/scriptCompiler.mjs` (ADR 0332). The build, the Node hooks, the editor's script loader, the Code panel and the project tsconfig derive from it and add only what is theirs. _Avoid:_ an inline compiler options object "matching" another.

## Netcode (ADR 0033, 0311, 0312)

- **Network session:** a networked World's net owner (`NetSession` in `net/session.ts`, `World._net`): its transports and connections, and the answers the other net modules ask for (ADR 0311): who owns a node, which tick is simulated, whether a ghost is relevant to a connection. _Avoid:_ a per-World `WeakMap` or a setter hook joining two net modules.
- **Ownership rule:** a connection owns what carries `Replicated.ownerId` when the id names it and the connection is open; 0 is the server (`session.owns`, ADR 0311). _Avoid:_ comparing `ownerId` with a peer id by hand.
- **Simulated tick:** the tick predicted systems are running for: the tick prediction replays (catch-up, re-simulation; `session.replay`), else `time.network.serverTick` (`predictedTick()`). Input streams return that tick's input.
- **Tick history:** values by tick for the newest ticks, kept by tick number whatever order they were written in (`TickHistory`, `net/tickHistory.ts`): a client's sent inputs, a predicted ghost's states.
- **Predicted plan:** a ghost layout's predicted values in one order, layout order (`PredictedPlan`, ADR 0312), for picking them from a received state, reading and writing the node and comparing a prediction with the server's (rotations by angle). _Avoid:_ restating the order of predicted values outside the plan.
- **Command (scene document):** one edit of a scene document (`src/editor/document/commands.ts`, ADR 0026, 0321): a label, an `apply` that edits the document in place and returns its `Change`s for the Editor World, and optional text file writes. It never undoes itself: `CommandStack.execute` runs it and the stack undoes, redoes and jumps by patch (ADR 0027). _Avoid:_ an `undo` method or undo bookkeeping on a command; calling `apply` outside a stack.

## Browser tests (ADR 0023, 0330)

- **Editor boot (e2e):** the edit World of the editor a spec opened has stepped more than 10 frames: the one condition `openEditor` and `waitForEditor` wait for (`tests/e2e/fixtures.ts`). _Avoid:_ a spec writing its own frame-count wait.
- **Test project:** the Flappy sample opened as a writable folder in memory with a spec's files (text or bytes) written over it (`openEditor(page, { files })`, the editor's `openTestProject` hook); what the editor writes is read back through `window.testFolder`.
- **Window hooks:** the editor's debug and end-to-end hooks on `window` (`engine`, `playEngine`, `orbit`, `overlayHandles`, `nodeRect`, `testFolder`, `openTestProject`), typed once as `Hooks` in the fixture; specs use them to find things, never to read the renderer. _Avoid:_ a spec declaring its own hooks type.
